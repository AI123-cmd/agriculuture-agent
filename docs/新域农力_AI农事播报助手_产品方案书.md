# 第一章 项目概述

## 1.1 项目名称

新域农力------AI 农事播报助手

## 1.2 项目简介

新域农力是一款面向农户的微信小程序 AI
Agent。产品通过外部传感器或网关获取温湿度、土壤、光照、降雨等环境数据，结合农户选择的作物入口、自然语言输入以及历史问答，形成面向具体农户与具体作物的上下文信息。

系统进一步接入农业/通用大模型 API，通过 Agent
对用户意图进行识别与路由，在诊断、气象、种植、知识、播报等专业 Skill
之间进行调用，最终将复杂的信息处理结果转化为简洁、易理解、可执行的农事建议。

产品核心链路为：环境感知 → 作物入口 → 自然语言对话 → 用户画像 →
规则优先的智能播报 → 农业 AI 兜底 → 简洁卡片输出。

## 1.3 项目目标

- 降低农户获取专业农业知识的门槛，让农业咨询从"找专家"变成"随时问"。

- 通过传感器与气象数据，将被动问答升级为主动风险提醒。

- 通过作物入口、农户档案与历史问答，为不同农户提供个性化建议。

- 通过 Agent 编排把不同农业任务拆分为可插拔 Skill，提高系统扩展能力。

- 在真实农业大模型 API 不可用时支持 Mock 模式，降低开发和联调门槛。

# 第二章 产品背景与用户痛点

## 2.1 产品背景

农业生产具有明显的地域性、作物差异和环境依赖性。农户在实际生产中既需要专业知识，也需要结合当天环境做出快速判断。单纯提供一个通用聊天机器人，无法充分利用作物、地块、环境和历史行为等上下文。

因此，新域农力将"农业知识问答"与"环境感知、主动播报、农户画像"结合，形成以农业生产场景为中心的
AI 助手。

## 2.2 核心痛点

  ------------------------------------------------------------------------------------------
  **用户痛点**            **具体表现**                               **产品对应能力**
  ----------------------- ------------------------------------------ -----------------------
  知识获取门槛高          农业问题专业性强，农户难以快速判断         农业 AI 问答 + 知识
                                                                     Skill

  病虫害发现困难          肉眼判断存在误判，专家资源有限             图像/诊断能力预留 +
                                                                     诊断 Skill

  农事决策依赖经验        浇水、排水、防高温等判断容易滞后           传感器 + 规则播报

  环境变化响应慢          高温、低温、干旱、高湿等风险需要及时处理   环境标签 + 主动提醒

  服务难以个性化          不同作物、地区、经验水平需求不同           农户档案 + 用户画像
  ------------------------------------------------------------------------------------------

# 第三章 产品定位：是什么？

## 3.1 产品定义

新域农力 = 微信小程序 + 农业 AI + Agent 智能调度 + 外部传感器 +
用户画像。

它不是单纯的农业知识库，也不是单纯的聊天机器人，而是一个围绕"农户当前问题"和"当前农业环境"进行信息整合、任务路由和建议生成的农业
AI Agent。

## 3.2 核心价值

  -------------------------------------------------------------------------------------------
  **价值方向**                        **产品价值**
  ----------------------------------- -------------------------------------------------------
  简单                                使用微信小程序即可进入服务，支持文字/语音等自然交互。

  及时                                通过传感器和规则检测环境异常，及时产生提醒。

  个性化                              结合作物、地区、面积、历史问答和环境标签构建画像。

  可执行                              输出结论、要点、来源、下一步等结构化卡片。

  可扩展                              通过 LangGraph 与可插拔 Skill 支持新增农业任务。
  -------------------------------------------------------------------------------------------

## 3.3 核心输出形式

统一建议卡片结构：

  --------------------------------------------------------------------------
  **模块**                            **内容**
  ----------------------------------- --------------------------------------
  结论                                直接告诉农户当前最需要知道的事情

  要点                                列出 1---3 条关键原因或风险

  来源                                说明信息来自规则、传感器、气象或农业
                                      AI 等

  下一步                              给出农户可以立即执行的动作
  --------------------------------------------------------------------------

# 第五章 产品核心功能：有什么功能？

## 5.1 作物入口

用户进入小程序后选择辣椒、水稻、玉米、小麦、杂草防治、果树、蔬菜大棚、棉花等入口。作物入口既是交互入口，也是
Agent 的上下文信息，为后续问答与播报提供作物背景。

## 5.2 自然语言对话

- 文字提问：直接输入农业问题。

- 语音提问：适合农户在田间操作时快速咨询。

- 意图识别：将问题路由到诊断、种植、气象、知识、播报等 Skill。

- 结构化回答：将复杂回答压缩为清晰的建议卡片。

## 5.3 智能农事播报

系统优先使用规则判断环境风险；当规则没有命中时，再由农业 AI
结合用户画像与传感器数据生成当日简报。

  --------------------------------------------------------------------------------
  **环境条件**            **优先提醒**            **建议方向**
  ----------------------- ----------------------- --------------------------------
  高温                    防暑/高温风险           减少高温时段作业，关注作物胁迫

  低温                    防冻                    关注低温影响，做好防寒措施

  土壤偏干                灌溉                    检查墒情并根据作物需求补水

  降雨                    排水                    提前检查排水沟与田间积水风险

  高湿                    防病                    加强通风、排湿并关注病害风险
  --------------------------------------------------------------------------------

## 5.4 农户档案

记录作物、品种、种植面积、所在地区等信息，并与用户画像互通。

## 5.5 用户画像

画像由显式档案、作物入口、传感器环境标签和历史问答共同构建，并在每次对话后增量更新。

## 5.6 设备与环境数据

支持外部传感器/网关上报温湿度、土壤、光照、降雨等数据。尚未接入真实设备时，可以通过
Mock 数据完成前后端联调。

# 第七章 页面之间的业务逻辑

## 7.1 新用户首次使用

微信登录 → 建立基础账户 → 填写农户档案 → 选择作物 → 可选绑定传感器 →
生成初始用户画像 → 进入首页。

## 7.2 日常咨询

首页/作物入口 → 输入文字或语音 → 意图识别 → 条件路由 → 调用专业 Skill →
结果合并 → 输出建议卡片 → 保存历史问答 → 增量更新画像。

## 7.3 查看今日播报

打开首页 → 获取最新传感器数据 → 读取作物与用户画像 → 规则匹配 →
命中则直接输出提醒；未命中则调用农业 AI → 生成当日简报。

## 7.4 设备数据链路

传感器 → 网关/API → /sensors/data → SensorService → 最新读数 → 环境标签
→ BroadcastService / Agent → 农事建议。

## 7.5 页面逻辑总图

用户登录 → 农户档案 → 作物入口 → 首页 →（AI咨询 / 今日播报 / 设备管理 /
历史记录）→ 对话结束 → 更新用户画像 → 为下一次播报与问答提供上下文。

# 第八章 核心业务链路与 Agent 工作流

## 8.1 核心链路

外部传感器感知环境数据 → 小程序选择作物入口 → 自然语言对话 →
综合传感器 + 用户输入 + 历史问答 → 用户画像 → 智能播报（规则优先 + 农业
AI 兜底）→ 简洁卡片输出。

## 8.2 Agent 工作流

农户输入 + 传感器数据 + 作物入口 + 用户画像 → 意图识别 → 条件路由 → 专业
Skill → 结果合并 → 简洁农事建议卡片。

## 8.3 意图类型

  --------------------------------------------------------------------------------
  **意图**                            **用途**
  ----------------------------------- --------------------------------------------
  diagnosis                           作物异常、病虫害等诊断问题

  planting                            种植、施肥、灌溉等农事问题

  weather                             天气与环境相关问题

  knowledge                           农业知识查询

  broadcast                           "现在该注意啥""今天怎么样"等主动播报型需求

  parallel                            需要多个 Skill 并行分析的复杂问题
  --------------------------------------------------------------------------------

## 8.4 Broadcast Skill

新增 broadcast 意图后，BroadcastService
优先根据传感器读数进行规则匹配。高温、低温、干旱、降雨、高湿等条件命中时直接生成简洁提醒；没有命中规则时，再由
BroadcastSkill 调用农业 AI，结合用户画像和传感器数据生成当日简报。

# 第九章 用户画像体系

## 9.1 画像数据来源

  ------------------------------------------------------------------------
  **来源**                            **示例**
  ----------------------------------- ------------------------------------
  显式档案                            作物、品种、地区、种植面积

  作物入口                            用户主动选择辣椒、水稻等

  传感器环境标签                      高温、低温、土壤偏旱、高湿、有降雨

  历史问答                            常问作物、关注主题、经验水平
  ------------------------------------------------------------------------

## 9.2 画像字段

crops / region / concerns / expertise_level / environment_tags /
summary。

每次对话结束后，ProfileService 对画像进行增量更新。

## 9.3 画像的实际作用

- 帮助 Agent 理解"这个农户是谁、种什么、在哪里种"。

- 帮助播报系统判断哪些风险与当前农户更相关。

- 帮助农业 AI 在回答时减少重复询问，提高个性化程度。

- 沉淀长期农业服务数据，为后续智能化升级提供基础。

# 第十章 传感器与智能播报机制

## 10.1 传感器数据

系统接收外部传感器或网关上报的温湿度、土壤、光照、降雨等环境数据。没有真实设备时，可以通过
/sensors/mock 生成模拟数据。

## 10.2 规则优先机制

  -------------------------------------------------------------------------
  **配置项**                **默认阈值**            **业务含义**
  ------------------------- ----------------------- -----------------------
  BROADCAST_TEMP_HIGH       35.0℃                   高温防暑

  BROADCAST_TEMP_LOW        5.0℃                    低温防冻

  BROADCAST_SOIL_DRY        20.0%                   土壤干旱灌溉

  BROADCAST_HUMIDITY_HIGH   85.0%                   高湿防病
  -------------------------------------------------------------------------

## 10.3 为什么采用"规则 + AI"

规则适合处理明确、可验证、需要稳定输出的环境风险；AI适合处理复杂、开放、需要综合上下文的问题。二者结合可以避免所有问题都交给大模型，同时保留
AI 对复杂农业场景的兜底能力。

## 11.4 交互设计原则

- 语音优先：降低输入门槛。

- 大字化卡片：适配农业场景下的快速阅读。

- 极简操作：尽量减少层级和复杂设置。

- 结论优先：先告诉用户应该做什么，再补充原因。

# 第十四章 质量保障与评估机制

## 14.1 自动化评估

backend/harness/包含质量评估与测试集，可通过 /api/v1/harness/run
运行质量评估。方案中设定默认评分阈值为 90%。

## 14.2 评估方向

- 意图识别是否正确。

- 是否调用正确的 Skill。

- 传感器风险是否被正确识别。

- 建议是否简洁、可执行。

- 来源与下一步是否完整。

- 异常情况下是否能够安全降级到 Mock 或兜底逻辑。

# 第十五章 产品创新点与商业化方向

## 15.1 产品创新点

  ----------------------------------------------------------------------------------------
  **创新点**                          **说明**
  ----------------------------------- ----------------------------------------------------
  从"问答"到"主动播报"                系统能够根据环境变化主动提醒，而不是等待农户提问。

  多源信息融合                        融合传感器、作物入口、显式档案和历史问答。

  规则 + AI 双层决策                  明确风险优先规则处理，复杂问题交给农业 AI。
