# T4-04 语音朗读与语音输入

## 这一项要做什么

把"能听"和"能说"两条无障碍路径补齐：提示条目与处方卡可被农户点一下就读出来，问诊输入以语音为主、打字为备选。两条路径的边界必须同时立住——小程序只做"农户主动打开时朗读"，不做后台播报，也不承诺到点自动响；方言语音识别的实现方式尚未确定，因此接口要按可替换设计，先接一个能跑通的实现，把方言能力作为同一接口下的可替换后端，而不是写死在页面里。现有的 `chat.ts` 里 `playVoice` 只弹一个"语音播放中…"的 toast、`toggleVoice` 弹"语音功能开发中"，两处都是占位，需要替换为真实能力。

## 实现要点

### 一、边界：只做主动朗读

产品说明书 4.6 功能点 4 与附录 A5 的结论要落在代码里，而不是只写在注释里。落地方式有三条硬约束：

第一，不注册后台播放。不申请 `wx.setBackgroundAudioOption` 之外的音频后台权限，不调用 `backgroundAudioManager`，朗读一律用 `innerAudioContext` 或 `plugin` 的前台能力。不写定时器在页面不可见时触发朗读。这三条在代码评审时逐条核对。

第二，朗读不承担触达职责。首页提示的新增与提醒由 T3-12 的一次性订阅消息链路负责，朗读只在农户已经打开页面、且主动点击时才发生。`voice.ts` 不导出任何带 `auto` 语义的方法，方法名全部是动词加对象（`speak`、`stopSpeaking`、`startRecord`、`stopRecord`），从命名上堵住"自动播报"的想象空间。

第三，朗读入口明确。提示条目与处方卡各有一个 `.tip-read-btn`，点击即读该条内容，再点一次停止；朗读中切到其他条目则先停后读。产品说明书 4.7.2 要求"保留无限次重听"，因此不做任何次数限制与冷却。

### 二、可替换接口设计

A12 未定，所以两条能力都走适配器。`utils/voice.ts` 只暴露与实现无关的接口，页面对它编程。

```typescript
// miniprogram/utils/voice.ts
export interface TtsAdapter {
  /** 朗读一段中文文本；多次调用同一句应能重新播放（无限次重听） */
  speak(text: string): Promise<void>
  /** 立即停止当前朗读；未在朗读时应安全返回 */
  stop(): void
  /** 供页面查询是否正在朗读，用于切换按钮图标 */
  isSpeaking(): boolean
}

export interface AsrAdapter {
  /** 开始录音并识别；返回识别文本与是否用了方言通道 */
  recognize(opts: { dialect?: boolean }): Promise<{ text: string; viaDialect: boolean }>
  /** 取消本次识别，不返回文本 */
  cancel(): void
}

/** 适配器注册点：A12 定稿后，只替换这里返回的实现，页面代码不动 */
export function getTtsAdapter(): TtsAdapter { /* 返回 tts-default 或后续实现 */ }
export function getAsrAdapter(): AsrAdapter { /* 返回 asr-default 或方言后端 */ }
```

`viaDialect` 这个字段是为 A12 预留的：无论最终走自建模型还是第三方服务，页面只需知道"这次识别是否走了方言通道"，用于在识别结果不准时给农户更友好的提示（例如"没听清，可以再说一次，或者打字告诉我"）。接口定成这样，A12 之后的选择只影响 `getAsrAdapter` 的返回值，`chat.ts` 与 `index.ts` 不需要改。

### 三、默认适配器的实现

`tts-default.ts` 用 `wx.createInnerAudioContext` 播放后端或平台返回的语音。若当前后端不提供 TTS 接口，则退化为"平台朗读"路径：调用 `wx.createInnerAudioContext` 播放由 TTS 服务生成的临时音频；如果两者都不可用，`speak` 必须**明确失败**并让页面给出"朗读暂不可用"的提示，不允许静默无响应或弹假 toast。现有 `playVoice` 弹"语音播放中..."的假反馈必须在本次改造中删除。

`asr-default.ts` 用 `wx.getRecorderManager` 录音并调用识别服务，在 A12 未定前先做成"普通话识别 + `viaDialect` 恒为 false"的最小实现，并在文件头注释写明"本实现为占位，方言后端待 A12 定稿后替换；接口契约不得更改"。这是全局约定第八节要求的处理方式：在 A12 给出明确答复前按占位方式实现，不擅自决定。

两个适配器都要处理授权拒绝：录音授权被拒时返回可读错误，页面提示"需要允许使用麦克风才能语音提问，也可以直接打字"，并保证打字输入路径完全不受影响（4.7.3 功能点 4 与 4.6 功能点 5 的要求：核心链路不因单项能力不可用而断裂）。

### 四、语音输入优先的交互

4.7.3 功能点 3 要求语音是"第一输入方式而非备选"。落地为三点：输入栏左侧的语音按钮是主入口，视觉权重大于输入框（现有 `chat.wxml` 的顺序已经是语音在前、输入框居中、发送在后，顺序正确，需提升语音按钮的视觉权重）；录音期间显示清晰的阶段反馈（"正在听…"加波形或计时），农户松手即结束，不要求点击两次；识别结果先填入输入框让农户确认再发送，而不是识别完直接提交——目标用户对"发错了"的容忍度低，且 4.7.3 功能点 6 要求误发的提问可撤回或重新编辑。

录音按钮的热区按 T4-02 的 `.tap-88` 处理，现有 `.voice-btn .voice-icon` 为 48rpx、`.voice-label` 为 22rpx，均需按 T4-02 的清单上调；本项只负责行为，不重复定义尺寸。

### 五、转人工场景的朗读按钮

技术方案 16.5 与产品说明书 4.2 提到"建议咨询当地农技站"的转人工路径（连续 4 轮未收敛或超出能力边界）。转人工消息在对话流里以卡片形式出现，内容包含"为什么建议转人工"与"去哪里找农技站"。这类消息同样需要朗读按钮，理由与提示条目一致：不识字或视力障碍的农户在被告知"要去找人"时更需要听清这句话。

实现上区分两条消息类型：普通 AI 回复的朗读按钮为 `.voice-play-btn`（现有类，需提到 `.tap-88`），转人工消息的朗读按钮为独立的 `.tip-read-btn` 且文案为"把这段读给我听"，因为转人工内容更长、更关键，需要更明确的引导。朗读内容取 T2-23 上下文包中面向农户的部分，**不朗读内部字段**（置信度数值、槽位名、内部标识），这与 T3-07"模板出事实、模型只改写"的口径一致：能读的是已定稿的农户文案。

### 六、朗读与执行回执的关系

首页提示条目上的朗读按钮与执行勾选是两个并列的小热区，尺寸均为 `.tap-88`。顺序上把朗读放在勾选左侧，避免农户在误触时把"听"点成"完成"。两者点击区域不重叠，间距取 `--space-inline`。朗读不改变提示条目的任何状态（不改 `done`、不触发 T3-15 台账写入），保证"听一遍"这个动作没有副作用。

### 七、失败与降级

朗读失败、识别失败、授权拒绝三种情况都要给出农户能懂的原因和下一步动作。朗读失败提示"现在读不出来，稍后再试"并提供重试；识别失败提示"没听清，再说一次，或者打字告诉我"；授权拒绝提示"需要允许使用麦克风"。三种都不显示技术错误码。这一条与产品说明书 4.6 功能点 5 一致，也是 6.3 兜底三"不允许整体页面不可用"在语音链路上的落地。

## 验收标准

- `node tests/ui/test_voice_contract.mjs` 通过，含四组断言：`getTtsAdapter()` 与 `getAsrAdapter()` 的返回对象具备接口声明的全部方法；`speak` 在同一文本上可被连续调用两次且第二次仍会播放（无限次重听）；`stop()` 在未播放时调用不抛异常；`cancel()` 在未录音时调用不抛异常。
- 断开放配器：把 `getTtsAdapter` 替换为 `speak` 恒抛异常的桩，断言页面收到失败并展示可读提示，不出现空白反馈或假 toast；`grep -n "语音播放中" miniprogram/pages/ai/chat.ts` 无输出，证明占位反馈已删除。
- `grep -n "backgroundAudioManager\|setBackgroundAudio\|autoPlay" miniprogram/utils/voice.ts miniprogram/pages/ai/chat.ts miniprogram/pages/index/index.ts` 无输出，证明未注册任何后台播放能力。
- 真机验证：在首页点击一条提示的朗读按钮，听到该条文本；连续点击两次，两次都能重听；朗读过程中点击另一条，前一条立即停止。把小程序切到后台，断言音频停止且不继续播放。
- 真机验证：在咨询页按住语音按钮说一句普通话问题，松手后文本填入输入框等待确认；拒绝麦克风授权后再次点击，出现可读提示且打字发送路径正常可用。
- 转人工消息（构造连续 4 轮未收敛的会话，或用 `USE_MOCK_LLM` 返回转人工信号）出现时带独立朗读按钮，点击后朗读内容不含置信度数值与内部槽位名；对朗读文本做一次 `grep` 校验，不出现"置信度""槽位""process_id"等内部词。
- `miniprogram/utils/voice-adapters/asr-default.ts` 文件头含 A12 待定说明，且 `viaDialect` 字段存在于接口与返回值中，替换适配器时页面代码零改动（用一个返回 `viaDialect: true` 的桩适配器验证页面正常显示结果）。
- `ruff` 与前端静态检查不受影响；新增的 `.ts` 文件通过项目既有的 TypeScript 编译（微信开发者工具无编译错误）。
- 8 个页面在语音能力不可用（模拟器无麦克风）时仍可完成登录、首页、提问、查看结论四条核心链路，符合 4.7.3 功能点 4 与 6.3 兜底三。
