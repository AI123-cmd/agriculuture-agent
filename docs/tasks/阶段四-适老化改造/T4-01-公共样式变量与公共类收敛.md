# T4-01 公共样式变量与公共类收敛

## 这一项要做什么

把字号、行距、间距、热区、对比度这五类适老约束从各页面 WXSS 中抽出来，收敛成一份公共 token 与一套公共类，让"字号下限 32rpx、行距不低于 1.3 倍、热区不小于 88rpx"从每个页面的自觉遵守变成全局唯一的定义。当前 `miniprogram/app.wxss` 全文只有一个 `.container` 规则，没有任何字号或热区定义；8 个 WXSS 文件各自声明字号，实测 58 处小于 32rpx。只要定义仍散落在页面里，任何一个新页面或一次小改都会把规范重新拉垮，因此本项是 T4-02 至 T4-04 的前置。

## 前置依赖

- 无上游任务依赖，是本阶段的第一项。
- 现有改造起点：`miniprogram/app.wxss`（仅 9 行，只有一个 `.container`）、`pages/index/index.wxss`、`pages/ai/chat.wxss`、`pages/mine/mine.wxss`、`pages/history/list.wxss`、`pages/profile/farmer-profile.wxss`、`pages/env/env.wxss`、`pages/login/login.wxss`、`custom-tab-bar/index.wxss`。
- 可复用的既有先例：`pages/login/login.wxss` 已在 `page` 选择器上定义 `--page-padding` 与 `--max-content` 两个 CSS 变量并被 `var()` 使用，说明本项目的小程序基础库版本支持在 WXSS 中使用 CSS 自定义属性，本项沿用同一机制，不引入新的技术方案。
- 外部环境要求：微信开发者工具可编译，基础库版本与线上一致（产品说明书 4.7.3 功能点 4 要求核心链路在低版本环境可用，因此不依赖新版本 API）。

## 实现要点

### 一、为什么必须收敛到公共样式层

三条依据指向同一结论。第一，现状是真正的散落：`app.wxss` 里没有任何字号定义，而 8 个页面 WXSS 各写各的，实测 58 处字号字面量小于 32rpx，其中 20rpx 1 处、22rpx 5 处、24rpx 10 处、26rpx 16 处、28rpx 19 处、30rpx 7 处；同一语义的文字在不同页面取不同值，例如"辅助说明"这一类在 `index.wxss` 是 24 与 26，在 `env.wxss` 是 20 与 22，在 `chat.wxss` 是 22 与 26。第二，同一组件的样式已经分叉：`.card` 与 `.card-title` 在 `index.wxss`、`env.wxss`、`farmer-profile.wxss` 各自定义，`.card` 的圆角取 16rpx 与 20rpx 两种、内边距取 `36rpx` 与 `36rpx 32rpx 12rpx` 两种。第三，产品说明书 9.2 第 12 条把"收敛到公共样式层"写成必须修复项，9.1 的样式层约束直接写明"禁止各页面自行定义字号与热区"。逐页手调无法通过 6.5 红线第 1 条的逐页核验，因为它没有单一来源可供核对，改完这一页会破坏上一页。

收敛的形态是"两段式"：字号阶梯、行距、间距、热区、颜色这五类只允许在 `tokens.wxss` 里出现字面量；页面只允许使用公共类或 `var(--token)`。这样一次上调只改一个文件，新页面天然继承。

### 二、token 定义骨架

```css
/* miniprogram/styles/tokens.wxss
   全项目唯一允许出现字号与热区字面量的文件 */

page {
  /* ---- 字号阶梯：下限 32rpx，产品说明书 4.7.2 与附录 A10 ---- */
  --font-caption: 32rpx;   /* 辅助说明、单位、来源标注，即下限值 */
  --font-body:    36rpx;   /* 正文、提示文案、对话气泡 */
  --font-title:   40rpx;   /* 卡片小标题、页面副标题 */
  --font-heading: 44rpx;   /* 区块标题、卡片标题 */
  --font-display: 52rpx;   /* 页面主标题、核心数值 */

  /* ---- 行距：不低于 1.3 倍 ---- */
  --line-tight: 1.4;       /* 与 40rpx 及以上字号搭配 */
  --line-body:  1.5;       /* 与 36rpx 正文字号搭配，实际行距 54rpx */

  /* ---- 间距 ---- */
  /* 段间距下限 = 正文字号 × 行距 × 1.3 = 36 × 1.5 × 1.3 = 70.2rpx */
  --space-para:    72rpx;  /* 段间距，向上取整到 72rpx */
  --space-heading: 24rpx;  /* 标题与其所属正文之间，属标题间距，不参与段间距核验 */
  --space-block:   72rpx;  /* 模块间距，与段间距同值，避免一屏出现第三种垂直节奏 */
  --space-inline:  24rpx;  /* 行内水平间隔 */

  /* ---- 热区 ---- */
  --tap-min: 88rpx;             /* 可点击热区下限，宽与高须同时满足 */
  --btn-primary-height: 96rpx;  /* 关键操作按钮：发送、更新提示、已执行、提交 */
  --tabbar-height: 120rpx;      /* 底部导航高度，单个 Tab 的点击区域高度即此值 */

  /* ---- 颜色与对比度：正文色对背景须满足可读性要求 ---- */
  --text-primary: #1a1a1a;  /* 白底对比度约 17.4:1 */
  --text-body:    #333333;  /* 白底约 12.6:1 */
  --text-muted:   #595959;  /* 白底约 7.0:1，替代现有 #999 辅助文字 */
  --text-inverse: #ffffff;  /* 深绿底 #2e7d32 上约 5.1:1 */
  --text-brand:   #2e7d32;
  --bg-page:      #eef5ec;
  --bg-card:      #ffffff;
  --line-divider: #e0e0e0;
}
```

三个取值的推导要写清，否则执行者会自行改动。`--space-para` 取 72rpx 是因为正文字号 36rpx 乘行距 1.5 得 54rpx，再乘 1.3 得 70.2rpx，72rpx 是满足"大于"的最小整数档；如果执行者把正文字号改成 40rpx，本值必须同步改为 78rpx，两者在文件内以注释互相标注。`--text-muted` 取 #595959 而不保留现有 #999999，因为 #999999 在白底上的对比度约 2.85:1，不满足 4.7.2 的对比度行；#595959 约 7.0:1，视觉上仍明显弱于正文色。`--line-body` 取 1.5 而不贴着 1.3 的下限，是因为 1.3 是硬门槛，留出余量可以避免后续微调字号时踩线。

字号可调一行（4.7.2 的"支持系统字号缩放跟随"）的要求是**不锁定字号**：token 值用 rpx 而不是 px，不使用 `text-size-adjust`，不写 `font-size: 0` 之外的强制覆盖，页面不设置 `!important` 锁死字号。这一点不产生额外代码，但要在 `styles/README.md` 中写明为纪律。

### 三、公共类

```css
/* 字号类：页面只用类，自身不再写 font-size */
.t-caption { font-size: var(--font-caption); line-height: var(--line-body); color: var(--text-muted); }
.t-body    { font-size: var(--font-body);    line-height: var(--line-body); color: var(--text-body); }
.t-title   { font-size: var(--font-title);   line-height: var(--line-tight); color: var(--text-primary); font-weight: 600; }
.t-heading { font-size: var(--font-heading); line-height: var(--line-tight); color: var(--text-brand); font-weight: 600; }
.t-display { font-size: var(--font-display); line-height: var(--line-tight); color: var(--text-primary); font-weight: 700; }
.t-body + .t-body { margin-top: var(--space-para); }   /* 段间距由类保证，不逐页手调 */

/* 热区类：外层保证 88rpx 可点，内层负责视觉尺寸 */
.tap-88 {
  min-width: var(--tap-min);
  min-height: var(--tap-min);
  display: flex; align-items: center; justify-content: center;
  flex-shrink: 0;
}

/* 关键操作按钮 */
.btn-primary {
  height: var(--btn-primary-height);
  border-radius: 16rpx;
  font-size: var(--font-body);
  font-weight: 600;
  display: flex; align-items: center; justify-content: center;
}

/* 卡片与模块：合并此前三处各自定义的 .card 与 .card-title */
.card {
  background: var(--bg-card);
  border-radius: 20rpx;
  padding: 36rpx 32rpx;
  box-shadow: 0 2rpx 16rpx rgba(0, 0, 0, 0.04);
  box-sizing: border-box;
}
.card-title {
  font-size: var(--font-heading);
  line-height: var(--line-tight);
  font-weight: 600;
  color: var(--text-brand);
  margin-bottom: var(--space-heading);
}
.block { margin-top: var(--space-block); }
.block:first-child { margin-top: 0; }

/* 执行勾选：视觉 56rpx，热区靠外层撑满 88rpx */
.check-circle {
  width: 56rpx; height: 56rpx;
  border: 2rpx solid #c8e6c9;
  border-radius: 50%;
  background: var(--bg-card);
  display: flex; align-items: center; justify-content: center;
}
.check-circle .check-icon { font-size: var(--font-caption); color: var(--text-brand); font-weight: bold; }
```

`.tap-88` 与内层视觉尺寸分离是本项最重要的写法。现有 `index.wxss` 的 `.broadcast-check` 把 44rpx 同时当作视觉尺寸和热区，直接放大到 88rpx 会让勾选圆圈在视觉上突兀。正确做法是外层用 `.tap-88` 撑起 88rpx 的可点区域，内层 `.check-circle` 保持 56rpx 的视觉尺寸，并在需要时用负 margin 或 `justify-content` 让圆圈与文字基线对齐。这个模式在 T4-02 要被复用到至少 5 处（首页勾选、历史删除、我的菜单项箭头、Tab 项、登录复选框）。

### 四、禁止各页面自行定义字号与热区的落地方式

只在文档里写"禁止"没有约束力，本项用三步让它可执行、可检查、可例外。

第一步，**字面量门禁**。`scripts/check_wxss_tokens.mjs` 扫描 `miniprogram/**/*.wxss`，除 `styles/tokens.wxss` 外，任何文件出现以下形态即报错并给出文件与行号：

- `font-size:` 后跟数字 + rpx
- `width` / `height` / `min-width` / `min-height` 后跟小于 88rpx 的数字 + rpx
- `line-height:` 后跟无单位小数
- `margin-top` / `padding` 后跟垂直方向小于 72rpx 的模块级数值（仅对 `.block` 类生效，不误伤行内间距）

第二步，**例外登记而非静默放行**。确有必要保留字面量的（例如纯装饰性图标尺寸、1rpx 分隔线、`env(safe-area-inset-*)` 计算式），登记到 `scripts/wxss-token-whitelist.json`，每条含 `file`、`match`、`reason` 三个字段，脚本命中白名单则跳过并打印已登记条数。这与全局约定第三节"不允许 `# noqa` 跳过，确有例外需在白名单里显式登记并写明理由"同形。

第三步，**页面声明**。每个页面 WXSS 首行必须出现 `@import '../../styles/tokens.wxss';`，`custom-tab-bar` 因是自定义组件、不继承页面样式，路径为 `@import '../styles/tokens.wxss';` 并自行导入一份。脚本检查该 import 是否存在，缺失即报错。这样"页面没引 token"这个最常见的退化原因会被当场拦住。

### 五、白名单的收口规则

白名单条目只允许三类：装饰图形（不影响可读性与可点性，如 `location-pin` 的 24rpx、`broadcast-dot` 的 12rpx）、结构性 1rpx 分隔线、`calc()` 中与安全区相关的偏移量。凡是承载文字的元素、凡是可点击元素，一律不允许进白名单。脚本在输出里按这三类分组统计，任何新增条目若落在第三类之外，需要在 PR 描述里写明理由，供评审判断。

## 验收标准

- `node scripts/check_wxss_tokens.mjs` 返回 0，输出形如 `scanned 9 wxss files, 0 violations, 7 whitelisted entries (decoration 4 / divider 2 / safe-area 1)`。
- 故意在 `pages/ai/chat.wxss` 加入 `font-size: 24rpx;` 后重跑脚本，返回非 0 且输出精确指出该文件与行号；删除后恢复为 0。这一步证明门禁真的在工作，而不是恒真。
- `grep -rn "font-size:" miniprogram --include=*.wxss` 的结果中，除 `styles/tokens.wxss` 外不出现任何 `rpx` 字面量（`em`、`inherit` 允许）。
- 每个页面 WXSS 首行含 `@import` 指向 `styles/tokens.wxss`；`grep -c "@import" miniprogram/pages/*/*.wxss miniprogram/custom-tab-bar/*.wxss` 每个文件返回 1。
- 把 `--font-body` 从 36rpx 改为 40rpx、`--space-para` 从 72rpx 改为 78rpx，重新编译后所有引用正文字号与段间距的页面同步变化，不需要改动任何页面 WXSS。这一步证明收敛生效。
- 微信开发者工具中打开首页、咨询页、我的、环境页、农户档案页、登录页，均无样式丢失（无元素回落到浏览器默认字号 16px）。
- `miniprogram/styles/README.md` 存在，含 token 清单表与白名单申请流程，且与 `tokens.wxss` 中实际定义的 token 名称逐一对应。
