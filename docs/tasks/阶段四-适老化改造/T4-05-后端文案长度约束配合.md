# T4-05 后端文案长度约束配合

## 这一项要做什么

在产品说明书第四步里，前端是主体，但有两处必须由后端在生成侧就约束住：提示文案的可见字数上限、问诊问题的并列选项数量上限。技术方案 16.5 明确这两处"如果留到前端截断，会在适老化验收时反复返工"。本项把约束做实到配置层与契约层：文案在快照生成时按句子边界收敛到字数上限并落库，问诊选项在槽位设计时定死上限并由契约校验，前端只负责按后端给定的内容渲染，不做任何裁剪。

## 前置依赖

- T3-07 的文案生成链路（`render_template` / `rewrite_with_model` / `build_text`）与 `output_template.max_chars` 的取值方式；T3-08 的快照生成链路与幂等锁，本项的字数收敛发生在 `build_text` 之后、落库之前。
- T3-01 的 `PromptItem` 字段：`callout`（`String(30)`）、`fact` / `impact` / `action`（`Text`），以及 `suppressed` 字段（用于记录因超长被收缩的条目）。
- T2-10 的 `InterviewQuestion`（`options: list[str] | None`、`answer_type`）与 `InterviewBatch`（`questions` 裁至 2 的写法）；T2-02 的 `SlotSpec`；T2-03 的配置加载校验；T2-04 的七条流程 YAML；T2-17 的追问候选池筛选器。
- T2-13 的 Agent 基类降级路径（契约校验失败时重试一次，再失败降级为模板），本项的选项上限校验失败应走同一条降级路径，而不是抛错中断问诊。
- 外部环境要求：无额外服务依赖；`USE_MOCK_LLM=true` 下也应能验证两条约束（构造超长 mock 响应与超量选项响应）。

## 实现要点

### 一、为什么必须在后端控制

前端截断有三个具体的坏处，都是适老化验收时会暴露的。第一，`text-overflow: ellipsis` 或 `-webkit-line-clamp` 会把句子切在半途，农户读到"建议傍晚灌水降..."会以为内容没加载完，反复刷新或反复重听；产品说明书 4.7.2 的语音朗读行要求朗读内容完整，被截断的文案念出来是残句。第二，前端截断丢失的信息无法回收，而句子边界的信息（"避开中午"这类限定条件）恰恰是行动句的关键部分。第三，前端截断是逐页面重复实现，与 T4-01"禁止各页面自行定义"的方向相反，会再制造一处样式与逻辑的散落。

因此在后端收敛的正确位置是文案生成之后、落库之前：`PromptItem` 的 `fact / impact / action` 三段在入库时就已经是完整且不超限的句子，前端拿到的任何一条都可以直接铺满展示或整段朗读。

### 二、提示文案的字数上限

上限分两级：单条提示的可见总长，以及各段的分配。

```python
# app/broadcast/limits.py
"""提示文案长度约束：在生成侧收敛，前端不做截断。"""

MAX_ITEM_CHARS: int = 100      # 单条提示可见总长（含标点），32rpx 字号下约 6 行
MAX_CALLOUT_CHARS: int = 20    # 呼告短，字段本身为 String(30)
MAX_FACT_CHARS: int = 32       # 事实
MAX_IMPACT_CHARS: int = 24     # 影响
MAX_ACTION_CHARS: int = 24     # 行动
_SENTENCE_END = "。！？；"


def fit_item_text(text: str, limit: int) -> str:
    """超长则退到最近句末标点；无句末标点才硬切。绝不返回半句。"""
    text = text.strip()
    if len(text) <= limit:
        return text
    head = text[:limit]
    idx = max((head.rfind(ch) for ch in _SENTENCE_END), default=-1)
    return head[: idx + 1] if idx >= 0 else head
```

100 这个数字来自版面而不是来自习惯：正文字号 36rpx，一屏内容宽约 690rpx，每行约 19 字，100 字约 6 行，乘 1.5 行距得 324rpx，加上级别标签与勾选热区后单条提示不超过 400rpx，三条提示加标题仍可在 iPhone SE 的一屏内呈现。四条分配值之和为 100，保证了"逐段不超即总长不超"。

`fit_item_text` 与 T3-07 已有的截断逻辑的关系要说清，避免重复实现：T3-07 的截断作用于"模型改写结果对照 `output_template.max_chars`"，粒度是整条文案，用于控制模型输出长度；本项的 `fit_item_text` 作用于逐段字段，是落库前的最终收敛，粒度是段。两者叠加执行的顺序是 `模型输出 → T3-07 裁到 max_chars → 拆段 → fit_item_text 逐段收敛 → 落库`。T4-05 的 `MAX_ITEM_CHARS` 与流程配置的 `max_chars` 取较小值作为有效上限，这一点在 `snapshot.py` 里显式写出，不默认执行者会自行取小。

四级配置的优先级要写死：`流程配置 output_template.max_item_chars`（可覆盖）> `limits.MAX_ITEM_CHARS`（默认）> 逐段常量。七条流程的 YAML 里写 `output_template.max_item_chars`，缺省则用默认值，`loader.py` 校验其必须落在 60 至 140 之间，超出区间直接报错——防止某条流程把上限调大后让适老约束失效。

超长且无法在句末安全收敛的条目（例如一整段没有句号的描述），处理方式是收缩后再入库并把 `suppressed` 置为 `True`，而不是丢弃。理由与 T3-01 对 `suppressed` 的定义一致：复盘"哪些内容长期被压制"依赖这些记录；同时农户侧仍能看到一条更短但不残缺的提示。

### 三、问诊问题的并列选项数量上限

上限同样分两级：单个问题的选项数、以及一轮问诊的选项总数。

```python
# app/process_config/models.py（片段）
MAX_OPTIONS_PER_QUESTION: int = 4   # 含"说不清"这一类跳过项
MAX_OPTIONS_PER_BATCH: int = 6      # 一轮最多 2 问，2 × 3 正常情形


class SlotSpec(BaseModel):
    ...
    options: list[str] = []          # 并列选项，长度不得超过 MAX_OPTIONS_PER_QUESTION
    @field_validator("options")
    @classmethod
    def _cap_options(cls, v: list[str]) -> list[str]:
        if len(v) > MAX_OPTIONS_PER_QUESTION:
            raise ValueError(
                f"槽位选项数 {len(v)} 超过适老上限 {MAX_OPTIONS_PER_QUESTION}"
            )
        return v
```

上限取 4 的依据有两处。一是产品说明书 4.2.2 给出的既有问诊示例是三个并列选项（"打过 / 没打过 / 记不清"），T2-10 又要求单选与多选必须固定包含一个跳过项，因此"三个实质选项加一个跳过项"是自然上限，`4` 是把这个自然上限写成常量。二是版面：88rpx 的热区在 690rpx 内容宽上一行最多容纳四列，超过四列会压缩到 88rpx 以下，直接违反 4.7.2 的热区下限。选项上限因此不是偏好问题，而是与热区下限的算术约束绑定：`每列宽度 ≥ 88rpx` 且 `列间距 ≥ 24rpx` 时，`4 × 88 + 3 × 24 = 424rpx` 仍在一行内，`5` 列则需 512rpx 加边距，在窄屏上会被迫换行或缩窄热区。

两级校验的分工必须分清，否则会出现"配置层拦住了但模型仍在超量输出"的漏洞：

| 层级 | 文件 | 职责 | 失败处置 |
| --- | --- | --- | --- |
| 配置层 | `process_config/loader.py` | 启动时校验 YAML 中每个槽位的 `options` 不超过上限，超限拒绝加载该流程 | 启动失败，该流程不可用（与 9.3"红线配置缺失时该流程不可用"同一口径） |
| 契约层 | `agent/contracts/interview.py` | 模型返回的 `InterviewQuestion.options` 超过上限时裁剪到前 4 项并保留跳过项 | 裁剪而非报错，与 T2-10 对 `questions` 裁至 2 的语义一致 |
| 生成前 | `agents/candidate_pool.py`（T2-17） | 候选池构造阶段就按上限收口，模型只负责生成文本 | 不产生超量候选 |

三层的顺序是"配置定上限、候选池按上限构造、契约兜底裁剪"。契约层的裁剪要保证跳过项不被裁掉：先取出跳过项标记（"说不清""记不清""不知道"这一类，由 T2-10 的跳过项常量给出），裁剪时优先保留它，再从非跳过项里按原顺序取前 3 个。若不这样做，模型把跳过项排在末位时会被裁走，农户就失去了"答不出"这个合法答案，而 4.2.2 明确"未知是合法答案"。

一轮问诊的选项总数上限 6 由 `InterviewBatch` 的校验器实现，写法沿用它对 `questions` 裁至 2 的方式：逐问先各裁到 4，再按总上限 6 依次收敛，优先保证首问的选项完整（首问信息量更大）。

### 四、前端不得截断

本项的另一半是纪律：前端只按后端给定内容渲染。具体为三条禁止，写入 T4-01 的 `styles/README.md` 与前端约定：

- 提示正文不得使用 `-webkit-line-clamp`、`text-overflow: ellipsis`、`white-space: nowrap` 做截断。历史列表的 `.conv-preview` 允许 `ellipsis`，因为它是列表摘要而非提示正文，且点击后可见全文。
- 问诊选项不得由前端丢弃。后端给几个就渲染几个；若版面放不下，按 T4-02 的方式改为两行或纵向排列，而不是删除选项。
- 前端不得写 `slice` / `substring` 处理面向农户的文案。现有 `chat.ts` 的 `saveConversationToStorage` 里有 `.slice(0, 30)` 生成列表预览，属于历史列表标题/预览的用途，允许保留，但需在代码注释中写明"仅用于列表预览，不用于展示正文"。

这三条要有可检查的落点：`grep -rn "line-clamp\|text-overflow\|\.slice(\|substring(" miniprogram/pages` 的结果逐条评审，确认命中项都不涉及提示正文与问诊选项。

### 五、可验证的约束入口

两条约束都要有"能被跑出来"的验证方式，不能只靠评审。字数：构造一条 `fact` 为 80 字的规则结果，调用 `build_text` 后断言返回长度不超过 100 且结尾为句末标点。选项数：构造一个 `options` 有 6 项（跳过项在末位）的 `InterviewQuestion`，断言结果长度为 4、跳过项仍在、前 3 项为原顺序前 3 个。这两条用例放在本任务的测试文件里，不依赖模型。

`USE_MOCK_LLM=true` 下同样可测：让 mock 返回超长文本与超量选项，断言收敛逻辑生效，从而保证 CI 不依赖外部服务也能覆盖这两个约束。

## 验收标准

- `pytest tests/broadcast/test_length_limits.py` 全部通过，含：`fact` 为 80 字且中段有句号的条目收敛后不超过 100 字且以句末标点结尾；`fact` 为 80 字且无句末标点的条目收敛后长度等于上限且不做半句保留策略之外的改动；未超长的条目原样返回（逐字节相等），证明函数不改写合格文案。
- `pytest tests/contracts/test_interview_option_limit.py` 全部通过，含：6 项选项（跳过项在末位）裁为 4 项且跳过项保留；正好 4 项时不裁剪；`InterviewBatch` 两问各 4 项时总选项收敛到 6 且首问完整。
- 配置校验：把某条流程 YAML 中一个槽位的 `options` 写成 5 项，`loader.py` 加载时报错并指出槽位名，该流程不进入注册表；改回 4 项后加载成功。
- 配置校验：把某条流程的 `output_template.max_item_chars` 写成 200，`loader.py` 报"必须在 60 至 140 之间"；改回默认值后加载成功。
- `USE_MOCK_LLM=true` 下让 mock 返回 200 字文案与 6 项选项，断言落库的 `PromptItem` 三段长度均不超限、返回的 `InterviewQuestion.options` 为 4 项，且未出现异常中断。
- `grep -rn "line-clamp\|text-overflow" miniprogram/pages --include=*.wxss` 的结果中，除 `.conv-preview` 与 `.empty-*` 这类列表摘要外无命中；每条命中在评审记录里标注"非提示正文"。
- `alembic upgrade head` 与 `alembic downgrade -1` 均返回 0（`OutputTemplate` 与 `SlotSpec` 的字段变更若涉及流程配置表列，需由迁移承接）。
- `ruff check`、`ruff format --check`、`mypy app` 三条命令均返回 0。
