# T6-08 结构化日志与敏感信息脱敏

## 这一项要做什么

用 structlog 建立结构化日志，并实现统一的脱敏组件 `ObservabilityMasker`：trace 与日志中不写完整农户手机号、不写原始设备 ID 明文。可观测性与隐私在这里是直接冲突的——为了让问题可复盘要把上下文写全，但农户手机号、设备原始标识、精确地理坐标都属于个人与生产信息，"为了可观测把隐私写进了日志"是这类系统最常见的一类合规问题。因此脱敏必须是统一入口而非各处的自觉，靠的是"日志与 trace 只经由一个序列化器落盘"这一工程约束。

## 前置依赖

- 依赖 T6-06 已提供：`current_trace_context()` 返回 `trace_id` 与 `span_id`，日志需带上二者以便把日志与 trace 对账。
- 依赖 T2-46：`gate_audit` 记录完整判定依据；审计表本身存结构化数据（不经日志脱敏），本项处理的是日志与 trace 中的脱敏，二者边界见实现要点五。
- 依赖 T5-03、T5-06：设备绑定与上报链路，设备 ID、`device_sn` 的产生位置；依赖 T5-07：读数校验，可能记录原始报文。
- 依赖 T1-08：`Settings` 与 `ENV`；生产环境日志级别与输出目标由本项按 `ENV` 区分。
- 外部条件：需新增依赖 `structlog`；现有代码用标准库 `logging` 与少量 `print`（`graph.py`、`ai_service.py` 中），需一并收敛。
- 现有起点：`backend/app/core/` 下无日志模块；`backend/app/main.py` 目前无日志初始化；本项在 `app/observability/logging.py` 新建并在 `main.py` 与 worker 入口调用。

## 实现要点

### 一、ObservabilityMasker 实现

```python
# app/observability/masker.py
import re
from typing import Any

PHONE_RE = re.compile(r"(?<!\d)(1[3-9]\d)\d{4}(\d{4})(?!\d)")
DEVICE_SN_RE = re.compile(r"(?<![A-Za-z0-9])([A-Za-z0-9]{6})[A-Za-z0-9\-]{6,}(?![A-Za-z0-9])")
DEFAULT_FIELDS = ("phone", "phone_number", "mobile", "real_name", "address",
                  "device_sn", "device_id", "raw_payload", "latitude", "longitude")

class ObservabilityMasker:
    """日志与 trace 的统一脱敏入口。所有落盘内容必须经 mask()。"""

    def __init__(self, extra_fields: tuple[str, ...] = (), *, mask_geo: bool = False) -> None:
        self._fields = tuple(DEFAULT_FIELDS) + tuple(extra_fields)
        self._mask_geo = mask_geo

    def mask_phone(self, value: str) -> str:
        """138****0000：保留号段与前 3 位便于识别，掩掉中间与末 4 位。"""
        return PHONE_RE.sub(lambda m: f"{m.group(1)}****{m.group(2)}", value)

    def mask_device(self, value: str) -> str:
        """保留前 6 位便于定位批次，其余替换为固定长度的 *。"""
        return DEVICE_SN_RE.sub(lambda m: f"{m.group(1)}{'*' * 6}", value)

    def mask_value(self, key: str, value: Any) -> Any:
        if key not in self._fields:
            return value
        if isinstance(value, str):
            return self.mask_phone(self.mask_device(value))
        return "***"                     # 非字符串的敏感字段整体替换

    def mask(self, event_dict: dict[str, Any]) -> dict[str, Any]:
        """递归脱敏：日志字段可能嵌套（如 prescription.facts_provenance）。"""
        return {k: self._walk(k, v) for k, v in event_dict.items()}
```

四处理由：

- **手机号保留前 7 位中的号段与后 4 位被掩**：完全掩成 `***` 会使"同一农户的两条日志无法关联"，保留号段与尾部有助于排查且不构成可识别信息（`138****0000`）。这是"可观测性可用"与"隐私"的平衡点，写进注释。
- **设备 ID 保留前 6 位**：设备批次定位需要前缀，完整 `device_sn` 可反查农户归属，属敏感。
- **`raw_payload` 与 `latitude` / `longitude` 默认脱敏**：设备原始报文可能含农户自定义字段，坐标属个人位置信息。`mask_geo` 开关允许本地开发打开（本地调试需要真实坐标），生产启动检查应拒绝 `mask_geo=False`。
- **递归**：`mask` 必须递归到嵌套 dict 与 list，否则 `prescription={"facts_provenance": {...}}` 这类结构会漏掉内层字段。这是本组件唯一容易做错的地方。

### 二、structlog 配置

```python
# app/observability/logging.py
def configure_logging(settings: Settings) -> None:
    masker = ObservabilityMasker(extra_fields=settings.MASK_EXTRA_FIELDS,
                                 mask_geo=settings.ENV != "production")
    processors = [
        structlog.contextvars.merge_contextvars,        # 绑定 trace_id / consultation_id
        add_trace_context,                              # 从 T6-06 的 current_trace_context 取值
        structlog.processors.add_log_level,
        structlog.processors.TimeStamper(fmt="iso", utc=True),
        wrap_for_masker(masker),                        # 脱敏处理器，必须在渲染之前
        (structlog.processors.JSONRenderer(ensure_ascii=False)
         if settings.LOG_FORMAT == "json" else structlog.dev.ConsoleRenderer()),
    ]
    structlog.configure(processors=processors,
                        wrapper_class=structlog.make_filtering_bound_logger(settings.LOG_LEVEL),
                        logger_factory=structlog.PrintLoggerFactory())
```

三个要点：

- **脱敏处理器必须在渲染器之前**。顺序反了，JSON 体已经成型，脱敏只能对整串正则替换，嵌套结构处理不了。这条写进注释并列在验收标准里。
- **`add_trace_context` 自动注入 `trace_id` / `span_id`**，使日志与 trace 可对账（T6-06 提供取值函数）。同时注入 `consultation_id`（若在上下文里），使"某次问诊的全部日志"可一次取齐。
- **生产用 JSON，开发用 console**。JSON 便于审计检索（4.2 表格的说明"结构化日志，便于审计检索"），console 便于本地阅读。`ensure_ascii=False` 是必需的，否则中文全部转义成 `\uXXXX`，日志不可读。

### 三、contextvars 与请求级绑定

一次问诊的日志分散在多个节点与异步任务里，逐个传 `logger` 不现实。用 `structlog.contextvars` 在问诊入口绑定 `consultation_id`、`user_id`、`process_id`，节点内直接 `logger.info("interview.asked", slots=[...])` 即可带上上下文。注意两点：`asyncio` 任务继承 contextvars，但 asyncio 之外的线程不继承；`contextvars` 必须在请求结束时清理（用中间件在 `finally` 里 `clear_contextvars`），否则跨请求串号，日志会带错 `consultation_id`。串号是这类实现的经典缺陷，`test_logging.py` 用两个并发请求断言互不串号。

### 四、日志与 trace 的字段分工

- **trace 属性**：跨节点的因果与耗时（T6-06），结构化程度高，用于"为什么走这条路"。
- **日志**：单点事件的细节与异常堆栈，用于"这一判定具体是什么"。异常必须用 `logger.exception(...)` 或 `logger.error(..., exc_info=True)`，保留堆栈。
- **不写进日志的**：完整农户手机号、原始设备 ID 明文、原始设备报文（未脱敏）、模型提示词全文（含农户原话）。最后一条容易忽略：提示词里嵌了 `raw_text`（A.2 的 `SlotValue.raw_text` 是"农户原始表述，保留用于复盘"），把它打进日志等于把农户原话写进日志，本项要求提示词只写模板名与版本（`prompt_name`、`prompt_version`），不写内容，内容在 Langfuse 私有化实例里查（T6-07）。

### 五、与 gate_audit 的边界

`gate_audit` 存 `prescription_snapshot` 全量快照，其中可能含农户信息，但它是**业务审计数据**（同库、受归属校验与保留策略约束），不是日志。因此 `gate_audit` 不经过 `ObservabilityMasker`——把审计数据脱敏会破坏"事后复盘完整判定依据"的能力。二者的边界要写清：日志与 trace 面向排障人员，脱敏从严；审计表面向合规复盘，完整保存且访问受控。混为一谈会导致两种错误——要么审计数据被脱敏而失去复盘价值，要么为了"审计完整性"把明文写进日志。

写审计表的日志（如 T2-46 的 `gate_audit_write_failed`）本身仍走脱敏，只记 ID 不记快照内容。

## 验收标准

- `python -m pytest backend/tests/observability/test_masker.py` 通过：`"13800000000"` 脱敏为 `"138****0000"`；`"13912345678"` 脱敏为 `"139****5678"`；`"1360000"`（不足 11 位）不被误伤，原样保留。
- 设备 ID 正例：`"AB12CD345678"` 脱敏为 `"AB12CD******"`；反例：`"A1B2C3"`（恰 6 位）原样保留，不产生 `"******"` 追加。
- 嵌套结构：`mask({"prescription": {"facts_provenance": {"phone": "13800000000"}}})` 返回的内层 `phone` 已脱敏，证明递归生效。
- `mask_geo=False` 时 `latitude` / `longitude` 保留原值；`mask_geo=True` 时被替换；`ObservabilityMasker(mask_geo=False)` 与 `Settings.ENV == "production"` 的组合被启动检查拒绝（指向 T1-08 的 `collect_violations`）。
- `python -m pytest backend/tests/observability/test_logging.py` 通过：`LOG_FORMAT=json` 时每条输出可被 `json.loads` 解析，含 `level`、`timestamp`、`event` 与 `trace_id` 字段；字段顺序不是断言目标。
- 在问诊入口绑定 `consultation_id` 后，该次问诊产生的所有日志行都含同一 `consultation_id`；并发发起两个不同 `consultation_id` 的请求，日志不串号（用两组交错的日志断言）。
- 构造一条含 `phone="13800000000"` 与 `device_sn="AB12CD345678"` 的日志调用，输出的 JSON 中不含 `"13800000000"` 与 `"AB12CD345678"` 子串（用字符串包含断言，覆盖任何形式的泄漏）。
- 异常日志保留堆栈：`logger.exception("node.failed")` 的输出含 `exc_info` 渲染后的堆栈文本，且其中若含手机号仍被脱敏。
- 把脱敏处理器移到渲染器之后，`test_logging.py` 中嵌套结构用例失败，证明顺序断言有效。
- `python -m pytest backend/tests/test_no_print.py` 通过：`app/` 下无 `print(` 语句，无 `logging.info(` 等裸标准库调用（豁免 `structlog` 的 `PrintLoggerFactory` 实现文件与 `alembic/`）。
- `LOG_FORMAT=json` 时日志内容含中文且不出现 `\uXXXX` 转义（`ensure_ascii=False` 生效）。
- `ruff check`、`ruff format --check`、`mypy app` 三条命令返回 0。
