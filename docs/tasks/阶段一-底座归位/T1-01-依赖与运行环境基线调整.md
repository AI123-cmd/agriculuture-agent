# T1-01 依赖与运行环境基线调整

## 这一项要做什么

把后端的运行环境从"MySQL 同步栈 + SQLite 检查点"整体切换到"PostgreSQL 全异步栈"，并一次性补齐静态检查、测试与可观测工具。现有 `backend/requirements.txt` 只声明了 `pymysql` 与 `langgraph-checkpoint-sqlite`，`backend/pyproject.toml` 也只有 `ruff` 的 `line-length` 一项，后续每一份任务都依赖这里新增的包，所以必须最先落地，否则后面所有改造都装不起来、跑不动。

换栈这件事本身不可回避：技术方案 4.3 已论证知识检索需要"向量相似度 + 强元数据过滤"在同一条 SQL 里完成、检查点与业务状态需要事务一致性、环境时序数据量在 TimescaleDB 能力范围内，因此 T1-02 之后的一切都建立在 PostgreSQL 之上。本项只调整依赖与配置基线，不改任何业务代码。

## 前置依赖

- 无任务依赖，是阶段一的第一项。
- 外部环境：可访问的 PyPI 源；本地或容器中的 PostgreSQL 16+（含 `pgvector` 与 `timescaledb` 扩展镜像）；Python 3.11 至 3.12。
- 需要确认的三个版本号：`langgraph` 与 `langgraph-checkpoint-postgres` 的兼容组合（技术方案要求"锁定可用版本"）、`psycopg` 与 `langgraph-checkpoint-postgres` 的驱动一致性、`sqlalchemy` 2.0.30 以上的异步支持。

## 实现要点

### 一、驱动选型：为什么同时保留 asyncpg 与 psycopg

两者不是二选一，而是分工。

- 业务库走 `asyncpg`（`postgresql+asyncpg://`），它是纯异步驱动，性能最好，配合 SQLAlchemy 2.0 的 `create_async_engine` 使用。
- Alembic 与 LangGraph 检查点走 `psycopg`（v3，`postgresql+psycopg://`），因为 `alembic/env.py` 现在是同步 `engine_from_config`，且 `langgraph-checkpoint-postgres` 官方示例使用 `psycopg` 的 `AsyncConnectionPool` + `dict_row`。

这条分工要在 `Settings` 里用两个字段表达（`DATABASE_URL` / `CHECKPOINT_DB_URL`），在 T1-02 落地。

### 二、requirements.txt 重写

按层分组，删掉 `pymysql`，新增以下条目：

```
# 数据库（PostgreSQL 统一栈）
sqlalchemy[asyncio]>=2.0.30
asyncpg>=0.29.0
psycopg[binary]>=3.1.18
alembic>=1.13.0
pgvector>=0.3.0
# 检查点
langgraph>=0.2.60
langgraph-checkpoint-postgres>=2.0.10
# 缓存与队列
redis>=5.0.0
arq>=0.26.0
# 可靠性与观测
tenacity>=8.2.0
structlog>=24.1.0
opentelemetry-api>=1.24.0
opentelemetry-sdk>=1.24.0
opentelemetry-instrumentation-fastapi>=0.45b0
```

`langgraph-checkpoint-sqlite`、`aiosqlite`、`pymysql` 在本项删除。`aiosqlite` 若测试仍需，移入 `requirements-dev.txt`。

### 三、pyproject.toml 工具配置

```toml
[tool.ruff]
line-length = 120
target-version = "py311"

[tool.ruff.lint]
select = ["E", "F", "I", "UP", "B", "ASYNC"]
ignore = ["E501"]

[tool.mypy]
python_version = "3.11"
packages = ["app"]
strict = false
warn_unused_ignores = true
disallow_untyped_defs = true

[tool.pytest.ini_options]
asyncio_mode = "auto"
testpaths = ["tests"]
```

`ASYNC` 规则集用于拦住"在 async 函数里用同步库"这类问题，例如误用 `requests`、误用同步 `Session`。

### 四、环境变量模板

`.env.example` 中数据库一节改为：

```
ENV=development
DATABASE_URL=postgresql+asyncpg://huanong:huanong@localhost:5432/huanong
CHECKPOINT_DB_URL=postgresql://huanong:huanong@localhost:5432/huanong
CHECKPOINT_SCHEMA=checkpoint
GATE_MODE=shadow
```

`DATABASE_URL` 与 `CHECKPOINT_DB_URL` 使用不同 driver 前缀（`+asyncpg` 与裸 `postgresql`），前者给 SQLAlchemy 异步引擎，后者给 psycopg 连接池。这条差异要在 `.env.example` 的注释里写明。

### 五、与验收项的对应

本项不单独对应产品说明书 9.2 的任何一条，但它是验收项 3（生产环境登录降级）与验收项 8（会话回滚）的前置：没有 `pytest-asyncio` 与异步引擎，这两条无法写出可执行的验证用例。

## 验收标准

- `pip install -r backend/requirements.txt` 在 Python 3.11 与 3.12 下均返回 0。
- `python -c "import asyncpg, psycopg, pgvector, arq, structlog, tenacity"` 无 ImportError。
- `python -c "import pymysql"` 与 `python -c "import aiosqlite"` 应失败，证明同步 MySQL 驱动与 SQLite 驱动已从运行依赖中移除。
- `grep -rn "pymysql\|langgraph-checkpoint-sqlite" backend/requirements.txt` 无输出。
- `ruff check backend/app` 与 `ruff format --check backend/app` 返回 0。
- `mypy backend/app`（在 `backend/` 下执行 `mypy app`）返回 0 或仅报存量错误，且错误清单记录在提交说明中。
- `pytest backend/tests/test_env_baseline.py` 全部通过。
- `python -c "from app.core.config import Settings; print(Settings().ENV)"` 输出 `development`。
