# T1-08 环境隔离配置与生产启动自检

## 这一项要做什么

新增 `ENV` 配置项（`development` / `staging` / `production`），并建立一套启动自检：生产环境下凡是不安全配置（微信密钥缺失、使用 mock LLM、闸门仍处于影子模式、Redis 未配置）一律让进程以非 0 退出，而不是带着不安全配置对外服务。这比运行时报错更安全，也是产品说明书 9.2 第 3 条"通过环境隔离消除"的落地方式。自检同时把技术方案 14.2 的 `GATE_MODE` 约束固化：生产环境不允许 `shadow`，否则闸门这个唯一有否决权的组件形同虚设。

## 前置依赖

- 依赖 T1-01 已提供：`requirements.txt` 与 `.env.example` 基线，`ENV` 键已写入模板。
- 依赖 T1-07 已提供：`ENV` 在登录链路已被使用，`REDIS_REQUIRED` 语义已被 `TokenRevoker` 依赖。
- 外部环境：staging 与 production 各有一套环境变量管理（技术方案 15.3：环境差异进环境变量）。
- 需要人工确认：生产环境 Redis 是否强制。技术方案 2.1 把 Redis 列为"核心依赖（额度、幂等、任务队列）"，本项据此把生产环境 Redis 设为必需；若用外部托管 Redis，需在 `.env` 写明。

## 实现要点

### 一、Settings 的扩展

```python
from typing import Literal

class Settings(BaseSettings):
    # 环境
    ENV: Literal["development", "staging", "production"] = "development"
    DEBUG: bool = False                     # 现状默认为 True，本项必须改默认为 False
    # 数据库
    DATABASE_URL: str = ""
    CHECKPOINT_DB_URL: str = ""
    DB_POOL_SIZE: int = 10
    DB_MAX_OVERFLOW: int = 20
    # 缓存
    REDIS_URL: str = ""
    REDIS_REQUIRED: bool = False            # production 下由自检强制转为 True
    # 认证
    JWT_SECRET: str = ""
    JWT_ALGORITHM: str = "HS256"
    TOKEN_EXPIRE_SECONDS: int = 7 * 24 * 3600
    # 闸门与模型
    GATE_MODE: Literal["shadow", "enforce"] = "shadow"
    USE_MOCK_LLM: bool = True
    # 微信
    WECHAT_APP_ID: str = ""
    WECHAT_APP_SECRET: str = ""
```

三处与现状不同的关键改动。其一，`DEBUG` 默认值从 `True` 改为 `False`：现状 `config.py:13` 是 `DEBUG: bool = True`，而 `main.py` 用 `DEBUG` 控制 `/docs`、`/redoc`、`/openapi.json` 是否暴露，默认 True 意味着"忘记配置的生产环境会暴露接口文档"，属典型失败方向错误，改默认 False 是 fail-closed。其二，`ENV` 用 `Literal` 而非 `str`：全局约定第四节要求"枚举封闭，不接受自由字符串"，`pydantic-settings` 会在启动时拒绝 `ENV=prod` 这类拼写，避免"以为设置了生产环境其实没生效"。其三，全部阈值型配置都要显式命名（技术方案 15.3），`MAX_COLLECT_ROUNDS`、`GATE_MODE` 已在此列。

### 二、启动自检清单

`app/core/startup_check.py`：

```python
"""生产启动自检：不安全配置一律拒绝启动。
为什么在启动时拒绝而不是运行时降级：带不安全配置对外服务的窗口期，
可能已经产生了越权数据或不合规输出，事后无法回滚。"""
from dataclasses import dataclass
from app.core.config import Settings, get_settings


@dataclass(frozen=True)
class Check:
    name: str
    detail: str

def collect_violations(settings: Settings) -> list[Check]:
    """返回全部违规项，而非在第一条就中断——便于一次修完所有配置。"""
    violations: list[Check] = []
    if settings.ENV != "production":
        if not settings.DATABASE_URL:
            violations.append(Check("database", "DATABASE_URL 未配置"))
        return violations
    # ---- 以下仅生产环境 ----
    if not settings.WECHAT_APP_ID or not settings.WECHAT_APP_SECRET:
        violations.append(Check("wechat", "生产环境缺少微信密钥，登录必须真实校验（9.2 第 3 条）"))
    if settings.USE_MOCK_LLM:
        violations.append(Check("llm", "生产环境不允许 USE_MOCK_LLM=true"))
    if settings.GATE_MODE == "shadow":
        violations.append(Check("gate", "生产环境 GATE_MODE 不允许为 shadow（技术方案 14.2）"))
    if not settings.REDIS_URL:
        violations.append(Check("redis", "生产环境 Redis 为核心依赖，REDIS_URL 必填"))
    if not settings.JWT_SECRET or len(settings.JWT_SECRET) < 32:
        violations.append(Check("jwt", "JWT_SECRET 缺失或短于 32 字符"))
    if settings.DEBUG:
        violations.append(Check("debug", "生产环境 DEBUG 必须为 false，否则接口文档对外暴露"))
    if not settings.DATABASE_URL.startswith("postgresql+asyncpg://"):
        violations.append(Check("db_driver", "生产环境 DATABASE_URL 必须使用 asyncpg 驱动"))
    return violations


async def run_startup_checks() -> None:
    """服务启动时调用；有违规项则抛异常终止进程。"""
    settings = get_settings()
    violations = collect_violations(settings)
    if violations:
        lines = "\n".join(f"  - [{c.name}] {c.detail}" for c in violations)
        raise RuntimeError(f"启动自检未通过（ENV={settings.ENV}）：\n{lines}")
    await _check_runtime_dependencies(settings)


async def _check_runtime_dependencies(settings: Settings) -> None:
    """连通性检查：数据库与 Redis 必须可连，失败即终止。"""
    from sqlalchemy import text
    from app.db.session import engine

    async with engine.connect() as conn:
        await conn.execute(text("SELECT 1"))
    if settings.REDIS_URL:
        from app.db.redis_client import get_redis

        client = get_redis()
        if client is None:
            raise RuntimeError("REDIS_URL 已配置但连接失败，拒绝启动")
        await client.ping()
```

三条设计决策要说明。**一次报全部违规，不 fail-fast 在第一条。** 生产环境配置错误往往成批出现（新建环境时），逐条修会反复重启；`collect_violations` 返回列表、`run_startup_checks` 一次性打印，管理员一轮即可修完。**`GATE_MODE=shadow` 在生产被拒，与技术方案 14.2 一致。** 14.2 明确"生产环境启动检查中增加一条：`GATE_MODE` 不允许为 `shadow`"；这与"灰度期先跑影子模式"并不矛盾——灰度期用 `ENV=staging`，此时 `GATE_MODE=shadow` 合法，全量切生产时把 `GATE_MODE` 改为 `enforce` 并配 `ENV=production`，该区分要在 `.env.example` 注释写清，否则部署者会在切生产时卡住。**连通性检查在配置检查之后。** 配置错误是"人能改的"，连通性错误是"环境待恢复的"，两类分开报便于定位。

### 三、main.py 的接入位置

```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    await run_startup_checks()     # 必须在最前，早于任何外部依赖初始化
    await get_agent()
    yield
    await close_checkpointer()
    await engine.dispose()
```

自检必须排在 `get_agent()` 之前。现状 lifespan 第一行是 `await get_agent()`，它会在预热时触发检查点连接；如果配置不安全，不应先建连接再退出。`FastAPI(...)` 的 `docs_url` 等已由 `DEBUG` 控制，`DEBUG` 默认改 False 后生产自动关闭文档，与自检的 `debug` 检查互为双保险。

### 四、preflight.py 与 secret 边界

```python
# scripts/preflight.py
import asyncio
import sys
from app.core.startup_check import run_startup_checks


def main() -> int:
    try:
        asyncio.run(run_startup_checks())
    except RuntimeError as e:
        print(str(e), file=sys.stderr)
        return 1
    print("preflight 通过")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

`python scripts/preflight.py` 返回 0 或 1，可直接进 CI；它比"起服务看日志"更省资源，也避免"自检失败但服务已占用端口"。`JWT_SECRET` 与 `WECHAT_APP_SECRET` 只允许从环境变量读，不写进 `.env` 提交物；本项把 `.env.example` 的注释扩展为完整"必须走密钥管理"清单：`JWT_SECRET`、`WECHAT_APP_SECRET`、`FARM_API_KEY`、`WEATHER_API_KEY`、`GEOCODING_API_KEY`，并在 CI 增加 `git ls-files | grep -E "^backend/\.env$" && exit 1 || exit 0`。

### 五、与验收项的对应

- 直接对应产品说明书 9.2 第 3 条（生产降级为模拟登录）：`wechat` 检查让"生产环境缺密钥"在进程启动阶段就无法通过，登录链路根本不会被调用。
- 对应技术方案 14.2（闸门影子模式在生产被拒）：`gate` 检查项；对应 13.5"环境隔离的实现"。
- 为产品说明书 6.3 兜底五（推送失败不影响已有功能）提供反面保障：生产环境 Redis 必需，避免"额度扣减静默失效"。

## 验收标准

- 以 `ENV=production` 且任一不安全项为真启动服务，进程在 3 秒内以非 0 退出，日志列出全部违规项（同时缺微信密钥与 `USE_MOCK_LLM=true` 时，日志同时出现 `[wechat]` 与 `[llm]` 两行）。
- 以 `ENV=production` 且全部配置合规启动，`curl -s -o /dev/null -w "%{http_code}" http://localhost:8000/docs` 返回 404（证明 `DEBUG=false` 生效）。
- 以 `ENV=development` 且 `USE_MOCK_LLM=true`、微信密钥为空启动，服务正常可用，`/docs` 返回 200。
- `python scripts/preflight.py` 在合规环境返回 0，在缺 `JWT_SECRET` 的环境返回 1 且 stderr 含 `[jwt]`。
- `pytest backend/tests/test_startup_check.py` 全部通过，覆盖 production+缺密钥、production+shadow、production+DEBUG=true、production+非 asyncpg URL、staging+shadow 合法、development+缺密钥合法，合计不少于 6 条断言。
- `for k in JWT_SECRET JWT_ALGORITHM REDIS_REQUIRED GATE_MODE ENV DB_POOL_SIZE; do grep -q "^$k=" backend/.env.example || echo "missing $k"; done` 无输出。
- `git ls-files | Select-String -Pattern "^backend/\.env$"` 无匹配；`ruff check backend/app`、`mypy backend/app` 通过。
