# T1-12 分层依赖检查脚本与 CI 门禁

## 这一项要做什么

建立 `scripts/check_layers.py`，用静态扫描强制四条硬性依赖规则：闸门不得依赖智能体与服务层、智能体不得直接导入 ORM、模型网关不得导入任何业务模块、任何模块不得直接使用 `db.query(Model)`。它不是风格检查，而是让安全闸门在物理上无法被绕过的执行手段，接入 CI 后违反即构建失败。

对应技术方案 15.2 的四条硬规则与产品说明书 9.1 分层约束，也是 T1-06 整改结果的长期守卫：没有这道门禁，整改会在两次迭代内回到原样。

## 前置依赖

- 依赖 T1-05 已提供：`OwnedRepository` 作为 L4 规则的唯一合法入口（白名单目录 `app/repositories/`）。
- 依赖 T1-06 已提供：42 处 `db.query` 已整改，脚本首次运行应为零违规。
- 依赖 T1-01 已提供：`ruff`、`mypy` 可运行，脚本与它们并列进 CI。
- 外部环境：CI 运行器需有 Python 3.11 与 Git 检出。
- 需要人工确认：白名单条目。脚本支持显式白名单并写明理由，不允许 `# noqa` 跳过。

## 实现要点

### 一、check_layers.py 完整骨架

```python
"""分层依赖检查：四条硬规则，违反即构建失败。无行内豁免，例外必须在 allowlist 登记。"""
from __future__ import annotations
import ast, sys, tomllib
from dataclasses import dataclass
from pathlib import Path

ROOT = Path(__file__).resolve().parents[1]          # backend/
ALLOWLIST_FILE = ROOT / "scripts" / "check_layers_allowlist.toml"

@dataclass(frozen=True)
class LayerRule:
    name: str
    module_prefix: str                          # 被检查的模块（如 app.gate）
    forbidden_prefixes: tuple[str, ...]
    reason: str                                 # 违规理由，给执行者看

@dataclass(frozen=True)
class AllowEntry:
    rule: str
    path: str                                   # 相对 backend/ 的路径前缀
    reason: str

LAYER_RULES = (
    LayerRule("L1", "app.gate", ("app.agent", "app.services"),
              "闸门必须独立可测、可单独部署，是生成与校验物理隔离的落地"),
    LayerRule("L2", "app.agent", ("app.models",),
              "智能体需能被单测喂假数据，耦合 ORM 就无法脱离数据库测试"),
    LayerRule("L3", "app.llm", ("app.agent", "app.gate", "app.services", "app.broadcast"),
              "网关是通用组件，反向依赖会让它无法复用"),
)
DB_QUERY_ALLOWED_FILES = {"app/repositories/", "app/db/"}   # L4 唯一合法入口

def walk_py_files(prefix: str) -> list[Path]:
    base = ROOT / prefix.replace(".", "/")
    return sorted(p for p in base.rglob("*.py") if p.is_file()) if base.exists() else []

def parse_imports(path: Path) -> list[str]:
    """用 AST 解析 import：正则误判字符串里的 import，也漏掉 from X import Y。"""
    tree = ast.parse(path.read_text(encoding="utf-8"), filename=str(path))
    out: list[str] = []
    for node in ast.walk(tree):
        if isinstance(node, ast.Import):
            out.extend(a.name for a in node.names)
        elif isinstance(node, ast.ImportFrom) and node.module and node.level == 0:
            out.append(node.module)
    return out

def load_allowlist() -> list[AllowEntry]:
    if not ALLOWLIST_FILE.exists():
        return []
    data = tomllib.loads(ALLOWLIST_FILE.read_text(encoding="utf-8"))
    return [AllowEntry(e["rule"], e["path"], e["reason"]) for e in data.get("allow", [])]

def is_allowed(allow: list[AllowEntry], rule: str, rel: str) -> bool:
    return any(e.rule == rule and rel.startswith(e.path) for e in allow)

def check_import_direction(allow: list[AllowEntry]) -> list[str]:
    """L1 / L2 / L3：import 方向禁令。"""
    bad: list[str] = []
    for rule in LAYER_RULES:
        for path in walk_py_files(rule.module_prefix):
            rel = str(path.relative_to(ROOT)).replace("\\", "/")
            if is_allowed(allow, rule.name, rel):
                continue
            for imp in parse_imports(path):
                if any(imp == f or imp.startswith(f + ".") for f in rule.forbidden_prefixes):
                    bad.append(f"[{rule.name}] {rel}: 非法依赖 {imp} —— {rule.reason}")
    return bad

def check_db_query(allow: list[AllowEntry]) -> list[str]:
    """L4：只认 ast.Call + ast.Attribute，不认注释与字符串。"""
    bad: list[str] = []
    for path in walk_py_files("app"):
        rel = str(path.relative_to(ROOT)).replace("\\", "/")
        if any(rel.startswith(p) for p in DB_QUERY_ALLOWED_FILES) or is_allowed(allow, "L4", rel):
            continue
        for node in ast.walk(ast.parse(path.read_text(encoding="utf-8"), filename=str(path))):
            if (isinstance(node, ast.Call) and isinstance(node.func, ast.Attribute)
                    and node.func.attr == "query" and isinstance(node.func.value, ast.Name)):
                bad.append(f"[L4] {rel}:{node.lineno}: 禁止直接 {node.func.value.id}.query()，请走 app/repositories/")
    return bad

def check_allowlist_hygiene(allow: list[AllowEntry]) -> list[str]:
    """白名单必须写明失效任务编号（如 T2-25），否则例外会永久存在。"""
    return [f"[allowlist] {e.path} 的理由必须写明失效任务编号" for e in allow if e.reason.count("T") != 1]

def check() -> list[str]:
    allow = load_allowlist()
    return check_import_direction(allow) + check_db_query(allow) + check_allowlist_hygiene(allow)

def main() -> int:
    violations = check()
    if not violations:
        print("分层依赖检查通过")
        return 0
    print(f"分层依赖检查未通过，共 {len(violations)} 项：", file=sys.stderr)
    for line in violations:
        print(f"  {line}", file=sys.stderr)
    print("不得使用 # noqa 跳过，确有例外请在 check_layers_allowlist.toml 登记并写明理由。", file=sys.stderr)
    return 1

if __name__ == "__main__":
    raise SystemExit(main())
```

### 二、为什么用 AST 而不是正则

技术方案 15.2 给的骨架是 `if "db.query(" in read(path)` 的子串匹配，它有两个假阳性（注释与文档字符串里的示例被判违规，逼执行者删注释）与一个假阴性（`getattr(db, "query")(Model)` 漏掉）。AST 的意义不在防绕过（静态分析永远能绕过），而在于"只报真实的代码表达式"，使门禁结果可被信任。`check_db_query` 用 `isinstance(node.func.value, ast.Name)` 限定"直接名为 `db` 的对象"，会漏掉 `self.db.query(...)`，这是刻意的：本项目规范里 `AsyncSession` 参数名固定为 `db`，该约定写进 00-全局约定第四节。`walk_py_files` 对不存在的目录返回空列表，第一步尚无 `app/gate/`、`app/llm/`，脚本不报错，因此 `main()` 建议打印每条规则的扫描文件数（`L1 app.gate: 0 个文件`），让"目录不存在"与"目录存在且合规"可区分。

### 三、白名单与 CI 接入

`check_layers_allowlist.toml` 每条登记都写明失效任务编号，例如 `path = "app/agent/nodes/"`、`reason = "T2-25 重排主图后删除本条"`——无失效条件的白名单会永久存在，`check_allowlist_hygiene` 就是防这一点。

```yaml
# .github/workflows/ci.yml：check-layers 放在 mypy 之后（分层违规常同时导致类型错误，先报基础门禁）
name: ci
on: [push, pull_request]
jobs:
  checks:
    runs-on: ubuntu-latest
    services:
      postgres:
        image: timescale/timescaledb-ha:pg16      # 迁移依赖 vector 与 timescaledb 扩展
        env: { POSTGRES_PASSWORD: huanong }
        ports: ["5432:5432"]
        options: >-  # 健康检查，避免迁移步骤在库未就绪时启动
          --health-cmd "pg_isready -U postgres" --health-interval 5s
          --health-timeout 5s --health-retries 10
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.11" }
      - run: pip install -r backend/requirements.txt -r backend/requirements-dev.txt
      - run: ruff check backend/app && ruff format --check backend/app
      - run: cd backend && mypy app
      - run: python backend/scripts/check_layers.py
      - run: cd backend && alembic upgrade head && alembic downgrade -1 && alembic upgrade head
      - run: cd backend && pytest -q
```

`migrations` 步骤的 `upgrade head → downgrade -1 → upgrade head` 落实技术方案 12.8 第三条；`scripts/ci.sh` 用同一命令序列（`ruff` → `mypy` → `check_layers.py`），避免"本地过 CI 挂"。`tests/test_check_layers.py` 用临时目录构造样例，`monkeypatch.setattr(check_layers, "ROOT", tmp_path)` 后断言，含四类正例（`app/gate/x.py` 写 `from app.services import s`、`app/agent/x.py` 写 `from app.models import User`、`app/llm/x.py` 写 `from app.gate import engine`、`app/services/x.py` 写 `db.query(User)`）与四类反例（注释、字符串、白名单目录、不在禁令内的 `app.process_config`）。

### 四、与验收项的对应

- 直接对应技术方案 15.2 的四条硬规则，为产品说明书 9.1 分层与依赖约束提供自动化执行。
- 为产品说明书 9.2 第 1 条（归属）提供长期守卫：L4 让 `db.query` 在整改后无法回潮。
- 为技术方案 8.1"闸门必须独立可测"提供物理保证：L1 让闸门真的无法引用智能体与服务层。
- 落实全局约定第三节"不允许 `# noqa` 跳过"：脚本不解析 `# noqa`，只认白名单文件。

## 验收标准

- `python backend/scripts/check_layers.py` 在已整改的代码库上返回 0，并打印 `分层依赖检查通过`。
- 脚本打印每条规则的扫描文件数，`L1`、`L2`、`L3` 三行都可读（目录不存在时显示 0）。
- 在 `backend/app/services/` 任一文件临时加入 `db.query(User)` 后运行脚本，返回 1，错误信息含 `[L4]`、文件名、行号与"请走 app/repositories/"。
- 加入注释 `# db.query(User)` 后运行脚本返回 0（AST 不误判）；在 `backend/app/agent/` 加入 `from app.models import User` 后返回 1 且错误信息含 `[L2]` 与原文理由。
- `pytest backend/tests/test_check_layers.py` 全部通过，含 4 条正例与 4 条反例，合计不少于 8 条断言。
- 白名单中每条 `[[allow]]` 的 `reason` 都含一个 `T` 开头任务编号；构造一条不含编号的条目时脚本额外报 allowlist 卫生错误；条目数不超过 5。
- CI 流水线 `checks` 作业在五个步骤（ruff / mypy / check-layers / migrations / tests）全部返回 0 后才标记成功。
- 在 CI 上人为制造一次 L4 违规并推送，流水线在 `check-layers` 步骤失败，且 `tests` 步骤不执行。
