# T1-07 令牌吊销与登出失效修复

## 这一项要做什么

现有 `app/core/security.py` 已定义 `revoke_token(token)`，但通篇没有任何调用点，`app/api/v1/auth.py` 也没有登出路由。结果是农户点"退出登录"后，旧 token 仍然有效，直到 7 天有效期自然过期。本项把吊销名单接入校验链路，补 `POST /api/logout`，并把 token 从"无结构随机串"改为带 `jti` 与过期时间的签名令牌。

对应产品说明书 9.2 第 2 条（令牌吊销逻辑已定义但从未被调用，登出无效）与第 3 条（生产环境密钥缺失时降级为模拟登录）。

## 前置依赖

- 依赖 T1-05 已提供：仓储模式与异常体系（吊销名单若落库需要归属无关的仓储）。
- 依赖 T1-01 已提供：`redis>=5.0.0`，以及 T1-02 已把 Redis 提升为核心依赖（技术方案 2.1 明确"提升为核心依赖"）。
- 外部环境：Redis 7+ 可用且 `REDIS_URL` 已配置。**本项要求 Redis 不可用时生产环境拒绝启动**（见 T1-08 的启动自检），开发环境可退化为进程内集合。
- 需要人工确认：是否引入 `pyjwt` 或 `itsdangerous` 做签名。现状 `create_token` 用 `uuid4().hex` 明文存 Redis，无签名。本项按"引入签名"实现，包依赖在 T1-01 已加（若 T1-01 未加需补 `pyjwt>=2.8.0`）。

## 实现要点

### 一、为什么现有实现等于"没有登出"

现状三处事实叠加导致登出必然无效：

第一，`app/core/security.py` 的 `revoke_token` 没有调用方：`grep -rn "revoke_token" backend/app` 只命中定义行。

第二，`app/api/v1/auth.py` 只有 `POST /login`，没有登出路由——前端只能删本地存储，服务端会话仍然存在。

第三，`app/api/deps.py` 的 `get_current_user` 只调 `get_user_id(token)`，它在 Redis 里读 `token:<token>` 键。只要键还在，token 就有效。而 `revoke_token` 的存在恰恰说明"有人以为调用了"——它是 9.2 第 2 条描述的"已定义但从未被调用"的典型。

### 二、令牌结构：从随机串到签名令牌

现有令牌是 32 位 hex 随机串，其去重与过期全依赖 Redis 键。缺点有三：Redis 丢失即全员掉线；无法表达"某时刻前签发的令牌全部作废"；无法携带 `jti` 之外的元信息。改为 JWT 后：

```python
# app/core/security.py
from datetime import UTC, datetime, timedelta
from uuid import uuid4

import jwt

from app.core.config import get_settings


def create_token(user_id: str, *, jti: str | None = None) -> str:
    """签发访问令牌：含 jti 与 exp，用于精确吊销与过期判定。"""
    settings = get_settings()
    now = datetime.now(UTC)
    payload = {
        "sub": user_id,
        "jti": jti or uuid4().hex,
        "iat": int(now.timestamp()),
        "exp": int((now + timedelta(seconds=settings.TOKEN_EXPIRE_SECONDS)).timestamp()),
    }
    return jwt.encode(payload, settings.JWT_SECRET, algorithm=settings.JWT_ALGORITHM)


def decode_token(token: str) -> dict:
    """解码并验签。过期抛 ExpiredSignatureError，篡改抛 InvalidTokenError。"""
    settings = get_settings()
    return jwt.decode(token, settings.JWT_SECRET, algorithms=[settings.JWT_ALGORITHM])


def remaining_ttl(token: str) -> int:
    """剩余有效期（秒），用于吊销名单的 TTL——名单只需保留到令牌自然过期。"""
    payload = decode_token(token)
    return max(0, payload["exp"] - int(datetime.now(UTC).timestamp()))
```

`remaining_ttl` 是吊销名单的内存控制关键：如果不设 TTL，吊销名单会无限增长。设成"令牌剩余存活时间"后，令牌过期时名单条目自动消失，名单大小与"当前活跃的已吊销令牌数"成正比。

### 三、吊销名单

```python
# app/core/token_revoker.py
"""令牌吊销名单。

Redis 为生产实现；无 Redis 时退化为进程内集合，仅用于开发与单进程测试。
生产环境无 Redis 由 T1-08 的启动自检拦截，不在本模块做降级判断。
"""
import time

from app.core.config import get_settings
from app.db.redis_client import get_redis

_KEY = "revoked:jti"
_memory: dict[str, float] = {}   # jti -> 过期时间戳


class TokenRevoker:
    async def revoke(self, jti: str, ttl: int) -> None:
        r = get_redis()
        if r is not None:
            await r.setex(f"{_KEY}:{jti}", max(ttl, 1), "1")
            return
        _memory[jti] = time.time() + max(ttl, 1)

    async def is_revoked(self, jti: str) -> bool:
        r = get_redis()
        if r is not None:
            return await r.exists(f"{_KEY}:{jti}") == 1
        expire_at = _memory.get(jti)
        if expire_at is None:
            return False
        if time.time() > expire_at:
            _memory.pop(jti, None)
            return False
        return True


token_revoker = TokenRevoker()
```

现状 `app/db/redis_client.py` 的 `get_redis()` 是同步的且返回同步 `redis.Redis`。技术方案要求全异步，因此本项需要把它改为 `redis.asyncio`：

```python
import redis.asyncio as aioredis

_async_client: aioredis.Redis | None = None


def get_redis() -> aioredis.Redis | None:
    ...
```

这个改动会影响 T1-13（发件箱投递）与 T3 阶段的额度与幂等，属于共用底座，必须在本项完成。这是本项范围超出标题的一处扩展，理由是无法只用同步客户端实现"吊销检查在 `verify` 里 await"。

### 四、AuthService 的完整改造

```python
class AuthService:
    async def login(self, db: AsyncSession, code: str, user_info=None) -> dict:
        settings = get_settings()
        # 生产环境密钥缺失必须直接失败，不得降级为模拟登录（9.2 第 3 条）
        if not settings.WECHAT_APP_ID or not settings.WECHAT_APP_SECRET:
            if settings.ENV == "production":
                raise ConfigError("生产环境缺少微信密钥，拒绝启动登录流程")
            session_data = await self._mock_login(code)      # 仅非生产环境
        else:
            session_data = await self._code2session(code)     # 真实 code2session

        openid = session_data["openid"]
        user = await self.user_repo.get_by_openid(db, openid)
        is_new_user = user is None
        if user is None:
            user = User(id=new_id("user"), openid=openid)
            db.add(user)
            await db.flush()
        await self._apply_user_info(db, user, user_info)

        token = create_token(user.id)
        await db.commit()
        return {"token": token, "userId": user.id, "isNewUser": is_new_user}

    async def logout(self, db: AsyncSession, user_id: str, token: str) -> None:
        """登出：令牌真正失效，写入吊销名单（9.2 第 2 条）。"""
        payload = decode_token(token)
        await token_revoker.revoke(payload["jti"], ttl=remaining_ttl(token))

    async def verify(self, db: AsyncSession, token: str) -> User:
        """校验链路必须包含吊销检查。"""
        try:
            payload = decode_token(token)
        except ExpiredSignatureError as e:
            raise Unauthorized("登录已过期，请重新登录") from e
        except InvalidTokenError as e:
            raise Unauthorized("登录凭证无效") from e

        if await token_revoker.is_revoked(payload["jti"]):
            raise TokenRevokedError()

        user = await self.user_repo.get(db, payload["sub"])
        if user is None:
            raise Unauthorized("用户不存在")
        return user
```

`_mock_login` 的既有实现要保留兼容：现状 `app/integrations/wechat.py` 的 `code2session` 在 `WECHAT_APP_SECRET` 为空时**内部**返回 mock。这个"隐式降级"正是 9.2 第 3 条的病灶——判断逻辑藏在集成层，`AuthService` 无从知晓自己拿到的是真实还是模拟结果。修复方式是让 `wechat.code2session` 不再自行降级、改为抛 `ConfigError`，降级判断上移到 `AuthService.login` 并受 `ENV` 约束。这是对技术方案的一处具体化，13.5 的骨架给出了 `_mock_login` 方法但未说明 `code2session` 侧要如何处理。

### 五、`verify` 里为什么还要查库

`decode_token` 已经验签，理论上可以只依赖 `sub`。仍要 `user_repo.get` 的原因是：用户注销账号后（`cancel_account`），其 token 在自然过期前仍然有效。查库把"用户已删除"这一状态纳入校验，避免注销用户继续访问。产品说明书 4.6 未明确注销后令牌的处理，这是对技术方案的一处推断。

### 六、deps.py 与路由

```python
# app/api/deps.py
async def get_current_user(
    cred: HTTPAuthorizationCredentials | None = Depends(_bearer),
    db: AsyncSession = Depends(get_db),
) -> str:
    if cred is None or not cred.credentials:
        raise Unauthorized()
    user = await get_auth_service().verify(db, cred.credentials)
    return user.id
```

```python
# app/api/v1/auth.py
@router.post("/logout")
async def logout(
    cred: HTTPAuthorizationCredentials = Depends(_bearer_required),
    db: AsyncSession = Depends(get_db),
    user_id: str = Depends(get_current_user),
):
    await get_auth_service().logout(db, user_id, cred.credentials)
    return ok()
```

登出必须带 `user_id` 依赖，这样"未登录调登出"返回 401 而不是静默成功。

## 验收标准

- `pytest backend/tests/test_token_revocation.py` 全部通过，含以下断点：
  - 登录拿到 token 后调 `/api/farmer/profile` 返回 200；
  - 用同一 token 调 `/api/logout` 返回 200；
  - 再用同一 token 调 `/api/farmer/profile` 返回 401，且响应体 `code=401`；
  - 同一用户重新登录得到的新 token 可正常访问（证明吊销是按 `jti` 而非按 `user_id`）；
  - 连续生成 1000 个 token，`jti` 去重后仍为 1000 个。
- `pytest backend/tests/test_login_env_isolation.py` 通过：设置 `ENV=production`、`WECHAT_APP_SECRET=""` 后调登录接口返回 HTTP 500 与 `code=500`，且 `SELECT count(*) FROM "user"` 的前后值相等（未创建任何用户）。
- `ENV=development` 且密钥为空时登录成功并返回 token（开发可用性未被破坏）。
- Redis 中登出后 `EXISTS revoked:jti:<jti>` 返回 1，且 `TTL revoked:jti:<jti>` 小于等于 `TOKEN_EXPIRE_SECONDS`。
- 篡改 token 的最后一个字符后调接口返回 401（验签生效），而非 500。
- `grep -rn "revoke_token" backend/app` 中不再有"只定义不调用"的符号；`revoke` 至少有一个生产调用点（`AuthService.logout`）。
- `GET /openapi.json` 中包含 `/api/logout` 路径。
- `ruff check backend/app`、`mypy backend/app` 通过。
