# 全局约定与执行规范

> 所有任务文件共用这一份约定。动手前先读这一份，再读具体任务文件。
>
> 上游依据：《话农点金_多智能体协同技术实现方案》（`docs/话农点金_多智能体协同技术实现方案.md`）

---

## 一、任务文件的统一格式

每个任务文件按固定六段组织。缺任何一段都算任务文件不合格。

```markdown
# 任务编号 任务名

## 这一项要做什么
两到四句，说清目标与做它的理由。不重复标题。

## 前置依赖
- 依赖的任务编号与它必须已提供的东西
- 外部环境要求（数据库、扩展、密钥、模型服务）

## 参考章节
- 技术方案 第X章 X.Y 小节名（这一项对应方案里的哪一段）

## 改动范围
| 类型 | 文件路径 | 说明 |
| --- | --- | --- |
| 新增/修改/删除 | `app/...` | 一句话 |

## 实现要点
分小节写。关键结构给出代码骨架，说明为什么这样写。

## 验收标准
- 可跑出来或被观察到的结果，逐条列出
```

**"验收标准"的写法要求**：写可以被执行或观察的结果，不写"代码完成"这类无法核对的状态。例：

- 写「`alembic upgrade head` 与 `alembic downgrade -1` 均返回 0」而不是「迁移脚本写好」
- 写「`pytest tests/gate/rules/test_registered_crop.py` 全部通过，含 3 个正例与 3 个反例」而不是「规则实现完成」

## 三、四条硬性依赖规则

分层不是为了架构好看，而是为了让安全闸门在物理上无法被绕过。以下四条由 `scripts/check_layers.py` 检查，违反即构建失败。

| 编号 | 规则 | 理由 |
| --- | --- | --- |
| L1 | `app/gate/` 不得导入 `app/agent/` 或 `app/services/` | 闸门必须独立可测、可单独部署，这是生成与校验物理隔离的落地方式 |
| L2 | `app/agent/` 不得直接导入 `app/models/`（ORM） | 智能体要能被单测（喂假数据），耦合 ORM 就无法脱离数据库测试 |
| L3 | `app/llm/` 不得导入任何业务模块（`agent`/`gate`/`services`/`broadcast`） | 网关是通用组件，反向依赖会让它无法复用 |
| L4 | 任何模块不得直接使用 `db.query(Model)` | 必须走 `app/repositories/`，这是归属校验的工程保障 |

**不允许 `# noqa` 跳过**。确有例外需在脚本的白名单里显式登记并写明理由。

## 四、契约与编码约束

以下约束来自技术方案第五章 5.2，所有涉及契约的任务都要遵守。

**枚举封闭。** `process_id`、`confidence_level`、`severity`、`decision` 等必须是 Python `Enum`，不接受自由字符串。大模型输出的自由文本必须经解析落到枚举上，解析失败即视为契约违约并触发降级。

**事实必带溯源。** 任何数值型字段必须配套 provenance 字段，结构为 `{"字段路径": "来源标识"}`。没有 provenance 的数字不允许进入处方与提示。这条由闸门的 `R-PROVENANCE` 规则反向扫描校验。

**区分未知与缺失。** `unknown`（用户明确答不出）与 `missing`（尚未询问）是两个不同状态。`unknown` 是合法答案，系统据此降低确定性表述，不反复逼问。

**Python 版本与风格。**
- Python 3.11+，使用 `str | None` 而非 `Optional[str]`
- 全异步：数据库、HTTP、Redis 均用 async 驱动
- 类型标注完整，`mypy` 在 CI 中检查 `app/` 目录
- 格式化用 `ruff format`，lint 用 `ruff check`

**数据库约定。**
- 主键统一 `String(36)`（UUID），不用自增整数做主键（时序表除外，用 `BIGSERIAL` 配合时间分区）
- 所有业务表带 `user_id`，索引必建
- 时间统一带时区（`TIMESTAMPTZ` / `DateTime(timezone=True)`）
- 状态字段用字符串枚举值，不用整数编码

## 五、每个任务的完成定义

一项任务算完成，需要同时满足四点。

第一，**代码通过静态检查**。`ruff check`、`ruff format --check`、`mypy app` 三条命令均无错误。

第二，**验收标准逐条可复现**。任务文件里列出的每一条验收标准都能被实际执行并得到预期结果，不是纸面推断。

第三，**新增的对外行为有测试覆盖**。纯函数（路由、规则、优先级排序、解析器）必须有单元测试；图结构与接口必须有集成测试。测试文件路径写在该任务的"改动范围"表里。

第四，**没有留下临时物**。调试用的脚本、注释掉的大段代码、`print` 调试语句在提交前清理干净。

## 六、跨任务的共用约定

**流程配置是唯一事实来源。** 问诊问题、术语、红线、时机判据、回访策略全部从 `process_config` 读取，不写在代码里。新增一条流程的改动量应控制为：一份 YAML + 一个约 15 行的子图文件 + 路由表注册一行。

**模板出事实，模型只改写。** 药剂名、剂量、安全间隔期这类事实性内容由代码从知识库检索并填充，模型只负责把话说顺。处方的 `pesticide_items` 列表模型无权写入。

**失败行为分两类。** 守卫类（报告守卫、安全闸门）fail-closed，不确定时选更保守的一方。其余智能体降级但仍服务。

**凡是能被规则判定的，不交给模型。** 追问候选池筛选、优先级排序、条数截断、地区回退、时段判断都是纯代码逻辑，模型不参与。

**地区回退保留实际命中级。** 按县级查不到退市级，再退省级，最后用全国通用条目。每次回退都要在结果里记下实际命中的级别，供界面标注"当前按 XX 市通用农时提示"。

## 七、环境与工具

| 项 | 要求 |
| --- | --- |
| Python | 3.11 至 3.12 |
| 数据库 | PostgreSQL 16+，扩展 pgvector 0.7+、TimescaleDB |
| 缓存与队列 | Redis 7+，任务队列用 ARQ |
| 包管理 | `requirements.txt` 为准，`pyproject.toml` 存工具配置 |
| 测试 | pytest + pytest-asyncio + respx（HTTP mock） |
| 容器 | Docker + Docker Compose |

**Mock 约定**：`USE_MOCK_LLM=true` 时，模型网关返回预设的结构化响应，不发真实请求。所有不测模型的测试都应在 mock 模式下跑，保证 CI 不依赖外部服务。

## 八、需要人工确认的三处

以下三处无法由执行者独自判断，遇到时停下来问，不要自行选择。

**农技专业内容。** 药剂清单、剂量区间、安全间隔期、决定性特征判据、回访时点取值。这些来自植保口径与法规，执行者只负责按给定数据录入与建表，不负责决定数值是否正确。

**红线与术语的措辞。** 每条流程的禁用输出清单、面向农户的口语化改写对照，需要农技与产品共同确认后才能定稿。

**产品说明书附录 A 中待确认的假设。** 特别是 A9（烟草流程保留或移除）、A12（方言语音识别实现方式）、A7（油菜流程调研排期）。在这三项给出明确答复前，相关任务按占位方式实现，不擅自决定。
