# T3-01 提示快照数据模型与表结构

## 这一项要做什么

建立提示与触达链路的四张基础表：`prompt_snapshot`（一次生成的结果容器）、`prompt_item`（单条提示条目）、`subscription_quota`（每户推送额度）、`reach_record`（每一次触达记录）。字段定义原样采用技术方案 12.5，不做增删改。这四张表是后续 T3-02 至 T3-15 全部代码的落点，字段名一旦偏差，快照生成、条数控制、幂等锁、推送顺序约束、执行率统计都会连锁返工。因此本项先于所有业务代码完成，且只做模型与迁移，不写业务逻辑。

## 前置依赖

- T1-04 真实迁移链路（`alembic upgrade head` / `downgrade -1` 均可用），本项所有表由迁移建立，不依赖启动建表；T1-05 的 `OwnedMixin` 与 `OwnedRepository`，四张表中有 `user_id` 的字段必须带索引。
- 外部环境：PostgreSQL 16+；`prompt_item.snapshot_id → prompt_snapshot.id` 与 `reach_record.prompt_item_id → prompt_item.id` 两条外键需要 PostgreSQL 支持（12.7 列出，优先级均为高）。
- 现有改造起点：`app/models/broadcast.py` 当前只有 `BroadcastLog` 一张表（`String(32)` 主键、`date` 存字符串、`done` 用 `SmallInteger`），本项以新四表取代它作为主链路，旧表在 T3-08 完成后停止写入。

## 实现要点

### 一、PromptSnapshot

```python
class PromptSnapshot(Base, OwnedMixin):
    __tablename__ = "prompt_snapshot"
    id = mapped_column(String(36), primary_key=True)
    user_id = mapped_column(String(36), nullable=False, index=True)
    farm_entry_id = mapped_column(String(36), index=True)
    snapshot_date = mapped_column(Date, nullable=False, index=True)
    generated_at = mapped_column(DateTime(timezone=True), nullable=False)
    env_source = mapped_column(String(20))                # sensor / sensor_stale / weather / none
    revision = mapped_column(Integer, default=1)          # 同日第几次更新
    invalidated = mapped_column(Boolean, default=False)
```

`snapshot_date` 用 `Date` 而非 `DateTime`，因为幂等键的粒度是"自然日 + 农户 + 地块"（11.4），比较必须不涉及时区。`generated_at` 用 `DateTime(timezone=True)`，因为跨日弱化（11.5）与触达时段判断（11.9）都要求精确到小时且不因服务器时区漂移。`revision` 是同日第几次更新的计数器，从 1 开始；同日第二次点击改为合并去重时 `revision` 不变，只有真正重新生成才自增，因此 `revision > 1` 不等于"农户点了多次"，频次提示要用独立的点击数计数，见 T3-08。`invalidated` 是逻辑失效标记，保留记录以满足快照稳定性与复盘需求，不允许物理删除。

唯一约束 `(user_id, farm_entry_id, snapshot_date, revision)` 由迁移显式建立。没有这条约束，并发写入同一日的两条快照会同时存在，幂等检查在提交后才生效就来不及了。`farm_entry_id` 可为空（杂草流程不绑定地块，见 12.2），PostgreSQL 的唯一约束对 NULL 不去重，因此杂草流程用 `farm_entry_id IS NULL` 的部分唯一索引单独建一条。

### 二、PromptItem

```python
class PromptItem(Base, OwnedMixin):
    __tablename__ = "prompt_item"
    id = mapped_column(String(36), primary_key=True)
    user_id = mapped_column(String(36), nullable=False, index=True)
    snapshot_id = mapped_column(String(36), ForeignKey("prompt_snapshot.id"), index=True)
    source_kind = mapped_column(String(20))               # env_risk / calendar / followup
    severity = mapped_column(String(10))                  # urgent / notice / reminder
    callout = mapped_column(String(30))                   # 呼告（对象）
    fact = mapped_column(Text)                            # 事实
    impact = mapped_column(Text)                          # 影响
    action = mapped_column(Text)                          # 行动
    facts_provenance = mapped_column(JSON)
    rule_id = mapped_column(String(40))
    priority_score = mapped_column(Numeric(8, 3))
    suppressed = mapped_column(Boolean, default=False)    # 被截断
    executed = mapped_column(Boolean, default=False)      # 执行勾选（北极星指标）
    executed_at = mapped_column(DateTime(timezone=True))
```

`callout / fact / impact / action` 四段加 `severity` 正好是产品说明书 4.3.3 功能点 2 的五段式（呼告 → 级别 → 事实 → 影响 → 行动），`severity` 在契约里是级别字段，展示时必须前置。`facts_provenance` 沿用与处方一致的 `{"字段路径": "来源标识"}` 结构（全局约定第四节），使闸门的 `R-PROVENANCE` 与 `R-NO-DATA` 可以同一套逻辑扫描；环境类条目的来源标识形如 `env:sensor:<observed_at>`，农事历类条目形如 `knowledge:<id>`。

`source_kind` 三值与 11.2 的三类输入一一对应：`env_risk` 来自环境事实（`source="none"` 时该路条目被拦截）、`calendar` 来自农事历、`followup` 来自问诊与回访信号。这个字段是 T3-02 三级回退拦截、T3-03 两条流程排除、T3-04 回访信号过滤的判据，因此不允许为空。

`priority_score` 用 `Numeric(8, 3)` 而非 `Float`，因为排序键的三个维度要拼接成稳定可复现的分数，浮点误差会让同一批输入产生不同顺序，测试无法断言。`suppressed` 与 `executed` 都是 `Boolean` 而非整数布尔（对照现有 `BroadcastLog.done` 的 `SmallInteger`），因为状态字段用字符串或布尔、不用整数编码是全局约定第四节的硬要求。`suppressed=True` 的条目仍要落库，产品复盘"哪些内容长期被压制"依赖它（11.3）。

### 三、SubscriptionQuota 与 ReachRecord

```python
class SubscriptionQuota(Base, OwnedMixin):
    __tablename__ = "subscription_quota"
    user_id = mapped_column(String(36), primary_key=True)
    granted_total = mapped_column(Integer, default=0)
    consumed_total = mapped_column(Integer, default=0)
    remaining = mapped_column(Integer, default=0)
    last_grant_at = mapped_column(DateTime(timezone=True))
    last_consume_at = mapped_column(DateTime(timezone=True))
    reject_streak = mapped_column(Integer, default=0)     # 连续拒绝次数，用于降级索要


class ReachRecord(Base, OwnedMixin):
    __tablename__ = "reach_record"
    id = mapped_column(String(36), primary_key=True)
    user_id = mapped_column(String(36), nullable=False, index=True)
    prompt_item_id = mapped_column(String(36), ForeignKey("prompt_item.id"), nullable=False)
    channel = mapped_column(String(20))                   # subscribe_once / in_app
    status = mapped_column(String(20))                    # delivered / failed
    fail_reason = mapped_column(String(30))               # no_grant / quota_exhausted / api_error / quiet_hours
    attempted_at = mapped_column(DateTime(timezone=True), nullable=False)
    delivered_at = mapped_column(DateTime(timezone=True))
```

`SubscriptionQuota` 的 `user_id` 直接作主键（一户一行），不需要额外唯一约束。`reject_streak` 是"长期无额度不反复索要"（11.7 第四条）的存储位，T3-11 据此决定授权入口是否降级为弱提示。`remaining` 是冗余字段而非每次用 `granted_total - consumed_total` 现算，因为额度校验在推送上高频发生且必须原子扣减，冗余字段配合行级 `UPDATE ... WHERE remaining > 0` 才能做到无锁安全，一致性由 T3-11 的单条 SQL 保证。

`ReachRecord.prompt_item_id` 是 `nullable=False` 的外键，这是 11.8 顺序约束在数据层的落地：推送服务只能通过 `prompt_item_id` 取内容，不接受"直接传入文案"的调用方式。外键指向 `prompt_item.id` 而非 `prompt_snapshot.id`，因为一次推送对应一条具体提示而非整份快照。`fail_reason` 四类在 T3-14 细化，本项只保证列存在且允许为空（成功时为 `NULL`）。

### 四、枚举与迁移

六个枚举放 `app/models/enums.py` 并继承 `str, Enum`，与 T2-01 的 `ProcessId` 同一风格，字段仍是 `String` 列而非 PostgreSQL ENUM 类型——用数据库原生枚举会让新增取值必须走 `ALTER TYPE`，与"新增流程只改 YAML"的迭代方式冲突。迁移脚本只做三件事：建四张表、建索引与唯一约束、加上两条高优先级外键。外键的 `ondelete` 全部保持默认（`RESTRICT`）：快照与提示条目不允许被级联删除，触达记录是送达率指标的原始数据，删除会污染统计口径。

索引清单：`prompt_snapshot` 建 `(user_id, snapshot_date)` 与 `(user_id, farm_entry_id, snapshot_date)` 两条；`prompt_item` 建 `snapshot_id`、`user_id` 两条，另加一条供执行率统计的部分索引 `WHERE suppressed = false`；`reach_record` 建 `prompt_item_id`、`user_id+attempted_at` 两条；`subscription_quota` 主键即可。部分索引的理由与 T1-13 一致——只含需要的行，索引大小与被统计量成正比而非与历史总量成正比。

## 验收标准

- `alembic upgrade head` 后再执行 `alembic downgrade -1`，两条命令均返回 0；`SELECT column_name, data_type FROM information_schema.columns WHERE table_name='prompt_item'` 输出含 `source_kind`、`severity`、`callout`、`fact`、`impact`、`action`、`facts_provenance`、`rule_id`、`priority_score`、`suppressed`、`executed`、`executed_at` 共十二列，与 12.5 定义逐字一致。
- `SELECT column_name FROM information_schema.columns WHERE table_name='prompt_snapshot'` 含 `env_source`、`revision`、`invalidated`；`SELECT column_name FROM information_schema.columns WHERE table_name='reach_record'` 含 `fail_reason`、`channel`、`status`、`attempted_at`、`delivered_at`。
- `SELECT conname, pg_get_constraintdef(oid) FROM pg_constraint WHERE contype='f' AND conrelid='prompt_item'::regclass` 返回指向 `prompt_snapshot(id)` 的外键；对 `reach_record` 执行同样的查询返回指向 `prompt_item(id)` 的外键，且 `confdeltype` 不为 `c`（非级联删除）。
- 插入一条 `reach_record` 时把 `prompt_item_id` 设为不存在的 UUID，断言抛 `ForeignKeyViolation`；插入第二条 `(user_id, farm_entry_id, snapshot_date, revision)` 完全相同的 `prompt_snapshot`，断言违反唯一约束。
- 按日期插入跨越夏令时边界的 `generated_at`，断言存回后 `.tzinfo` 非空且 UTC 偏移可还原；插入 `source_kind="unknown_kind"` 时断言 ORM 层抛 `ValueError`（枚举解析失败）。
- `pytest tests/models/test_snapshot_tables.py` 全部通过，断言不少于 8 条；`ruff check backend/app`、`ruff format --check backend/app`、`mypy backend/app` 均返回 0。
