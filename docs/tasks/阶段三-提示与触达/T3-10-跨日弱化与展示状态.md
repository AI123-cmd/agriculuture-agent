# T3-10 跨日弱化与展示状态

## 这一项要做什么

实现快照与条目的展示状态计算：快照当日有效，跨日后标记为"昨日提示"并弱化展示，引导农户更新；同时把环境来源、地区回退命中级、被抑制条目等展示标注一并算好，供前端直接渲染。核心原则是**后端不做内容变更**——跨日弱化只是 `display_status` 字段的取值变化，提示条目的文案与结构保持在生成时的样子。这条原则保证农户第二天打开看到的内容与他昨天看到的一致，不会因为"过期"而被系统改写或删减，从而避免"我昨天明明看到的是这样"的困惑。

## 前置依赖

- T3-08 产出的 `PromptSnapshot`（`generated_at`、`snapshot_date`、`env_source`、`revision`、`invalidated`）与 `PromptItem`（`suppressed`、`severity`、四段字段）。
- T3-02 的 `EnvFacts.staleness_note` 与 `region_hit_level`（来源标注文案的数据来源）；T3-03 的地区回退实际命中级。
- T2-33 的 `ChatResponse.environmentNote` 口径（"暂无环境数据，判断基于你的描述"），两处文案风格需一致，避免同一件事在对话页与首页说法不同。
- 外部环境：无（纯计算）。现有改造起点：`app/services/broadcast_service.py` 的 `_to_item`（当前无任何展示状态字段）。

## 实现要点

### 一、SnapshotView 与 display_status

```python
class SnapshotView(BaseModel):
    items: list[PromptItem]
    generated_at: datetime
    display_status: Literal["today", "yesterday", "stale"]
    days_ago: int
```

产品说明书 4.3.3 功能点 1 要求"跨日后标记为'昨日提示'并弱化展示"。实现为 `display_status` 由代码按 `generated_at` 与当前日期计算，前端据此降透明度并提示更新，后端不做内容变更。

```python
def compute_display_status(generated_at: datetime, today: date) -> tuple[str, int]:
    """展示状态由天数差计算，不由快照内容决定。"""
    days_ago = (today - generated_at.date()).days
    if days_ago <= 0:
        return "today", 0
    if days_ago == 1:
        return "yesterday", 1
    return "stale", days_ago
```

三值而不是两值：`today` 正常展示、`yesterday` 弱化但内容仍可信（农业生产变化缓慢，隔一天的农事提示多数仍然适用）、`stale` 需要更强的引导（提示"这条提示是 N 天前的，建议更新"）。用两值（当日/非当日）会让放置了一周的快照与昨天的快照得到同样的展示强度，引导力度不够。`days_ago` 单列而不让前端自己算，因为天数计算涉及时区，前端本地时区与服务端不一致时会算出不同的天数。

`days_ago <= 0`（含负值）统一按 `today` 处理。负值在时钟回拨或服务器时区切换时可能出现，此时按"今天"展示比按"未来"展示更安全。

### 二、环境来源标注

```python
ENV_SOURCE_LABEL: dict[str, str] = {
    "sensor": "数据来源：本地传感器",
    "sensor_stale": "数据来源：本地传感器（数据为 {stale_hours} 小时前）",
    "weather": "数据来源：公共天气",
    "none": "暂无环境数据，判断基于你的描述",
}


def build_env_note(env_source: str, staleness_note: str | None,
                   region_hit_level: str | None) -> str:
    """环境来源标注：四值全覆盖，none 与 sensor_stale 必填。"""
    if env_source == "none":
        base = ENV_SOURCE_LABEL["none"]
        if region_hit_level:
            return f"{base}；农时提示按{region_hit_level}通用口径给出。"
        return base
    if env_source == "sensor_stale":
        return ENV_SOURCE_LABEL["sensor_stale"].format(stale_hours=_hours_of(staleness_note))
    return ENV_SOURCE_LABEL[env_source]
```

四值都要有对应文案，不允许"没数据就留空"（与 T2-33 的 `environmentNote` 口径一致）。`none` 与 `sensor_stale` 两种情形必须给出明确说明：前者说明"判断基于你的描述"，后者说明"数据是几小时前的"——农户有权知道 AI 的判断建立在什么之上，这是产品说明书 4.4.2 明确的"透明度设计是建立信任的必要条件，也是安全红线的组成部分"。

`sensor_stale` 的文案要把 `staleness_note` 里的小时数提取出来嵌进统一句式，而不是直接用 `staleness_note` 原文。原因是 `staleness_note` 由采集层生成，措辞可能与界面风格不一致（如"数据为 3.5 小时前"），界面需要的是规整说法（"数据为 3 小时前"）。`_hours_of` 负责取整与提取。

### 三、抑制条目不出现在展示列表

`SnapshotView.items` 只含 `suppressed=False` 的条目。被抑制条目存在于数据库但仍出现在 `items` 里会让前端需要额外判断，且一旦某处忘了过滤就会把被压制的提示展示出来，直接违反 T3-06 的条数控制。因此过滤放在视图组装处而不是交给前端。

`urgent` 条目的展示不受 `display_status` 影响：即便快照已是"昨日"，紧急提示仍以最高视觉权重呈现，因为灾害性天气、药害固定现场这类提示的时效性以小时计。状态弱化针对的是"今天该做什么"的常规农事提示，不是"马上要出事"的紧急提示。实现为 `PromptItemView` 上带一个 `emphasis` 字段（`urgent` 条目恒为 `high`），前端按它决定是否忽略 `display_status` 的透明度降级。

### 四、生成时间的显示

产品说明书 4.3.3 功能点 1 要求"明确标注生成时间（例如'今日提示 · 9 月 23 日 07:12 更新'）"。`generated_at` 直接给出 ISO 时间戳，展示文案由前端按本地时区格式化；后端同时给一个 `generated_label` 预格式化字段作为兜底，格式为"M 月 D 日 HH:MM"。两处都给的理由是适老化要求（T4-02 逐页核验）可能要求特定格式，后端预格式化能保证各页面一致；但前端仍可用 ISO 时间戳自行格式化以适配系统语言与字号。

`revision` 一并输出，使前端可以显示"第 N 次更新"或在频次提示中复用（T3-08 的 `updateNotice`）。`invalidated=True` 的快照不返回给前端，视同当日尚未生成，引导农户点击更新。
