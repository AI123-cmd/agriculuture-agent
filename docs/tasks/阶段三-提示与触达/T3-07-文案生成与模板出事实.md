# T3-07 文案生成与模板出事实

## 这一项要做什么

把规则层产出的结构化条目变成农户能读的文案，落实"模板出事实、模型只改写"的分工：`callout / fact / impact / action` 四段的事实性内容由模板填充，模型只负责口语化改写；模型不可用时直接用模板原文输出。本项的关键约束是**模板本身必须可读**——不能假设后续一定有模型润色，因为零模型模式下模板原文就是农户最终看到的文案。现有实现没有文案层，`RuleResult.content` 是规则里直接拼的字符串，模型整份生成简报的路径（`skill.py`）又不受任何模板约束，两条路都不符合本项要求。

## 前置依赖

- T3-05 的 `RuleResult` 四段字段与 `rule_id`；T3-06 的截断结果（只对未抑制条目做文案生成，抑制条目不必润色，省成本且避免无效调用）。
- T2-55 的模型网关统一入口 `gateway.chat(task_type, messages, schema)`；T2-57 的任务类型路由（`TaskType.SNAPSHOT_WRITER` 对应小模型档位）；T2-58 的熔断器与降级链。
- T2-04 的流程配置 `output_template`（`max_chars` 上限、`required_sections`）；T4-05 的文案长度约束（快照文案字数上限，适老化要求）。
- 外部环境：模型网关可用但**不是必须**；`USE_MOCK_LLM=true` 时网关返回预设响应。现有改造起点：`app/broadcast/skill.py`（已由 T3-05 删除）、`app/broadcast/rules/*.py` 里的 `content` 拼接。

## 实现要点

### 一、模板出事实

```python
RULE_TEMPLATES: dict[str, str] = {
    "env_risk.heat": "{callout}：{fact}。{impact}。{action}。",
    "env_risk.soil_dry": "{callout}：{fact}。{impact}。{action}。",
    "calendar.stage": "{callout}：{fact}。{impact}。{action}。",
    "followup.effect_check": "{callout}：{fact}。{action}。",
}


def render_template(item: RuleResult) -> str:
    """模板原文：零模型模式下的最终文案，也是模型输出的对照基线。"""
    tpl = RULE_TEMPLATES.get(item.rule_id) or RULE_TEMPLATES.get(_family(item.rule_id))
    if tpl is None:
        raise RuleImplementationError(f"{item.rule_id} 缺少文案模板")
    return tpl.format(callout=item.callout, fact=item.fact,
                      impact=item.impact, action=item.action)
```

模板按 `rule_id` 组织，未精确匹配时按 `_family`（`rule_id` 的第一个点之前的部分，如 `env_risk`）取通用模板。**模板本身必须是完整可读的句子**：`"{callout}：{fact}。{impact}。{action}。"` 填入"水稻田""未来三天无有效降雨""分蘖期缺水会影响有效穗数""及时灌溉"后得到"水稻田：未来三天无有效降雨。分蘖期缺水会影响有效穗数。及时灌溉。"——四句并列，语义完整，农户能读懂，只是不够口语。这正是零模型模式可接受的下限：损失的是语感，不损失事实。

模板缺失时抛异常而不是回落到"直接拼四段"。回落会让模板表形同虚设，且失去"每条规则都有对应文案"的完整性保证。

### 二、模型只改写

```python
REWRITE_SYSTEM_PROMPT = """你是农技提示文案的改写助手。你只做一件事：把给定的四段事实改写成更口语的说法。

硬性约束：
1. 不得新增任何数字、日期、药剂名、剂量、时间。给定的数字必须原样保留。
2. 不得删除任何一段的事实内容。
3. 不得改变级别（紧急/注意/提醒）的判定。
4. 不得添加原文没有的建议或承诺。
5. 输出为一段不超过 {max_chars} 字的中文，不分点、不加标题。

原文：
{template_text}"""


async def rewrite_with_model(item: RuleResult, template_text: str,
                             max_chars: int) -> tuple[str, bool]:
    """模型改写，失败即返回模板原文。返回 (文本, 是否降级)。"""
    try:
        resp = await gateway.chat(
            task_type=TaskType.SNAPSHOT_WRITER,
            messages=[{"role": "user", "content": REWRITE_SYSTEM_PROMPT.format(
                template_text=template_text, max_chars=max_chars)}],
            schema=None, timeout=8.0)
        text = (resp.content or "").strip()
        if not text or not _facts_preserved(item, text):
            return template_text, True                # 改写失败或丢事实 → 用模板原文
        return text[:max_chars], False
    except Exception:                                 # noqa: BLE001
        return template_text, True
```

五条约束里最关键的是第一条与第二条，它们由 `_facts_preserved` 反向校验：把 `item` 四段中出现的所有数字与日期抽取出来，断言改写后的文本中全部存在。**数字丢失或数字被改是必须拦截的错误**，不是"文风问题"——产品说明书 6.4 红线四要求"不出现无数据支撑的数字"，允许模型改动数字等于允许红线被突破。校验方式与闸门 `R-PROVENANCE` 的思路一致（反向扫描），但难度更低，因为这里的基线文本是可控的模板原文。

模型输出超长时截断而不重试。重试会在模型稳定输出长文本时反复消耗配额，而截断的后果只是句子可能不完整，仍保留了事实。超时设 8 秒（短于常规 LLM 调用的 30 秒），理由是与农户交互无关、纯后台任务，等待时间过长不如直接降级。

### 三、降级与开关

`rewrite_with_model` 内部只有在拿到"非空且事实完整"的文本时才认为成功，其余所有情况（异常、超时、空响应、事实丢失、模型网关熔断）统一返回模板原文并把"是否降级"标为 `True`。降级标记写入 `PromptItem.facts_provenance` 的 `writer:template` / `writer:model` 键，供灰度期统计"改写成功率"以及评估"改写好还是不改写好"。

`USE_MOCK_LLM=true` 时网关返回预设响应，本项不需要为 mock 单独写分支：mock 响应若通过事实校验就当作正常改写，不通过就降级。这样 CI 里既能测到改写路径（构造通过校验的 mock 响应），也能测到降级路径（构造不通过的响应）。

### 四、字数上限与适老化

`max_chars` 取自流程配置的 `output_template.max_chars`（技术方案 7.4 要求在 200 至 500 之间），叠加 T4-05 规定的快照文案字数上限，取两者较小值。字数在提示词里作为约束给出，同时在返回前强制截断——只靠提示词约束长度是不可靠的，必须在代码里兜住。

截断要按句子边界而不是按字符数硬切。硬切会产出"及时灌溉，避免作"这类断句，农户读到残缺句子会怀疑内容未加载完。实现为在 `max_chars` 附近向前找最近的句号或分号，找不到才硬切。这条与适老化目标一致：目标用户对"没说完的话"容忍度低，可能因此反复刷新。

### 五、零模型模式下的完整行为

零模型模式下 `build_text` 的路径为：`render_template` 产出模板原文 → `rewrite_with_model` 立即返回 `(template_text, True)` → 落库的是模板原文。整条链路不产生任何模型调用，前端展示与有模型时完全一致（只是文案略生硬），提示条目的数量、级别、执行勾选、触达能力全部不受影响。这就是产品说明书 6.3 兜底三"不允许整体页面不可用"在快照链路上的落地形态。

## 验收标准

- `pytest tests/broadcast/test_writer.py` 全部通过，含：对每条已注册的 `rule_id` 调用 `render_template`，断言不抛异常且输出含四段中每一段的非空内容（防模板漏配）。
- 零模型：把 `gateway.chat` 替换为抛异常的桩，断言 `build_text` 返回模板原文且降级标记为 `True`，不抛异常。
- 事实保全：构造一条含数字"3 天"与"35℃"的条目，让 mock 返回删掉数字的文本，断言 `_facts_preserved` 为 `False` 且最终返回模板原文；让 mock 返回保留全部数字的文本，断言返回模型文本且降级标记为 `False`。
- 字数：配置 `max_chars=120`，构造超长模板原文，断言返回值 `len(text) <= 120` 且结尾字符为句末标点或已用尽上限；断言在可能的情况下截断落在句子边界。
- 断言 `RULE_TEMPLATES` 的每个键都能被至少一条已注册规则产出（用 T3-05 的规则注册表交叉校验）；断言未登记 `rule_id` 时 `render_template` 抛 `RuleImplementationError`。
- `grep -n "药剂\|剂量\|安全间隔期" backend/app/broadcast/prompts/snapshot_writer.py` 只出现在"不得新增"的约束句里，无任何具体药剂或数值；`ruff check`、`ruff format --check`、`mypy app` 三条命令均返回 0。
