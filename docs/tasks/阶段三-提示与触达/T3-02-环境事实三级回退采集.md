# T3-02 环境事实三级回退采集

## 这一项要做什么

实现环境事实的三级回退采集：自有传感器新鲜读数 → 传感器陈旧读数带 `staleness_note` → 天气服务 → 均不可用返回 `source="none"`。任何一级都不得用推测值填充，`source="none"` 时环境风险类提示条目在生成阶段即被拦截，不进入文案环节。现有实现 `app/broadcast/snapshot.py` 的 `build_snapshot` 在无数据时回落到 `source="mock"` 并给出静态值，正是产品说明书 6.4 红线四"不出现无数据支撑的数字"要禁止的行为，本项整体替换。

## 前置依赖

- T3-01 提供的 `PromptSnapshot.env_source` 字段取值口径（`sensor` / `sensor_stale` / `weather` / `none`），本项产出的 `EnvFacts.source` 必须与此完全一致。
- T5-08 提供的环境数据读取接口与环境看板来源标注口径；T5-07 的读数合法性校验与 `quality` 三值（`ok` / `suspect` / `stale`），本项据此判断读数能否参与阈值判断。
- 外部环境：`env_reading` 时序表（T1-03 建立）、天气服务密钥（`WEATHER_API_URL` / `WEATHER_API_KEY`）。现有改造起点：`app/broadcast/snapshot.py`、`app/tools/sensors.py`、`app/tools/weather.py`。

## 实现要点

### 一、EnvFacts 与三级回退

```python
class EnvFacts(BaseModel):
    model_config = ConfigDict(extra="forbid")
    source: Literal["sensor", "sensor_stale", "weather", "none"]
    values: dict[str, float] = {}
    observed_at: datetime | None = None
    staleness_note: str | None = None
    region_hit_level: str | None = None       # 地区回退实际命中级，供界面标注
    provenance: dict[str, str] = {}           # 指标 -> 来源标识，进 facts_provenance


async def collect_env_facts(user_id: str, plot_id: str | None) -> EnvFacts:
    """环境事实采集：三级回退，不可用即返回 empty（该路提示不生成）。"""
    # 优先级 1：自有传感器
    reading = await sensor_service.latest(user_id, plot_id)
    if reading and reading.is_fresh(minutes=30):
        return EnvFacts(source="sensor", values=reading.values,
                        observed_at=reading.observed_at)
    if reading and reading.is_within_hours(24):
        # 参考值：可用但必须标注"数据为 XX 小时前"
        return EnvFacts(source="sensor_stale", values=reading.values,
                        observed_at=reading.observed_at,
                        staleness_note=f"数据为 {reading.age_hours()} 小时前")

    # 优先级 2：天气服务
    weather = await weather_service.current(user_id)
    if weather:
        return EnvFacts(source="weather", values=weather.values,
                        observed_at=weather.observed_at)

    # 优先级 3：均不可用 → 不生成环境风险类提示
    return EnvFacts(source="none", values={}, observed_at=None)
```

三级的分界线是 30 分钟与 24 小时，取值来自产品说明书 4.4.3 功能点 3。`is_fresh(minutes=30)` 内部还要叠加 `quality == "ok"` 判断：T5-07 会把超范围读数标 `suspect`、超时效标 `stale`，`suspect` 的读数保留原始值供排查但不参与阈值判断。因此实际判定是"新鲜 且 `quality=ok`"，被标 `suspect` 的读数等同于该级缺失，直接降级到下一级而不是带着可疑数字进入规则层。这条判断放在 `is_fresh` 内部而非调用处，因为它是"新鲜"这个概念的一部分，散落在调用处会被后续新增的调用点遗漏。

`sensor_stale` 与 `weather` 都是可用级，但语义不同：`sensor_stale` 是"本地实测但不新"，`weather` 是"区域预报但非本地"。前者必须带 `staleness_note`，后者不需要，因为天气预报本身就是区域值，不存在"过期"概念。界面标注文案因此在两种来源下不同（T3-10 的展示状态负责渲染）。

### 二、source="none" 时在生成阶段即拦截

```python
ENV_RISK_KINDS = {"env_risk"}

def is_env_risk_blocked(facts: EnvFacts, source_kind: str) -> bool:
    """环境事实不可用时，环境风险类条目在生成阶段被拦截。"""
    return facts.source == "none" and source_kind in ENV_RISK_KINDS
```

产品说明书 4.3.2 明确"天气数据也不可用时，该路提示条目不生成，而不是用推测值生成"，产品说明书 6.4 红线四要求"不出现无数据支撑的数字"。拦截点必须在生成阶段而不是文案阶段：如果让条目先产出、再在文案环节丢弃，规则层就已经用 `None` 参与过阈值比较，一旦某条规则忘了判空就会产出"当前气温 ℃"这类残缺文案。放在生成阶段，规则层根本收不到这些条目，出错面为零。

这与闸门的 `R-NO-DATA` 形成双保险：本层保证"没有数据就不生成"，闸门保证"即使生成了也过不去"。两层的判据不同（前者看 `source`，后者看 `facts_provenance` 是否覆盖文案中的数字），因此不是重复实现。拦截要记录原因而不是静默丢弃，`prompt_snapshot.env_source = "none"` 本身就是这条记录，同时 T3-10 据此渲染"暂无环境数据"的来源标注。

### 三、与现有实现的差异

现有 `build_snapshot` 有三个必须改掉的行为。其一，`source="mock"` 兜底必须删除：mock 值会一路流到文案层变成"当前气温 28℃"，正是红线四禁止的。其二，`_source()` 里"`snapshot.source == "mock"` 就返回 `weather`"这类推断式来源标注必须删除，来源只能由采集层给出实际命中级，不能由规则层猜。其三，`EnvSnapshot` 与 `weather.query_weather` 返回的 `forecast` 字典结构要收敛为 `EnvFacts.values` 的扁平指标映射，使 `facts_provenance` 能逐指标登记来源。

`weather_service.current(user_id)` 必须返回 `None` 而不是抛异常来表示不可用：天气服务是增强项，其失败不能让快照生成整体失败（产品说明书 6.3 兜底五"推送失败不能影响任何已有功能"同属一类失败隔离原则）。HTTP 超时、配额耗尽、地区无覆盖三种情况在 `weather.py` 内部分别处理并统一返回 `None`，调用方不需要区分。

### 四、与问诊链路的共享

本项产出的 `EnvFacts` 有两处消费者，两处必须看到同一份来源判断，否则会出现"首页说没有环境数据、对话页却拿环境值做判断"的不一致：

| 消费者 | 用途 | 取用字段 |
| --- | --- | --- |
| 快照生成（T3-08） | 环境风险类提示的阈值判断与生成拦截 | `source`、`values`、`provenance` |
| 问诊接口（T2-33） | `environmentNote` 必填场景判定 | `source`、`region_hit_level` |

`env_source` 的四个取值必须与 T2-33 的 `STALE_ENV_SOURCES = {"none", "sensor_stale"}` 完全对齐：`sensor_stale` 虽然在采集层是"可用"级（能支撑提示生成），但在问诊层必须提示农户"数据是几小时前的"，因为它不足以支撑判断。这两个判断看似矛盾，实则是同一事实在不同场景下的两种表达——提示生成说"我能给你一条基于实测的提醒"，问诊判断说"我的判断建立在非实时数据上"。因此本项不把 `sensor_stale` 归入"不可用"，而是保留该级并附上 `staleness_note`，由下游各自决定如何提示。

环境数据还与知识库的地区回退有交集：天气服务按农户所在地区取数，若农户档案缺地区，天气服务无法定位。此时 `weather.current` 返回 `None`，采集结果落到 `source="none"`，而农事历侧（T3-03）会退到全国通用条目。同一份快照里出现"环境不可用"与"农事历按全国口径"两种标注是正常的，两者说明的是不同数据的可用性，不应合并成一句话。

## 验收标准

- `pytest tests/broadcast/test_env_facts.py` 全部通过，含五条分支用例：新鲜读数（30 分钟内、`quality=ok`）返回 `source="sensor"` 且 `staleness_note is None`；陈旧读数（1 小时前）返回 `source="sensor_stale"` 且 `staleness_note` 含"小时前"；超 24 小时回退到天气返回 `source="weather"`；无传感器无天气返回 `source="none"` 且 `values == {}`；`quality="suspect"` 的读数被跳过后仍能正确降级到天气。
- 构造 `source="none"` 的 `EnvFacts`，断言 `is_env_risk_blocked(facts, "env_risk") is True`、`is_env_risk_blocked(facts, "followup") is False`；断言此时规则层产出的条目集合中不含 `source_kind="env_risk"` 的条目。
- 断言 `collect_env_facts` 在任何分支下都不产生"推测值"：monkeypatch 掉传感器与天气服务使其返回 `None`，断言返回值 `values` 为空字典而非含默认温度的数字。
