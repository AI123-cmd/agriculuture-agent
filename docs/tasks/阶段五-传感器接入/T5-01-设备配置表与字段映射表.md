# T5-01 设备配置表与字段映射表

## 这一项要做什么

建立传感器接入的两张核心配置表 `device_config` 与 `field_mapping`，作为三步接入流程与设备上报解析的数据地基。前者记录农户已绑定设备与接入参数，后者把设备原始字段翻译成系统标准环境指标。现有 `app/models/device.py` 的 `Device` 表只承担"设备台账"职责，字段为 `device_sn` / `device_type` / `status` / `last_online` / `bind_time`，缺少接入协议、厂商模板引用与密钥引用，且没有字段映射概念，本项按技术方案 12.6 新增两张表并与现有表建立关系。

这两张表刻意分离。设备配置是"这台设备怎么接进来"，字段映射是"它的报文每一列是什么"。同一品牌同一型号的设备报文结构相同，因此预置模板可以复用到多台设备，农户绑定第二台时第二步的"粘贴样例报文"可以直接命中模板而跳过。

## 前置依赖

- T1-04 提供的 Alembic 迁移链路（本项新增一支迁移，不使用启动建表）。
- T1-05 提供的 `OwnedMixin` 与 `OwnedRepository` 基类，两张表都要带 `user_id` 且索引必建。
- T1-03 提供的 `env_reading` 时序表（本项不建，但 `field_mapping.standard_metric` 的取值集合必须与它写入的 `metric` 对齐）。
- 外部环境：PostgreSQL 16+；`Numeric` 类型在 PG 上映射为 `numeric`。
- 需要人工确认：P0 指标集合的产品口径（土壤温度、土壤水分、空气温度、空气湿度、降雨量五项），作为 `standard_metric` 的封闭枚举取值。
- 现有改造起点：`app/models/device.py`（`Device` 表保留，不被替换）、`app/models/__init__.py`（注册新模型）。

## 实现要点

### 一、两表字段按方案 12.6 原样采用

```python
class DeviceConfig(Base, OwnedMixin):
    """设备接入配置：记录农户已绑定设备与接入参数。"""

    __tablename__ = "device_config"
    __table_args__ = (
        UniqueConstraint("device_sn", name="uq_device_config_sn"),
        Index("ix_device_config_user_bound", "user_id", "unbound_at"),
    )

    id: Mapped[str] = mapped_column(String(36), primary_key=True)
    # user_id 由 OwnedMixin 提供，索引在 OwnedMixin 内建
    device_sn: Mapped[str] = mapped_column(String(60), unique=True, nullable=False, index=True)
    farm_entry_id: Mapped[str | None] = mapped_column(String(36))
    vendor_template_id: Mapped[str | None] = mapped_column(String(36))   # 使用的厂商模板
    protocol_type: Mapped[str] = mapped_column(String(20), default="http_direct")
    online_status: Mapped[str | None] = mapped_column(String(20))        # online / offline / fault
    last_report_at: Mapped[datetime | None] = mapped_column(DateTime(timezone=True))
    bound_at: Mapped[datetime] = mapped_column(DateTime(timezone=True), server_default=func.now())
    unbound_at: Mapped[datetime | None] = mapped_column(DateTime(timezone=True))
    secret_ref: Mapped[str | None] = mapped_column(String(120))          # 指向上游的引用，本表不存明文


class FieldMapping(Base, OwnedMixin):
    """字段映射：把设备原始字段翻译成标准指标。

    与设备配置分离，使同品牌设备可共用预置模板。
    """

    __tablename__ = "field_mapping"
    __table_args__ = (
        UniqueConstraint("device_id", "raw_field", name="uq_field_mapping_device_raw"),
        Index("ix_field_mapping_device", "device_id"),
    )

    id: Mapped[str] = mapped_column(String(36), primary_key=True)
    device_id: Mapped[str] = mapped_column(
        String(36), ForeignKey("device_config.id", ondelete="CASCADE"), index=True
    )
    raw_field: Mapped[str] = mapped_column(String(40), nullable=False)          # 如 "t1"
    standard_metric: Mapped[str] = mapped_column(String(30), nullable=False)    # soil_temp / air_temp / ...
    unit: Mapped[str | None] = mapped_column(String(10))
    scale_factor: Mapped[Decimal] = mapped_column(Numeric(12, 6), default=1)
    offset_value: Mapped[Decimal] = mapped_column(Numeric(12, 6), default=0)
    data_type: Mapped[str | None] = mapped_column(String(10))                   # float / int / bool
    sample_raw: Mapped[str | None] = mapped_column(Text)                        # 样例报文中的原始片段
```

方案 12.6 的原文里 `id` 为 `String(36)`、时间列写 `DateTime`，本项按全局约定"时间统一带时区"改为 `DateTime(timezone=True)`，这是对方案的一处推断：方案写 `DateTime` 未标注时区，而归属与新鲜度判断（T5-07 的 24 小时、T5-08 的 30 分钟）跨时区比较必须显式带时区，否则 `last_report_at` 与 `observed_at` 相减会引入偏移。

`secret_ref` 一列超出方案 12.6 原文，来自调研报告 10.2 的"密钥存引用而非明文"。方案 13.3 要求 `verify_secret(device, x_device_secret)`，该函数需要一个可比对的密钥材料来源；把密钥明文落在业务表会让审计、轮换、离职回收全部失控。本项只建列并约定"值为密钥托管中的键名"，实际下发在 T5-03。

### 二、字段映射与设备配置分离的理由

两表分离的直接收益有三点，这三点决定了它不能合并成一张宽表：

第一，**复用**。同品牌同型号设备报文结构一致，`field_mapping` 的取值集合可以来自 `vendor_template.field_spec`。农户绑第二台同型号设备时，映射从模板一次性铺开，不需要再粘贴样例报文（T5-04 的模板匹配分支）。若映射写在设备表里，每台设备都要重复录入一份结构相同的配置。

第二，**一对多**。一台四合一墒情站会同时上报 `t1` / `h1` / `ec1` / `ph1` 四个字段，加上报文内嵌的 `ts`，映射条数是设备条数的数倍。合并成宽表后 `raw_field` 会退化成一列 JSON，索引与唯一约束都用不上，`parse_payload` 要反复解 JSON。

第三，**变更隔离**。两类数据的生命周期不同：`device_config` 随绑定关系变化，`field_mapping` 随报文结构变化。农户改一个字段含义时只动映射一行，不影响设备绑定关系、在线状态与上报时间戳；设备重新绑定或解绑也不该让映射行的语义发生变化。

### 三、标准指标用封闭枚举

`standard_metric` 不接受自由字符串，取值来自 `StandardMetric` 枚举。P0 五项来自产品说明书 4.4.4（"与现有提示阈值字段完全吻合，接入后无需改造提示逻辑"），另加 P1、P2 与基础气象项：

| 枚举值 | 中文名 | 默认单位 | 合法区间 | 优先级 |
| --- | --- | --- | --- | --- |
| `soil_temp` | 土壤温度 | °C | -10 至 60 | P0 |
| `soil_moisture` | 土壤水分 | % | 0 至 100 | P0 |
| `air_temp` | 空气温度 | °C | -40 至 60 | P0 |
| `air_humidity` | 空气湿度 | % | 0 至 100 | P0 |
| `rainfall` | 降雨量 | mm | 0 至 500 | P0 |
| `light_lux` | 光照 | lux | 0 至 200000 | P1 |
| `wind_speed` | 风速 | m/s | 0 至 60 | P1 |
| `soil_ph` | 土壤 pH | 无量纲 | 0 至 14 | P2 |
| `soil_ec` | 土壤电导率 | mS/cm | 0 至 20 | P2 |

合法性区间这一列是本项对方案的补充：方案 12.6 未给出指标量程，但 T5-07 的"数值范围合法性 → 标 `suspect`"与全局约定"凡是能被规则判定的，不交给模型"都要求量程是代码里的确定常量。区间与枚举放在同一个模块，避免"枚举在一处、区间在另一处"造成的漏配。

用枚举而不是自由字符串的理由是一致性要求：`standard_metric` 在 `field_mapping`、`vendor_template.field_spec`、`env_reading.metric` 三处出现，任何一处漂移都会让读数写进去却查不出来。解析器把设备原始字段映射到枚举上，落不到枚举即视为映射非法，在保存阶段（T5-05）就拒绝。

### 四、仓储与归属

两张表都由 `OwnedRepository` 派生。`field_mapping` 虽然自身带 `user_id`（跟随 `OwnedMixin`），但它的归属还可经 `device_config.user_id` 推导，存在两处不一致的可能。约定以 `field_mapping.user_id` 为唯一准据，写入时由 `device_config.user_id` 复制而来，读取时一律带 `user_id` 条件。这样即使 `device_id` 被猜测，跨农户读取也会返回空。

```python
class DeviceConfigRepository(OwnedRepository[DeviceConfig]):
    def __init__(self) -> None:
        super().__init__(DeviceConfig)

    async def get_by_sn(self, db: AsyncSession, device_sn: str) -> DeviceConfig | None:
        """设备上报专用：设备侧无小程序令牌，只能按 SN 定位后校验归属。"""
        stmt = select(DeviceConfig).where(DeviceConfig.device_sn == device_sn,
                                          DeviceConfig.unbound_at.is_(None))
        return (await db.execute(stmt)).scalar_one_or_none()
```

`get_by_sn` 不带 `user_id` 是刻意的例外，它服务的是设备上报入口（T5-06），该入口拿到 `device_sn` 时还不知道归属。归属校验必须在取到设备后再做一次（T5-06 校验顺序第二步"设备存在"、第三步"归属"），这一例外要在方法 docstring 里写明，避免被当成漏写归属条件的缺陷（产品说明书 4.5.2 功能点 4 把"未校验归属的访问路径"列为必须修复的安全问题）。

### 五、迁移与索引

```python
def upgrade() -> None:
    op.create_table(
        "device_config",
        sa.Column("id", sa.String(36), primary_key=True),
        sa.Column("user_id", sa.String(36), nullable=False, index=True),
        sa.Column("device_sn", sa.String(60), nullable=False, unique=True, index=True),
        sa.Column("farm_entry_id", sa.String(36)),
        sa.Column("vendor_template_id", sa.String(36)),
        sa.Column("protocol_type", sa.String(20), server_default="http_direct"),
        sa.Column("online_status", sa.String(20)),
        sa.Column("last_report_at", sa.DateTime(timezone=True)),
        sa.Column("secret_ref", sa.String(120)),
        sa.Column("bound_at", sa.DateTime(timezone=True), server_default=sa.func.now()),
        sa.Column("unbound_at", sa.DateTime(timezone=True)),
    )
    op.create_table(
        "field_mapping",
        sa.Column("id", sa.String(36), primary_key=True),
        sa.Column("user_id", sa.String(36), nullable=False, index=True),
        sa.Column("device_id", sa.String(36),
                  sa.ForeignKey("device_config.id", ondelete="CASCADE"), nullable=False, index=True),
        sa.Column("raw_field", sa.String(40), nullable=False),
        sa.Column("standard_metric", sa.String(30), nullable=False),
        sa.Column("unit", sa.String(10)),
        sa.Column("scale_factor", sa.Numeric(12, 6), server_default="1"),
        sa.Column("offset_value", sa.Numeric(12, 6), server_default="0"),
        sa.Column("data_type", sa.String(10)),
        sa.Column("sample_raw", sa.Text),
        sa.UniqueConstraint("device_id", "raw_field", name="uq_field_mapping_device_raw"),
    )
```

`ondelete="CASCADE"` 对应方案 12.7 把 `field_mapping.device_id → device_config.id` 列为"中"优先级外键。解绑采用软删除（写 `unbound_at`）而不是物理删除，因此级联删除只在物理清理设备行时生效，解绑后映射仍可追溯（T5-09 据此复用）。唯一约束 `(device_id, raw_field)` 防止同一设备的同一原始字段被映射两次，这是"同一条读数写两遍"的根因防护。
