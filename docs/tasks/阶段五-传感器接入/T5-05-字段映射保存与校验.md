# T5-05 字段映射保存与校验

## 这一项要做什么

实现三步接入的第三步收尾：农户确认或改选每个字段的含义后，后端校验整份映射的完整性与自洽性，写入 `field_mapping` 表，并把设备置为可接入状态。校验是这一步的重点——映射一旦错误就会让后续所有读数写错指标或算错数值，而农户已经离开配置页，错误只能等环境看板显示异常时才被发现。

校验分三层：字段级（原始字段存在、指标在枚举内、单位可规整）、映射级（同一设备同一原始字段不重复、标准指标不冲突、必要指标齐全）、换算级（用样例值试算，结果落在该指标合法区间内）。任一层不通过都拒绝保存并返回具体到字段的错误。

## 前置依赖

- T5-04 提供的字段推断结果（`DetectedField` 与 `MappingItem` 定义）；农户的改选以 `DetectedField.candidates` 为界。
- T5-01 提供的 `field_mapping` 表、`FieldMappingRepository`、`StandardMetric` 枚举与合法区间。
- T5-02 提供的模板 `field_spec`（模板铺开路径下本项直接复用其换算参数）。
- 外部环境：无。校验是纯规则，不调用模型。
- 需要人工确认：各标准指标的必填性（P0 五项是否强制要求齐全），属产品口径。

## 实现要点

### 一、出入参按方案 13.4 原样采用

```python
class MappingSaveRequest(BaseModel):
    model_config = ConfigDict(extra="forbid")
    deviceId: str
    mappings: list[MappingItem]               # 农户点选结果


class MappingItem(BaseModel):
    rawField: str
    standardMetric: str
    unit: str
    # 以下由系统填写，前端可回传但会被后端覆盖
    scaleFactor: float = 1.0
    offsetValue: float = 0.0
    dataType: str = "float"
    sampleRaw: str | None = None


class MappingSaveResponse(BaseModel):
    deviceId: str
    saved: int                               # 保存的映射条数
    skipped: list[str]                       # 被忽略的字段
    warnings: list[str] = []                 # 非阻断提示（如缺少 P1 指标）
```

`mappings` 里包含农户选择忽略的字段是不合法的：忽略的字段不进请求体。`skipped` 由后端根据原始报文与 `mappings` 的差集给出，用于前端提示"你忽略了 3 个字段，它们不会被记录"。

### 二、三层校验

```python
async def save_mappings(db: AsyncSession, user_id: str, req: MappingSaveRequest) -> MappingSaveResponse:
    device = await device_repo.get(db, user_id, req.deviceId)
    if device is None:
        raise NotFoundError("设备不存在或无权访问")

    normalized = [_normalize(item) for item in req.mappings]     # 覆盖换算参数与单位
    _validate_field_level(normalized)                            # 第一层
    _validate_mapping_level(normalized)                          # 第二层
    _validate_scale_level(normalized)                            # 第三层

    await mapping_repo.replace_all(db, user_id, device.id, normalized)
    await device_repo.mark_configured(db, device.id)
    return MappingSaveResponse(deviceId=device.id, saved=len(normalized),
                               skipped=_skipped_fields(device, normalized),
                               warnings=_soft_warnings(normalized))
```

三层各自失败时抛出 `ValidationError` 并带结构化的字段定位，前端能定位到具体某个输入框：`detail={"rawField": "t1", "layer": "scale"}`。

### 三、第一层：字段级

| 检查 | 失败行为 |
| --- | --- |
| `rawField` 非空、长度不超过 40 | 拒绝，`layer=field` |
| `rawField` 不在该设备最近一次样例报文的字段集合内 | 拒绝（防止前端构造任意字段） |
| `standardMetric` 落在 `StandardMetric` 枚举内 | 拒绝，`layer=field` |
| `unit` 能被规整到该指标的默认单位 | 静默覆盖为该指标默认单位（不拒绝） |
| `dataType` 落在 `float` / `int` / `bool` / `str` 内 | 静默覆盖为推断值 |

`rawField` 必须来自样例报文这一条是关键：没有它，请求体可以是任意 JSON，农户（或恶意调用者）能往 `field_mapping` 里写设备根本不会上报的字段，让后续解析器在 `parse_payload` 时找不到值。设备绑定后样例报文要被暂存（T5-04 落地时写入设备侧短时状态），本项据此比对。

`unit` 采取"覆盖而非拒绝"：农户或前端可能传 `"℃"` 或 `"C"` 或 `"摄氏度"`，这些都规整到 `°C`。单位是展示属性，不应该因为写法差异阻断保存。换算参数同理，一律由后端按指标与样例值重算覆盖。

### 四、第二层：映射级

| 检查 | 说明 |
| --- | --- |
| 无重复 `rawField` | 同一原始字段只能映射一次（数据库唯一约束兜底） |
| 无重复 `standardMetric` | 同一指标不能由两个字段映射（默认拒绝，避免读数二义） |
| P0 指标齐全度 | 缺失 P0 项时进 `warnings` 而非拒绝（设备可能只测部分指标） |
| 映射条数上限 | 不超过 20 条（防异常报文铺开过多字段） |

`standardMetric` 不重复这一条默认拒绝，但有一个例外：设备同时上报"瞬时值"与"平均值"时，两个字段都想映射到同一指标。这种场景极罕见，本项选择先拒绝并在错误信息里提示"请只保留一个字段"，避免引入"取哪个值"的隐式规则。这是对方案的一处推断：方案 13.4 未涉及同指标多字段的处理，本项取"显式拒绝、让农户决定"而不是"系统自动选一个"。

P0 缺失只告警不拒绝，理由是产品说明书 4.4 把传感器定位为可选增强层，农户完全可能只买一个土壤水分探头。若强制齐全，会与"接入门槛压到农户可自行为之"的目标冲突。

### 五、第三层：换算级

用样例值代入 `物理值 = scale_factor × raw + offset_value`，校验结果落在 `StandardMetric` 的合法区间内：

```python
def _validate_scale_level(items: list[MappingItem]) -> None:
    """用样例值试算，结果必须在指标合法区间内。这是错配的最后一道拦截。"""
    for it in items:
        metric = StandardMetric(it.standardMetric)
        raw = _parse_raw(it.sampleRaw)
        if raw is None:
            continue                              # 样例值无法数值化时跳过试算
        value = it.scaleFactor * raw + it.offsetValue
        lo, hi = METRIC_RANGES[metric]
        if not (lo <= value <= hi):
            raise ValidationError(
                f"字段 {it.rawField} 的换算结果 {value} 超出{metric.value}的合理范围",
                detail={"rawField": it.rawField, "layer": "scale"},
            )
```

这一层拦截的是最典型的错配：`t1=265` 被误认为"空气温度"且 `scale_factor=1`，试算得 265°C，超出区间直接拒绝。若没有这一层，错误会一直存到读数落库才由 T5-07 标 `suspect`，而那时农户已经离开配置页。样例值无法数值化（如 `"ON"`）时跳过试算而不是拒绝：布尔类字段没有区间概念，跳过只针对这一条映射，不影响其他字段的校验。

### 六、写入策略：整体替换

`replace_all` 在一个事务内先删后插：

```python
async def replace_all(self, db: AsyncSession, user_id: str, device_id: str,
                      items: list[MappingItem]) -> int:
    """整份替换：先删该设备全部旧映射，再插新映射，单事务。"""
    await db.execute(delete(FieldMapping).where(FieldMapping.device_id == device_id,
                                                FieldMapping.user_id == user_id))
    db.add_all([FieldMapping(id=str(uuid4()), user_id=user_id, device_id=device_id,
                             raw_field=it.rawField, standard_metric=it.standardMetric,
                             unit=it.unit, scale_factor=it.scaleFactor,
                             offset_value=it.offsetValue, data_type=it.dataType,
                             sample_raw=it.sampleRaw) for it in items])
    await db.commit()
    return len(items)
```

整体替换而不是增量 upsert，因为农户在确认页上的语义是"这就是完整的映射"。增量更新的问题在于：农户删掉一个字段时，前端要显式发删除指令，漏发就会留下幽灵映射。整体替换让请求体即为最终状态，前端不需要维护差异。代价是重绑设备时会重写一遍映射（数据量小，可接受）。先删后插必须在同一事务内，且删除带 `user_id` 条件，否则一个越权的 `device_id` 会删掉他人映射（产品说明书 4.5.2 功能点 4 把归属校验列为必修复项）。

### 七、保存后重算预览

保存成功后返回一份换算后的读数预览，让农户在离开前看到"你的设备上报时，系统会这样读"：

| 原始字段 | 原始值 | 映射指标 | 换算后 |
| --- | --- | --- | --- |
| `air_temp` | `265` | 空气温度 | `26.5 °C` |
| `air_humi` | `78` | 空气湿度 | `78 %` |
| `soil_moisture` | `23` | 土壤水分 | `23 %` |

预览的值由后端用保存后的 `field_mapping` 实跑一遍 `parse_payload` 得出，而不是另算一份。这样预览与实际链路口径完全一致，避免"预览对但上报错"。这也是本项与 T5-06 的接口约定：`parse_payload` 是共享函数，T5-05 用它做预览，T5-06 用它做落库解析。

## 验收标准

- `pytest backend/tests/services/test_mapping_save.py` 全部通过，含以下用例：合法映射保存成功且 `saved` 等于映射条数；重复 `rawField` 抛 `ValidationError`；重复 `standardMetric` 抛 `ValidationError`；`standardMetric="temp"`（不在枚举）抛 `ValidationError`；`rawField` 不在样例报文内抛 `ValidationError`。
- 换算级用例：`{"rawField":"t1","standardMetric":"air_temp","sampleRaw":"265","scaleFactor":1.0}` 抛 `ValidationError` 且 `detail.layer == "scale"`；同一条把 `scaleFactor` 改为 `0.1` 后保存成功。
- P0 缺失用例：只提交 `soil_moisture` 一条映射保存成功，`warnings` 含缺失 P0 指标提示，`saved == 1`。
- `unit` 覆盖用例：提交 `unit="℃"` 保存后 `SELECT unit FROM field_mapping` 返回 `°C`；提交 `unit="乱七八糟"` 同样被覆盖为 `°C` 而不报错。
- 整体替换用例：先保存 3 条映射，再提交 1 条，断言 `SELECT count(*) FROM field_mapping WHERE device_id=...` 返回 1；替换过程任一校验失败时不产生部分写入（事务回滚，计数仍为 3）。
- 越权用例：用 `u2` 的令牌对 `u1` 的设备保存映射返回 404，且 `u1` 的映射未被删除。
- 预览接口返回值与直接调用 `parse_payload` 对同一 `field_mapping` 的结果逐字段相等。
- `ruff check backend/app`、`ruff format --check backend/app`、`mypy backend/app` 三条命令均返回 0。
