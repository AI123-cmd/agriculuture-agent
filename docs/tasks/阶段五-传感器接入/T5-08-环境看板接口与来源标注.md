# T5-08 环境看板接口与来源标注

## 这一项要做什么

把环境看板接口改造为读取真实读数并标注来源。现有 `GET /api/environment/summary` 与 `/detail` 的数据来自 `tools/sensors.py` 的硬编码常量，`source` 写死 `"sensor_snapshot"`，前端无从知道这些数字是实测还是兜底。本项实现方案 13.1 的 `GET /api/v1/environment/board`，返回各指标的数值、单位、来源、更新时间与状态标注。

关键是**来源标注**：农户必须能看出"这个数字来自我的传感器"还是"来自公共天气"还是"暂无数据"，以及数据是不是几小时前的。这条透明度要求是产品说明书 4.4.2 的组成部分，也是安全红线（农户有权知道判断建立在什么之上）。

## 前置依赖

- T5-07 提供的读数质量口径（`ok` / `suspect` / `stale`）与 `latest()` / `age_hours()`。
- T3-02 提供的 `EnvFacts` 模型与 `collect_env_facts()` 三级回退；本项与它共用同一套来源集合与新鲜度判据。
- T5-03 至 T5-05 提供的设备与映射（看板的设备侧数据）；T5-01 的 `StandardMetric` 与合法区间（状态标注的判据）。
- 外部环境：`env_reading` 时序表；天气服务密钥（`WEATHER_API_URL` / `WEATHER_API_KEY`）。
- 现有改造起点：`app/api/v1/environment.py`（两个接口，前缀 `/api/environment`）、`app/services/environment_service.py`（`summary()` / `detail()`，内部调 `sensors.query_sensors()`）、`app/schemas/environment.py`（`EnvironmentSummary` / `EnvironmentDetail`）、`app/integrations/weather.py`（`get_weather_summary()` 返回字符串，无结构化时间戳）。

## 实现要点

### 一、看板出入参

```python
class BoardMetric(BaseModel):
    metric: str                    # StandardMetric 枚举值
    label: str                     # 中文标签，如"土壤温度"
    value: float | None
    unit: str
    status: str                    # normal / high / low / unknown
    quality: str                   # ok / suspect / stale
    observed_at: datetime | None


class SourceBadge(BaseModel):
    source: Literal["sensor", "sensor_stale", "weather", "none"]   # 与 T3-02 EnvFacts.source 同集合
    label: str                     # "数据来源：本地传感器" 等
    freshness_note: str | None     # "数据为 3 小时前"
    region_hit_level: str | None   # 地区回退实际命中级，天气来源时使用


class EnvironmentBoard(BaseModel):
    metrics: list[BoardMetric]
    source_badge: SourceBadge
    devices: list[DeviceItem]      # 复用现有 DeviceItem
    last_update_at: datetime | None
```

`source` 的取值集合与 T3-02 的 `EnvFacts.source` 完全一致（`sensor` / `sensor_stale` / `weather` / `none`）。这不是巧合而是硬约束：同一个农户的同一份环境事实，在首页看板与问诊接口两处必须给出一致的来源判断，否则会出现"看板说本地传感器、对话页说暂无环境数据"的矛盾。

### 二、来源标注文案

| `source` | `label` | `freshness_note` | 触发条件 |
| --- | --- | --- | --- |
| `sensor` | 数据来源：本地传感器 | 无 | 读数 30 分钟内且 `quality=ok` |
| `sensor_stale` | 数据来源：本地传感器 | 数据为 XX 小时前 | 读数在 24 小时内但超 30 分钟 |
| `weather` | 数据来源：公共天气 | 无（天气预报本身是区域值） | 传感器不可用，天气可用 |
| `none` | 暂无环境数据，判断基于你的描述 | 无 | 两者都不可用 |

`none` 的文案直接取自产品说明书 4.4.2 与 4.2.3 功能点 6 的原文（"界面必须明确标注当前没有环境数据，以下判断基于你描述的情况"）。文案不由 `environment_service` 硬编码拼接，而是从一处常量表读取。理由与"流程配置是唯一事实来源"同类：同一句话在环境看板（本项）、问诊的 `environmentNote`（T2-33）、提示快照的来源标注（T3-10）三处出现，硬编码在三处必然措辞分叉。

`sensor_stale` 与 `weather` 的差异要在文案上体现：前者是"本地实测但不新"，后者是"区域预报但非本地"。这两种数据对农户的意义不同，一句"数据来源：公共天气"和一句"数据为 3 小时前"回答的是不同的问题，不能合并。

### 三、"数据为 XX 小时前"的计算

```python
def _freshness_note(observed_at: datetime | None, source: str) -> str | None:
    """仅 sensor_stale 带时效标注；weather 不作时效标注。"""
    if source != "sensor_stale" or observed_at is None:
        return None
    hours = _age_hours(observed_at)
    if hours < 1:
        return "数据为 1 小时前"
    return f"数据为 {int(hours)} 小时前"
```

小时数向下取整并设下限 1：不足 1 小时显示"1 小时前"而不是"0 小时前"（后者语义上等于实时，与 `sensor_stale` 的定义矛盾）。超过 24 小时的读数不会走到这里（`collect_env_facts` 已降级到天气），因此小时数上限是 24。

`age_hours()` 的定义要放在 `tools/sensors.py` 与 T3-02 共用，不要在 `environment_service` 里重写。两处都算"距现在几小时"，重写就会引入时区处理不一致的风险。

### 四、与 T3-02 共用来源集合与新鲜度判据

这是本项最重要的约束。看板与提示快照必须看到同一份环境事实，否则同一条读数会在两个地方得出不同可信度结论：

| 消费者 | 用途 | 取用字段 | 数据来源 |
| --- | --- | --- | --- |
| 环境看板（本项） | 展示数值、单位、来源、更新时间 | `source` / `values` / `observed_at` / `staleness_note` | `collect_env_facts()` |
| 提示快照（T3-08） | 环境风险类提示的阈值判断 | `source` / `values` / `provenance` | `collect_env_facts()` |
| 问诊接口（T2-33） | `environmentNote` 必填场景判定 | `source` / `region_hit_level` | `collect_env_facts()` |

三处都调 `collect_env_facts()`，不各自取数。共用同一个函数带来两个可检验的后果：新鲜度窗口（30 分钟 / 24 小时）只有一处定义；`suspect` 读数的排除只有一处实现。若看板自己写一遍"查最新读数、判断时间"，就会在 T5-07 调整窗口时漏改，而漏改不报错，只让两处判断悄悄分叉。

```python
async def board(self, db: AsyncSession, user_id: str, plot_id: str | None = None) -> EnvironmentBoard:
    """环境看板：与提示快照、问诊共享同一份环境事实，避免可信度结论分叉。"""
    facts = await collect_env_facts(user_id, plot_id)
    metrics = [_to_board_metric(m, facts) for m in STANDARD_METRICS]
    badge = SourceBadge(
        source=facts.source,
        label=SOURCE_LABELS[facts.source],
        freshness_note=_freshness_note(facts.observed_at, facts.source),
        region_hit_level=facts.region_hit_level if facts.source == "weather" else None,
    )
    return EnvironmentBoard(metrics=metrics, source_badge=badge,
                            devices=await self._devices(db, user_id),
                            last_update_at=facts.observed_at)
```

### 五、地区回退级别的标注

天气服务按农户所在地区取数，若农户档案缺地区或地区无覆盖，天气服务会退回更大范围。回退的实际命中级要展示给农户：

| `region_hit_level` | 标注 |
| --- | --- |
| `county` | 无标注（精确命中） |
| `city` | 当前按 XX 市通用数据 |
| `province` | 当前按 XX 省通用数据 |
| `national` | 当前按全国通用数据 |

这与 T2-50 的地区回退匹配、T3-02 的 `region_hit_level` 字段一致。全局约定要求"每次回退都要在结果里记下实际命中的级别"，界面的"当前按 XX 市通用农时提示"是这条约定在环境数据侧的对应形态。

农事历按省级回退、环境按市级回退是正常的：两者查的是不同数据集，可用范围不同。看板只标注环境数据自己的命中级，不合并农事历的级别。

### 六、状态标注与旧接口兼容

每个指标旁给"正常/偏高/偏低"标注（产品说明书 4.4.3 功能点 4："农户需要的不是数据罗列，而是这些数字意味着什么"）。状态判据用与提示系统同一套阈值（`BROADCAST_TEMP_HIGH` / `BROADCAST_SOIL_DRY` / `BROADCAST_HUMIDITY_HIGH` / `BROADCAST_RAINFALL_MM`），从 `core/config.py` 读取而非另定义：

| 状态 | 文案 | 判据 |
| --- | --- | --- |
| `normal` | 正常 | 落在阈值区间内 |
| `high` | 偏高 | 超上限（如 `air_temp > BROADCAST_TEMP_HIGH`） |
| `low` | 偏低 | 低于下限（如 `soil_moisture < BROADCAST_SOIL_DRY`） |
| `unknown` | 未知 | 无读数或读数 `quality != ok` |

`suspect` 与 `stale` 的读数状态一律标 `unknown` 而不是按数值算状态：一条 30 小时前的 22°C 读数不能标"正常"，因为它不代表现在；一条超量程的 265°C 不能标"偏高"，因为它是坏数据不是高温。展示仍给原始数值（配合 `quality` 标记），但状态列不参与判断。这与 T3-02"suspect 等同于该级缺失"的口径一致。

旧接口的兼容处理：`GET /api/environment/summary` 与 `/detail` 的返回结构保持不变（调研报告 10.4："接口签名与返回结构保持不变，小程序侧 `environment.ts` 无需改动"），内部数据源改为 `collect_env_facts`，并新增 `sourceBadge` 字段供前端渐进采用。新看板接口用新路径 `/api/v1/environment/board`，避免破坏现有调用。

- `pytest backend/tests/api/test_environment_board.py` 全部通过，含四条来源用例：30 分钟内的 `ok` 读数返回 `source_badge.source == "sensor"` 且 `freshness_note is None`；3 小时前的读数返回 `source == "sensor_stale"` 且 `freshness_note == "数据为 3 小时前"`；无传感器但天气可用返回 `source == "weather"` 且 `freshness_note is None`；两者都不可用返回 `source == "none"` 且 `label` 含"暂无环境数据"。
