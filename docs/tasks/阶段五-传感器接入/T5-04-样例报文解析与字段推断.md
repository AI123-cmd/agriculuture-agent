# T5-04 样例报文解析与字段推断

## 这一项要做什么

实现三步接入的第二步：农户粘贴一条设备上报报文，后端解析出所有字段，并对每个字段推断它代表哪个标准环境指标，返回供农户确认或改选。这一步是"傻瓜化"的核心，决定了农户是否需要理解单位换算。

推断分两层：先匹配厂商模板（`vendorTemplateMatched` 为真时直接采用模板的 `field_spec`），匹配不到再走启发式——按字段名（`t1` / `temp` 映射温度、`h1` / `hum` 映射湿度）与按数值范围（0~50 且一位小数可能是温度、0~100 整数可能是湿度）。农户只需确认或改选，不需要理解单位换算。

## 前置依赖

- T5-03 提供的绑定结果 `deviceId`、`vendorTemplateMatched`、`templateId`；绑定未完成时本接口应拒绝。
- T5-02 提供的 `VendorTemplateRepository.match()` 与模板的 `field_spec` 结构。
- T5-01 提供的 `StandardMetric` 枚举与各指标合法区间（启发式的数值范围判据取自同一处，避免"推断用一套范围、校验用另一套"）。
- 外部环境：无。本项是纯函数为主，不依赖数据库以外的服务。
- 需要人工确认：各标准指标的中文标签与候选排序口径（面向农户的措辞，属全局约定"需要人工确认的三处"）。

## 实现要点

### 一、出入参按方案 13.4 原样采用

```python
class ParseSampleRequest(BaseModel):
    model_config = ConfigDict(extra="forbid")
    deviceId: str
    payload: str                              # 农户粘贴的样例报文


class ParseSampleResponse(BaseModel):
    parsed: bool
    fields: list[DetectedField]               # 系统解析出的字段
    inferError: str | None = None             # 解析失败时的友好提示


class DetectedField(BaseModel):
    rawField: str                             # "t1"
    sampleValue: str                          # "26.3"
    inferredMetric: str | None = None         # 系统推断（可能为空）
    candidates: list[str]                     # 可选项供农户点选
    confidence: float
```

`payload` 用 `str` 而不是 `dict`：农户从设备说明书或抓包工具里复制的是文本，允许带尾随换行、全角引号、单引号键这类常见脏字符。把它当字符串接收并在服务内清洗，比在 schema 层要求合法 JSON 更宽容，也更符合"农户粘贴"的实际形态。

`sampleValue` 是字符串而非数字：报文中可能有 `"26.3"`（带引号的数值）、`"ON"`（枚举）、`"1"`（布尔），统一按字符串展示，避免解析期就因类型不符而拒绝整条报文。数值化发生在推算换算参数时，不在展示层。

`inferredMetric` 可为空是必要的：报文里可能有 `"battery":3.7`、`"rssi":-71` 这类设备自身状态字段，它们不对应任何环境指标。给它们一个错误的推断比留空更糟，因为农户会照着点确认。此时 `candidates` 仍给出可选项（农户可选"忽略此字段"），但要放在末位。

### 二、MappingItem 的完整定义

方案 13.4 只给了 `MappingItem` 的三个字段（`rawField` / `standardMetric` / `unit`），但保存时需要 `scale_factor` / `offset_value` / `data_type` / `sample_raw` 才能让 `parse_payload` 完整工作（T5-01 的 `field_mapping` 列）。这三个字段不给农户填，由系统从模板或样例值反推，随确认结果一同提交：

```python
class MappingItem(BaseModel):
    rawField: str                             # 报文中的原始字段名
    standardMetric: str                       # StandardMetric 枚举值
    unit: str                                 # 标准单位，由后端正则，农户不可改
    scaleFactor: float = 1.0                  # 模板给出，或由样例值反推
    offsetValue: float = 0.0                  # 默认 0，模板可给出
    dataType: str = "float"                   # float / int / bool / str
    sampleRaw: str | None = None              # 样例报文中的原始片段
```

`unit` 与 `scaleFactor` 的取值不由前端决定：前端提交的 `standardMetric` 是农户的选择，`unit` 与 `scaleFactor` 由后端按指标与样例值匹配得出（T5-05 校验时强制覆盖）。这样农户即便改了请求体也改不动换算参数，避免"农户把温度单位改成 K 导致读数全错"这类问题。

### 三、第一层：厂商模板匹配

```python
async def parse_sample(db: AsyncSession, user_id: str, req: ParseSampleRequest) -> ParseSampleResponse:
    device = await device_repo.get(db, user_id, req.deviceId)
    if device is None:
        raise NotFoundError("设备不存在或无权访问")

    payload = _load_payload(req.payload)           # 容错解析，失败抛友好错误
    if payload is None:
        return ParseSampleResponse(parsed=False, fields=[],
                                   inferError="报文格式不正确，请粘贴一条完整的 JSON 报文")

    flat = flatten_payload(payload)                # {"data.air_temp": 26.5, ...}

    if device.vendor_template_id:
        tpl = await template_repo.get(db, device.vendor_template_id)
        if tpl and _template_covers(tpl, flat):
            return ParseSampleResponse(parsed=True, fields=_fields_from_template(tpl, flat))

    return ParseSampleResponse(parsed=True, fields=infer_fields(flat))
```

`_template_covers` 要求模板 `field_spec` 的键集合是报文扁平化后键集合的子集，否则视为"模板与实际报文不符"，退回启发式。这一步防止绑定设备时命中的模板与实际粘贴的报文不匹配（同一 SN 换了固件、或农户粘贴了另一台设备的报文）。模板命中时 `confidence` 直接给 1.0：模板是人工核实过的对应关系，不是猜测。

### 四、第二层：字段名启发式与数值范围启发式

```python
NAME_RULES: list[tuple[re.Pattern[str], StandardMetric, float]] = [
    (re.compile(r"^(t|temp|tem|t1|t2|airt|air_temp)$", re.I),     StandardMetric.AIR_TEMP,     0.7),
    (re.compile(r"^(h|hum|humi|h1|h2|rh|air_humi)$", re.I),       StandardMetric.AIR_HUMIDITY, 0.7),
    (re.compile(r"^(st|soilt|soil_temp|tt)$", re.I),              StandardMetric.SOIL_TEMP,    0.75),
    (re.compile(r"^(sm|soil|soil_moisture|vwc|wc)$", re.I),       StandardMetric.SOIL_MOISTURE,0.75),
    (re.compile(r"^(rain|rf|rainfall|precip)$", re.I),            StandardMetric.RAINFALL,     0.7),
    (re.compile(r"^(lux|light|lux1)$", re.I),                     StandardMetric.LIGHT_LUX,    0.7),
    (re.compile(r"^(ws|wind|wind_speed)$", re.I),                 StandardMetric.WIND_SPEED,   0.6),
    (re.compile(r"^(ph|soil_ph)$", re.I),                         StandardMetric.SOIL_PH,      0.7),
    (re.compile(r"^(ec|soil_ec)$", re.I),                         StandardMetric.SOIL_EC,      0.7),
]


def infer_fields(flat: dict[str, Any]) -> list[DetectedField]:
    """两层启发式：先字段名，再数值范围。农户只做确认或改选。"""
    out = []
    for raw_field, raw_value in flat.items():
        by_name = _match_by_name(raw_field)
        by_range = _match_by_range(raw_value)
        metric, confidence = _merge_hints(by_name, by_range)
        out.append(DetectedField(
            rawField=raw_field,
            sampleValue=str(raw_value),
            inferredMetric=metric.value if metric else None,
            candidates=_candidates(metric, by_name, by_range),
            confidence=confidence,
        ))
    return out
```

`_match_by_range` 的判据直接取 `StandardMetric` 的合法区间（T5-01 同一处定义）：

| 样例值形态 | 判据 | 推断结果 | 置信度 |
| --- | --- | --- | --- |
| 0~50 且一位小数（如 `26.3`） | 落在 `air_temp` / `soil_temp` 区间且非整数 | 温度（空气或土壤，二选一进候选） | 0.5 |
| 0~100 整数（如 `78`） | 落在 `air_humidity` / `soil_moisture` 区间且为整数 | 湿度或土壤水分 | 0.5 |
| 0~14 且两位小数（如 `6.6`） | 落在 `soil_ph` 区间 | 土壤 pH | 0.5 |
| 0~2000 且非整（如 `1.2`） | 落在 `soil_ec` 区间 | 土壤 EC | 0.4 |
| 0 或 1 或 `"ON"`/`"OFF"` | 布尔形态 | 不推断（可能是开关字段） | 0.2 |

`_merge_hints` 的合并规则：两层结论一致时置信度相加并截断到 0.95；两层结论不同时取字段名结论并把范围结论放进候选；只有一层有结论时取该层结论。字段名优先的理由是它表达的是设备厂商的意图（`t1` 就是温度），数值范围只是旁证——`78` 既可能是空气湿度也可能是土壤水分，只有字段名能区分。

置信度不乘任何模型分数，全部来自规则。这符合全局约定"凡是能被规则判定的，不交给模型"：字段推断完全没有必要引入模型调用，纯规则确定性更高、延迟更低、可单测。

### 五、农户只确认或改选

推断结果的呈现约定：`inferredMetric` 是系统的推荐（下拉框的默认项），`candidates` 是全部可选项（按推荐度排序）。农户的操作只有两种：接受默认或改选。这条约束的落地是：

第一，`candidates` 必须包含 `inferredMetric`，且排第一位。前端不必做"默认项是否在候选里"的判断。

第二，候选里附一个"忽略此字段"选项，对应设备状态类字段。它排在最后，不进 `standardMetric` 枚举，保存时该字段被跳过。

第三，界面要展示的换算结果由后端算好返回，不让前端做单位换算。`DetectedField.sampleValue` 是原始值，前端若要展示"26.3°C"需要换算后的值，这个值随 `MappingItem.scaleFactor` 一起给出（T5-05 的预览接口），前端只做拼接不做运算。

产品说明书 4.4.3 功能点 1 的原话是"全程不需要农户理解协议、寄存器、字节序或单位换算"。这条要求有可检验的形态：农户在整个流程里看不到 `scale_factor`、`offset`、`byte_order` 任何一项，也看不到单位下拉框。

### 六、解析容错与友好提示

粘贴的报文常见三类问题，都要有针对性提示，且都不能抛 5xx：

| 问题 | `inferError` 文案 |
| --- | --- |
| 不是合法 JSON | "报文格式不正确，请粘贴一条完整的 JSON 报文" |
| 是 JSON 但没有可映射字段 | "报文里没有找到可以识别的数据字段，请检查是否粘贴了完整内容" |
| 字段全是设备状态类 | "只识别到设备状态字段，请确认粘贴的是环境数据报文" |

`_load_payload` 的容错包括：剥离 BOM 与首尾空白、把全角引号 `“”‘’` 转半角、单引号键名转双引号、去掉尾随逗号。这些是农户从聊天窗口或文档里复制时的实际形态，不做清洗会让"明明是正确报文"的粘贴失败。容错只在解析层做，不影响后续存储——存进 `sample_raw` 的是清洗后的标准 JSON。

## 验收标准

- `pytest backend/tests/services/test_field_inference.py` 全部通过，含以下用例：字段名 `t1` / `temp` / `air_temp` 均推断为 `air_temp`；`h1` / `hum` 均推断为 `air_humidity`；样例值 `26.3`（0~50 一位小数）的候选含 `air_temp` 与 `soil_temp`；样例值 `78`（0~100 整数）的候选含 `air_humidity` 与 `soil_moisture`；样例值 `6.6` 推断为 `soil_ph`；`battery=3.7` 的 `inferredMetric is None` 且候选末位为忽略项。
- 模板命中用例：构造一条与 `tpl_generic_http` 结构一致且字段被模板覆盖的报文，断言所有字段 `confidence == 1.0` 且 `inferredMetric` 与模板 `field_spec` 完全一致。
- 模板不覆盖用例：设备有 `vendor_template_id` 但报文扁平化键集合不是模板键集合的子集时，断言退回启发式（`confidence < 1.0`）。
- `POST /api/v1/device/parse-sample` 对以下输入返回 200 且 `parsed=false`，`inferError` 非空：`"{不是json"`、`"[]"`、`"{\"ip\":\"1.2.3.4\",\"rssi\":-71}"`。
- 粘贴带全角引号或尾随逗号的报文（如 `{“air_temp”: 26.5,}`）返回 `parsed=true`，字段被正确识别。
- 断言候选列表中 `candidates[0] == inferredMetric`（当 `inferredMetric` 非空时）；`grep -c "StandardMetric" backend/app/services/field_inference.py` 大于 0（范围判据取自枚举而非另写常量）。
- `ruff check backend/app`、`ruff format --check backend/app`、`mypy backend/app` 三条命令均返回 0。
