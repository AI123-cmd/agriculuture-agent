# T2-06 流程红线配置模型与完整性校验

## 这一项要做什么

在 `app/process_config/redlines.py` 中定义红线的领域模型与完整性校验器，把 T2-02 里作为引用外壳的 `RedlineSpec` 展开为可被闸门直接消费的结构。校验器要回答三个问题：这条红线引用的闸门规则是否真实存在、红线声明的 `data` 载荷是否符合该规则的期望结构、七条流程的红线是否在启动时全部齐备。 技术方案 8.4 明确"红线缺失即不可用"。本项是这条规则的判定者，它产出一个"可用性清单"交给 T2-05 的注册表与 T2-24 的路由函数；任何一条流程的红线不完整，该流程在路由表中被标记不可用，入口处直接返回转人工引导。

## 前置依赖

- 依赖 T2-03：必须已提供 `ConfigIntegrityError` 与加载器；依赖 T2-02：必须已提供 `RedlineSpec`、`ProcessConfig`、`ViolationSeverity`
- 依赖 T2-01：必须已提供 `ProcessId`、`ViolationSeverity`；外部条件：红线措辞需农技与产品共同确认（见全局约定第八节），确认前按 `# TODO(红线措辞待确认)` 标注
- 与闸门的关系：本项只产出结构化的红线对象，规则的执行在 T2-42 与 T2-43

## 实现要点

### 闸门规则 id 常量表

```python
# app/process_config/rule_ids.py

class GateRuleId(str, Enum):
    WHITELIST = "R-WHITELIST"
    REGISTERED_CROP = "R-REGISTERED-CROP"
    DOSAGE = "R-DOSAGE"
    INTERVAL = "R-INTERVAL"
    MAX_USE = "R-MAX-USE"
    CONFLICT = "R-CONFLICT"
    REGION = "R-REGION"
    PROVENANCE = "R-PROVENANCE"
    REDLINE = "R-REDLINE"
    REDLINE_LOAD = "R-REDLINE-LOAD"
    CAUTION = "R-CAUTION"
    NO_DATA = "R-NO-DATA"
# 每条规则对该规则专属 data 载荷的期望键名（None 表示该规则不接受 data）
RULE_PAYLOAD_SPEC: dict[GateRuleId, set[str] | None] = {
    GateRuleId.REDLINE: {"forbidden", "forbidden_phrases", "reference", "labels", "min_days", "notice"},
    GateRuleId.REGION: {"regions", "standards"},
    GateRuleId.INTERVAL: {"min_days", "by_pesticide"},
    GateRuleId.MAX_USE: {"limit"},
    GateRuleId.DOSAGE: {"unit", "min", "max"},
    GateRuleId.REGISTERED_CROP: None,
    GateRuleId.WHITELIST: None,
    GateRuleId.CONFLICT: None,
    GateRuleId.PROVENANCE: None,
    GateRuleId.REDLINE_LOAD: None,
    GateRuleId.CAUTION: None,
    GateRuleId.NO_DATA: None,
}
```

规则 id 与 8.2 的规则清单逐条对应，用枚举而不是散字符串，让"配置里写了一个不存在的规则 id"在加载阶段就能被抓到。`RULE_PAYLOAD_SPEC` 只声明键名的合法集合，不校验证的取值，因为取值的正确性属于农技内容，由人工确认。

### 红线领域模型

```python
class Redline(BaseModel):
    """一条展开后的红线，闸门可直接消费。"""
    model_config = ConfigDict(extra="forbid", frozen=True)
    id: str
    desc: str
    rule_ids: tuple[GateRuleId, ...]        # rule 字段按逗号拆分后的结果
    severity: ViolationSeverity
    payload: dict[str, Any] = {}
    @property
    def is_blocking(self) -> bool:
        return self.severity is ViolationSeverity.BLOCK
    def labels(self) -> list[str]:
        """命中即拦截的文本清单（禁用词与禁用短语的并集）。"""
        return list(self.payload.get("forbidden", [])) + list(self.payload.get("forbidden_phrases", []))
```

`rule_ids` 是元组而不是列表，因为红线对象要放进 `frozen=True` 的配置里，元组可哈希、可安全共享。`labels()` 把 `forbidden`（禁用品种）与 `forbidden_phrases`（禁用短语）统一暴露，供 T2-42 的 `R-REDLINE` 规则做一次文本包含扫描。

### 加载结果对象

```python
class LoadedRedlines(BaseModel):
    """一条流程的红线加载结果，是 GateResult.process_redlines_loaded 的数据源。"""
    model_config = ConfigDict(extra="forbid", frozen=True)
    process_id: ProcessId
    version: int
    redlines: tuple[Redline, ...]
    loaded: bool
    unavailable_reason: str | None = None
    @classmethod
    def unavailable(cls, process_id: ProcessId, version: int, reason: str) -> "LoadedRedlines":
        return cls(process_id=process_id, version=version, redlines=(), loaded=False, unavailable_reason=reason)
    def blocking_labels(self) -> list[str]:
        out: list[str] = []
        for item in self.redlines:
            if item.is_blocking:
                out.extend(item.labels())
        return out
    def declared_rule_ids(self) -> list[str]:
        return sorted({r.value for item in self.redlines for r in item.rule_ids})
```

`loaded` 是布尔而不是"红线列表非空"的隐式判断。理由是：一条流程可能配置了红线但其结构不合法，此时列表非空但本质不可用；显式布尔能让 T2-12 的 `process_redlines_loaded` 字段有明确来源。 `unavailable` 类方法让"不可用"成为一种可构造的正常结果，而不是靠 `None` 表达。这样闸门侧无须判空，只判 `loaded`。

### 完整性校验器

```python
class RedlineValidator:
    """红线完整性校验。启动时对七条流程各跑一次。"""
    def validate(self, config: ProcessConfig) -> LoadedRedlines:
        problems: list[str] = []
        parsed: list[Redline] = []
        seen_ids: set[str] = set()
        if not config.redlines:
            return LoadedRedlines.unavailable(config.process_id, config.version, "redlines 为空")
        for spec in config.redlines:
            if spec.id in seen_ids:
                problems.append(f"红线 id 重复: {spec.id}")
                continue
            seen_ids.add(spec.id)
            rule_ids: list[GateRuleId] = []
            for raw in spec.rule.split(","):
                token = raw.strip()
                if not token:
                    problems.append(f"{spec.id} 的 rule 字段含空项")
                    continue
                try:
                    rule_ids.append(GateRuleId(token))
                except ValueError:
                    problems.append(f"{spec.id} 引用了不存在的规则 {token!r}")
            payload_keys = set(spec.data)
            for rid in rule_ids:
                allowed = RULE_PAYLOAD_SPEC.get(rid)
                if allowed is None and payload_keys:
                    problems.append(f"{spec.id} 的规则 {rid.value} 不接受 data，但配置了 {sorted(payload_keys)}")
                elif allowed is not None and payload_keys and not payload_keys <= allowed:
                    problems.append(
                        f"{spec.id} 的 data 键 {sorted(payload_keys - allowed)} 不在 {rid.value} 的允许集合内"
                    )
            if not rule_ids:
                continue
            parsed.append(Redline(
                id=spec.id, desc=spec.desc, rule_ids=tuple(rule_ids),
                severity=spec.severity, payload=spec.data,
            ))
        if problems:
            return LoadedRedlines.unavailable(config.process_id, config.version, "; ".join(problems))
        return LoadedRedlines(process_id=config.process_id, version=config.version,
                              redlines=tuple(parsed), loaded=True)
```

校验器返回结果而不抛异常，因为它要被两处调用：启动时汇总七条流程的可用性清单，以及闸门运行时判断 `process_redlines_loaded`。抛异常的形态会让调用方不得不写 `try`，而 `try` 里又必须处理所有异常，容易掩盖真正的问题。

### 不可用流程的处置

```python
def build_availability(validator: RedlineValidator, configs: dict[ProcessId, ProcessConfig]) -> dict[ProcessId, LoadedRedlines]:
    """产出七条流程的红线可用性清单，缺项一律标记不可用（不静默跳过）。"""
    manifest: dict[ProcessId, LoadedRedlines] = {}
    for pid in ProcessId:
        config = configs.get(pid)
        if config is None:
            manifest[pid] = LoadedRedlines.unavailable(pid, 0, "配置未加载")
            continue
        manifest[pid] = validator.validate(config)
    return manifest
```

对七条流程遍历而不是只遍历已加载的，缺项的流程要显式出现在清单里并标记不可用。若只遍历已加载的，一条流程"因为配置文件被删掉"而消失时会没有任何记录。 清单的消费方有两个：路由层（T2-24 的 `route_after_triage` 在进入流程前查清单，不可用则指向 `handoff`）与启动自检（T1-08 汇总后写健康检查）。两处都不接受"红线不可用但继续按通用规则跑"，这正是产品说明书 9.3 所禁止的。

### 与闸门的对接约定

闸门拿到 `LoadedRedlines` 后：
- 若 `loaded` 为 False，`R-REDLINE-LOAD` 判定违规，`GateResult.decision = block`，`process_redlines_loaded = False`
- 若 `loaded` 为 True，`R-REDLINE` 用 `blocking_labels()` 扫描处方文本与 `detail_terms` 的改写结果
- 校验通过后，`checked_rules` 必须覆盖 `declared_rule_ids()`，未覆盖的写审计告警

第三条是"声明了但没执行"的反查依据，对应技术方案 8.5 的第三条复盘用途。
