# T2-10 问诊与证据契约

## 这一项要做什么

在 `app/agent/contracts/interview.py` 与 `app/agent/contracts/evidence.py` 中定义问诊智能体与证据核查智能体的输出契约，即 `InterviewQuestion`、`InterviewBatch`、`EvidenceItem`（契约版）与 `EvidenceSet`。

问诊契约承载产品说明书 4.2.2 的五条关键设计规则：每轮不超过 2 问、必须解释为什么问、不得重复问已知项、每步要有进度提示、未知是合法答案。这些规则中有一部分由契约的字段约束直接执行（长度上限、`why` 必填），另一部分由代码在生成前过滤实现（不重复问已知项），二者必须分清，不能都指望模型自律。

## 前置依赖

- 依赖 T2-08：必须已提供 `ConsultationState`、`SlotValue`、`EvidenceItem`（state 侧序列化形态）
- 依赖 T2-02：必须已提供 `SlotSpec`，`slot_key` 的取值须来自流程配置
- 依赖 T2-01：必须已提供 `AnswerType`
- 与 T2-17 的关系：候选池筛选器在契约之外先跑，本项契约只负责模型产出的形态约束
- 与 T2-18 的关系：`EvidenceSet` 是证据核查智能体的输出，检索实现由 T2-18 与 T2-49 提供

## 实现要点

### InterviewQuestion

```python
class InterviewQuestion(BaseModel):
    """单个追问。技术方案 5.3.3 原样定义。"""
    model_config = ConfigDict(extra="forbid")

    slot_key: str
    text: str
    why: str
    options: list[str] | None = None
    answer_type: Literal["single", "multi", "text", "photo", "number"]

    @field_validator("text", "why")
    @classmethod
    def _non_blank(cls, v: str) -> str:
        if not v.strip():
            raise ValueError("不得为空")
        return v.strip()

    @model_validator(mode="after")
    def _options_match_answer_type(self) -> "InterviewQuestion":
        if self.answer_type in ("single", "multi") and not self.options:
            raise ValueError("single/multi 类型必须给出选项")
        return self
```

`why` 必填且非空，对应产品说明书 4.2.2 的"必须解释为什么问"。校验失败时的处置在 T2-13 的基类里：重试一次，仍失败则降级为模板问题（模板里 `why` 已写好）。

`options` 与 `answer_type` 的一致性校验拦的是"选了单选却没给选项"这类会让前端无法渲染的问题。单选与多选的选项列表必须固定包含一个跳过项（如"说不清"），由 `InterviewBatch` 的校验器统一检查，避免每个智能体各自记得加。

### InterviewBatch

```python
class InterviewBatch(BaseModel):
    """一轮追问的完整输出。硬校验：1 至 2 问。"""
    model_config = ConfigDict(extra="forbid")

    questions: list[InterviewQuestion]
    stage_hint: str
    confidence_note: str | None = None

    @field_validator("questions")
    @classmethod
    def _max_two(cls, v: list[InterviewQuestion]) -> list[InterviewQuestion]:
        if len(v) > 2:
            return v[:2]          # 裁剪至 2，而不是抛错
        return v

    @model_validator(mode="after")
    def _at_least_one(self) -> "InterviewBatch":
        if not self.questions:
            raise ValueError("一轮至少一个问题，无问题时应进入下一环节")
        return self

    @model_validator(mode="after")
    def _no_duplicate_slot(self) -> "InterviewBatch":
        keys = [q.slot_key for q in self.questions]
        if len(set(keys)) != len(keys):
            raise ValueError("同一轮不得重复询问同一槽位")
        return self

    @model_validator(mode="after")
    def _skip_option_present(self) -> "InterviewBatch":
        for q in self.questions:
            if q.answer_type in ("single", "multi") and q.options:
                if not any(SKIP_MARKERS & {opt} for opt in q.options):
                    q.options.append("说不清")
        return self
```

三个校验器的策略各不相同，这是刻意的：

- `_max_two` 裁剪而不是抛错。技术方案 5.3.3 的对照表里写"校验失败，裁剪至 2"，因为多问一个问题的代价有限，不值得为此让整轮重试。
- `_at_least_one` 抛错。零问题意味着契约违约（该智能体本该转其他节点），静默通过会让主图空转一轮。
- `_no_duplicate_slot` 抛错。同一轮问两次同一槽位是明显的生成异常。
- `_skip_option_present` 兜底补一个跳过项。技术方案 5.3.3 要求"options 固定包含跳过项"，用户跳过即写 `status="unknown"`。补位而不是抛错，因为漏加跳过项属于机械遗漏，补上即可，不影响语义。

```python
SKIP_MARKERS = {"说不清", "不清楚", "不知道", "跳过", "不好说"}
```

`stage_hint` 必填，且由代码按轮次计算，不由模型生成。合同层面只要求它非空，具体文案如"正在了解情况 2/3"由 T2-16 的问诊智能体按 `round` 与预算计算后填入。

`confidence_note` 是数据缺失时的显式标注，例如"暂无传感器数据，判断基于你的描述"。它与 `ObservationResult.note` 有重叠但用途不同：前者面向农户的当前轮次，后者面向环境事实的说明。

### 问诊契约不负责的部分

以下两件事**不在契约里做**，必须由 T2-17 的候选池筛选器在调用模型之前完成：
- 剔除 `slots` 中已是 `filled` 的槽位
- 剔除可由档案或环境直接读取的项

原因是这两件事需要读全量 `slots` 与流程配置，属于全局判断，而契约只是模型输出的容器。若把过滤放在契约校验里，模型会先浪费一次调用生成已被过滤的问题，再被丢弃。

### EvidenceQuery

```python
class EvidenceQuery(BaseModel):
    """检索请求。process_id 为硬过滤条件，不是软排序。"""
    model_config = ConfigDict(extra="forbid")

    process_id: ProcessId
    keywords: list[str]
    region_code: str | None = None
    slot_snapshot: dict[str, str] = {}
    kind_filter: list[Literal["pest", "disease", "pesticide", "cultivation", "threshold"]] = []
    top_k: int = 8
```

`process_id` 是硬过滤字段，技术方案 9.3 明确"术语与判据不能跨流程混用"。若只做软排序，茶流程的查询仍可能召回辣椒的药剂条目，而后续重排序未必能纠正。硬过滤从候选集层面消除这个风险。

### EvidenceSet

```python
class EvidenceSet(BaseModel):
    """证据核查输出。命中为空时必须显式标注。"""
    model_config = ConfigDict(extra="forbid")

    query: EvidenceQuery
    items: list[EvidenceItem] = []
    hit: bool
    region_level_actual: Literal["county", "city", "province", "national", "none"]
    reranked: bool = False
    unmatched_reason: str | None = None
    fallback_chain: list[str] = []

    @model_validator(mode="after")
    def _miss_requires_reason(self) -> "EvidenceSet":
        if not self.hit and not self.unmatched_reason:
            raise ValueError("未命中时必须给出 unmatched_reason")
        return self

    @model_validator(mode="after")
    def _all_items_same_process(self) -> "EvidenceSet":
        bad = [i.knowledge_id for i in self.items if i.process_id != self.query.process_id.value]
        if bad:
            raise ValueError(f"证据跨流程: {bad}")
        return self
```

第二条校验器是 `process_id` 硬过滤的自检：即使检索实现有疏漏，契约层也会在下游之前拦住跨流程证据。这类"双保险"在安全相关路径上值得多写几行。

`region_level_actual` 记录实际命中的行政级别，取值来自地区回退链的终点。检索侧的回退顺序为县级、市级、省级、全国通用（T2-50 实现），本项只保存结果。`fallback_chain` 记录完整的尝试路径（如 `["county:330100", "city:330000", "province:330000"]`），供界面对照与线上排查。

### 知识库空结果的处置

技术方案 5.1 规定证据核查失败时"返回空集并标注未命中"。因此 `hit=False` 是合法输出，但必须带 `unmatched_reason`。下游的判定智能体拿到空集时应降低确定性表述并给出观察建议，而不是编造证据。这条约束在 T2-18 实现，本项只保证契约能表达这个状态。
