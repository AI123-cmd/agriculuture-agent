# T2-27 一期五条流程子图

## 这一项要做什么

交付水稻、茶、辣椒、杂草、养猪五条一期流程的子图文件，路径为 `app/agent/graph/subgraphs/{rice,tea,chili,weed,pig}.py`。五个文件形态完全同构（见方案 7.4 的 `build_tea_subgraph` 原文），差异全部来自各自的 `ProcessConfig`，因此每个文件都很薄。本项同时建立 `SUBGRAPH_BUILDERS` 注册表，作为主图（T2-25）分发流程的唯一入口。养猪子图在本项只建出标准骨架，其报告守卫的结构特例在 T2-28 单独处理，本项不越权改通用节点。

## 前置依赖

- T2-26 流程子图工厂函数：提供 `get_config` 与五个节点工厂、`make_panel_node`。
- T2-04 七条流程 YAML 配置编写：五条一期流程的 YAML 必须已存在且能通过加载器校验。
- T2-24 条件边函数 routes：提供 `route_after_interview` / `route_after_judge` / `route_after_verify` 与对应 path_map。
- T2-22 报告守卫 ReportGuard：养猪子图需要能调用守卫节点（具体插桩点见 T2-28）。
- 外部环境：模型网关 `USE_MOCK_LLM=true`；知识库可检；无数据库直连。

### 子图骨架（rice.py / tea.py / chili.py / weed.py 同构）

以茶为例，其余四个文件只改 `ProcessId`。方案 7.4 的原文骨架缺 `observe` 与 `report_guard` 的衔接，本项按 T2-25 约定的三条边补齐。

```python
"""茶流程子图：结构与其他流程相同，差异全部来自 ProcessConfig。"""
from langgraph.graph import END, StateGraph

from app.agent.graph.factories import (
    get_config,
    make_interview_node,
    make_judge_node,
    make_observe_node,
    make_panel_node,
    make_prescribe_node,
    make_verify_node,
)
from app.agent.graph.routes import (
    ROUTE_AFTER_INTERVIEW,
    ROUTE_AFTER_JUDGE,
    ROUTE_AFTER_OBSERVE,
    route_after_interview,
    route_after_judge,
    route_after_observe,
)
from app.agent.state import ConsultationState, ProcessId


def build_tea_subgraph():
    """茶流程子图：observe → interview →(panel)→ verify → judge → prescribe。"""
    config = get_config(ProcessId.TEA)
    graph = StateGraph(ConsultationState)

    graph.add_node("observe", make_observe_node(config))
    graph.add_node("interview", make_interview_node(config))
    graph.add_node("verify", make_verify_node(config))
    graph.add_node("judge", make_judge_node(config))
    graph.add_node("prescribe", make_prescribe_node(config))

    panel = make_panel_node(config)      # 茶 panel_enabled=true
    if panel is not None:
        graph.add_node("panel", panel)

    # observe 之后交给主图的报告守卫兜底检查，守卫通过再回 interview
    graph.add_conditional_edges("observe", route_after_observe, ROUTE_AFTER_OBSERVE)

    graph.add_conditional_edges("interview", route_after_interview, ROUTE_AFTER_INTERVIEW)
    if panel is not None:
        graph.add_edge("panel", "verify")
    graph.add_edge("verify", "judge")
    graph.add_conditional_edges("judge", route_after_judge, ROUTE_AFTER_JUDGE)
    graph.add_edge("prescribe", END)
    return graph
```

辣椒与杂草文件与茶一致（三者 `panel_enabled=true`）。水稻文件去掉 panel 相关四行（`panel_enabled=false`），其余不变。

### 并行会诊的接线

`ROUTE_AFTER_INTERVIEW` 的 `panel` 分支只在 `panel_enabled=true` 的流程上有对应节点。水稻子图不注册 `panel` 节点，因此水稻的 `route_after_interview` 永远不会返回 `panel`——这是由 routes 内部读 `process_id in PANEL_ENABLED_PROCESSES` 与 state 上的 `panel_needed` 共同保证的，不是靠子图自觉。三条启用流程的 `panel → verify` 用普通边，聚合器产出的 `PanelAggregate` 直接写进 state 的 `panel_aggregate`，供 `judge` 读取。

### 猪流程骨架与本项的停止边界

本项只为猪流程建标准骨架（`observe → interview → verify → judge → prescribe`），并**不**实现报告守卫插桩。守卫插桩是结构特例，处理方式、节点位置与输出优先级由 T2-28 决定。本项交付的 `pig.py` 只保证：能被导入、能在 `SUBGRAPH_BUILDERS` 中注册、能在 mock 模式下跑通一条无信号命中的路径。

### 术语与指标

子图本身不涉及术语替换——`display_metrics` 与 `colloquial_map` 由提示词组织（T2-60）与展示层消费，子图只做控制流。子图也不做条件判断，全部判断在 `routes.py`，这是"编排与业务分离"的边界。
