## 实现要点

### 两条子图的形态

两条子图与一期五条在控制流上完全同构（含 `observe` 之后的兜底守卫 `report_guard`），差异仍全部来自配置。油菜子图不注册 `panel`（`panel_enabled=false`），通用子图同样不注册。

```python
"""油菜流程子图：占位实现，L3 处置知识检索关闭，禁止输出药剂推荐。"""
from langgraph.graph import END, StateGraph

from app.agent.agents.report_guard import build_report_guard_node
from app.agent.graph.factories import (
    get_config,
    make_interview_node,
    make_judge_node,
    make_observe_node,
    make_prescribe_node,
    make_verify_node,
)
from app.agent.graph.routes import (
    ROUTE_AFTER_INTERVIEW,
    ROUTE_AFTER_JUDGE,
    ROUTE_AFTER_SUBGRAPH_GUARD,
    route_after_interview,
    route_after_judge,
    route_after_subgraph_guard,
)
from app.agent.state import ConsultationState, ProcessId


def build_rapeseed_subgraph():
    """油菜子图：结构同构，处置知识与药剂输出由配置与闸门双重关闭。"""
    config = get_config(ProcessId.RAPESEED)     # knowledge_l3_enabled=false
    graph = StateGraph(ConsultationState)

    graph.add_node("observe", make_observe_node(config))
    graph.add_node("report_guard", build_report_guard_node(config))
    graph.add_node("interview", make_interview_node(config))
    graph.add_node("verify", make_verify_node(config))
    graph.add_node("judge", make_judge_node(config))
    graph.add_node("prescribe", make_prescribe_node(config))

    graph.add_edge("observe", "report_guard")
    graph.add_conditional_edges("report_guard", route_after_subgraph_guard, ROUTE_AFTER_SUBGRAPH_GUARD)
    graph.add_conditional_edges("interview", route_after_interview, ROUTE_AFTER_INTERVIEW)
    graph.add_edge("verify", "judge")
    graph.add_conditional_edges("judge", route_after_judge, ROUTE_AFTER_JUDGE)
    graph.add_edge("prescribe", END)
    return graph
```

通用子图逐行相同，只把 `ProcessId.RAPESEED` 换成 `ProcessId.GENERAL`。

### 油菜流程的占位方式

占位不是"少写几行代码"，而是三条相互独立的约束同时生效，任何一条单独存在都不够。

| 约束 | 落点 | 作用 |
| --- | --- | --- |
| `RAPE-01: 禁止输出药剂推荐` | `rapeseed.yaml` 的 `redlines` | 由闸门 `R-REDLINE` 规则在输出前拦截任何药剂推荐类内容 |
| L3 处置知识检索开关 `disabled` | `rapeseed.yaml` 的知识检索配置 | `verify` 与 `prescribe` 节点不再检出油菜药剂条目，`pesticide_items` 恒为空 |
| 输出定位为鉴别与农事 | `output_template` 与 `role_definition` | 只讲病害识别、菌核病防治窗口、后茬关系等非用药内容 |

`RAPE-01` 之所以必须与检索开关并存：检索开关防的是"正常路径检不出药剂"，红线规则防的是"知识库误入药剂条目或模型自行编造药剂名"。方案 9.5 的原文即为此意——"这样即使知识库中误入了油菜药剂条目，闸门也会拦截"。两条约束叠加后，油菜流程在闸门处可能出现的 `decision` 只应为 `allow`（未涉用药）或 `block`（意外检出禁项），`degrade` 在补齐调研前不应出现。

油菜流程的合同条款还有一条隐含要求：`requires_tech_station` 在涉及病虫害防治时置 `True`，输出引导农户咨询当地农技站，而不是给出"再等等看"这类模糊答复。

### A7 未答复前的处理

产品说明书附录 A7 的油菜流程调研排期未定，因此本项只交付占位子图，不预置任何油菜专属阈值（`L4`）与药剂条目（`L3`）。若后续调研给出排期，补齐工作是"补 YAML 的知识条目 + 打开检索开关 + 复核 `RAPE-01` 是否保留"，本项代码无需回改。**不得**因"体验上像缺了功能"而临时放开药剂输出，这条属于全局约定第八节列出的"农技专业内容"，需停下确认。

### 通用农业流程的兜底定位

通用流程是分诊降级的目标（`TriageResult.fallback_reason` 非空时落到此处），它的定位是"能给出可用的通用农事建议，但不承担任何专属判断"。

| 字段 | 取值 | 含义 |
| --- | --- | --- |
| `calendar_source` | `null` | 不建农事历，接入 `NO_CALENDAR_PROCESSES` 集合 |
| `required_slots` | 通用几条（对象、症状、时间） | 不做流程专属必问 |
| `timing_rules` | 空列表 | 不适用天数窗口或采摘倒推 |
| `redlines` | 仅通用红线（不发布病虫害预报等） | 无流程专属禁用清单 |
| `confusable_items` | 空列表 | 不做显式排除（`excluded` 允许为空） |
| `panel_enabled` | `false` | 不启用并行会诊 |

`NO_CALENDAR_PROCESSES` 在方案中以 `{ProcessId.WEED, ProcessId.GENERAL}` 的形式出现，本项需确认通用流程确实包含在内，且 `calendar_source` 为 `None` 时不触发任何农事历相关查询（提示快照链路 T3-03 会读这个字段做分支）。

通用流程的知识库条目只有通用农事知识，没有专属阈值与药剂条目。因此它的 `pesticide_items` 恒为空、`requires_tech_station` 在涉及用药时置 `True`。这与油菜流程的占位是同一种保守姿态，区别是通用流程并非"待补齐"，而是**设计上就如此**——它的价值在于不让农户在档案缺失、对象不明时被直接推开。

### 分诊降级到通用流程的可观察性

`TriageResult` 的 `fallback_reason` 必须非空，且进入通用流程时在 state 上记下 `process_id = ProcessId.GENERAL` 与降级原因，供接口层在 `reply` 或 `stageLabel` 里说明"当前按通用农业建议作答"。这条不做，农户会误以为系统识别了他的作物。
