# T2-33 问诊接口改造为图驱动

## 这一项要做什么

把 `app/services/ai_service.py` 的 `chat` 与 `app/api/v1/ai.py` 的 `/ai/chat` 从"喂一次 state、取一次 `reply` 文本"改造成完整的图驱动接口：入参用技术方案 13.2 的 `ChatRequest`，出参用 `ChatResponse`（含 `stage`、`progress`、`questions`、`prescription`、`environmentNote`、`handoff`、`quotaPrompt`、`degraded`），并在入口处判断新会话还是中断恢复。现有实现只返回 `sessionId / reply / relatedSuggestions / tagsAdded` 四个字段，且直接透传 `db` 进 config、用 `req.sessionId` 当 `thread_id`，本项整体替换。核心约束有两条：**转人工用 200 + `handoff` 字段表达，不用错误码**；**`environmentNote` 在 `env_source ∈ {none, sensor_stale}` 时必填**。

## 前置依赖

- T2-25 主图组装 main：`build_graph()` 与图节点产出的 state 字段名。
- T2-32 人工介入与断点续问：提供 `resume_graph` 与"新会话 / 中断 / 已结束"的三分支判断依赖的 `aget_state().next`。
- T2-08 ConsultationState 与 ConsultStage：`ConsultStage` 枚举与 `stage` 字段；`SlotValue` 结构。
- T2-10 问诊与证据契约：`InterviewBatch` / `InterviewQuestion`（有 `why`、`options`、`answer_type`）。
- T2-11 判定与处方契约：`Prescription`（含 `facts_provenance`、`pesticide_items`）。
- T2-30 Postgres 检查点器：`session_id` 作 `thread_id` 持久化。
- T2-31 轮次与成本预算守卫：`degraded` 字段来源。
- T2-05 流程配置版本化：`stageLabel` 的口语化文案来自流程配置。
- T1-05 OwnedRepository / T1-11 历史列表优化：落库与历史查询改走 repository。
- 外部环境：PostgreSQL 可连；`env_source` 由环境事实三级回退采集（T3-02）写入，本项只读。

## 实现要点

### ChatRequest 完整定义

```python
"""问诊接口出入参：对齐技术方案 13.2。"""
from __future__ import annotations

from typing import Literal

from pydantic import BaseModel, Field

from app.agent.state import ConsultStage


class SlotAnswer(BaseModel):
    slotKey: str
    value: str
    status: Literal["filled", "unknown"] = "filled"


class ChatRequest(BaseModel):
    sessionId: str | None = None              # 为空表示新会话
    farmEntryId: str | None = None            # 问诊对象（多地块场景，见 6.3）
    message: str | None = None                # 文字输入
    imageUrl: str | None = None               # 图片输入
    voiceUrl: str | None = None               # 语音输入（转写后）
    processHint: str | None = None            # 入口直达（如杂草防治按钮）
    answers: list[SlotAnswer] | None = None   # 结构化快捷选项回答
```

`processHint` 是"受理即分流"的入口直达通道：小程序上的"杂草防治"按钮直接带 `processHint="weed"`，`intake` 节点据此锁定流程、跳过 triage 的提问，这是 T2-25 里 `process_locked` 的来源。`farmEntryId` 在多地块场景下作为 `farm_plot_id` 的来源，槽位键加地块前缀（见方案 6.3）。

### ChatResponse 完整定义

```python
class ProgressInfo(BaseModel):
    current: int
    total: int


class QuestionView(BaseModel):
    slotKey: str
    text: str                                 # 面向农户的口语化问题
    why: str                                  # 为什么问（必填，来自契约）
    options: list[str] | None = None          # 快捷选项（含跳过项）
    answerType: Literal["single", "multi", "text", "photo", "number"]
    allowUnknown: bool = True                 # "未知"是合法答案


class PrescriptionView(BaseModel):
    diagnosisSummary: str
    actions: list[PrescriptionActionView]
    safetyIntervalDays: int | None = None
    maxUsesPerSeason: int | None = None
    pesticideItems: list[PesticideItemView] = []
    followupPlan: FollowupPlanView
    requiresTechStation: bool = False
    detailTerms: dict[str, str] = {}          # 术语 -> 口语化改写


class HandoffView(BaseModel):
    reason: Literal[
        "out_of_scope", "safety_degrade", "safety_block",
        "not_converged", "mandatory_report",
    ]
    summary: str                              # 农户可携带的上下文摘要
    confirmedInfo: list[str]                  # 已确认信息
    observationPoints: list[str]              # 可自行观察的要点
    excludedItems: list[str]                  # 已排除项
    contacts: list[ContactInfoView] = []       # 本地联系入口
    speakable: bool = True                    # 是否提供朗读入口（A5）


class QuotaPromptView(BaseModel):
    scene: str
    text: str
    granted: bool = False


class ChatResponse(BaseModel):
    sessionId: str
    stage: ConsultStage
    stageLabel: str                           # 口语化进度文案
    progress: ProgressInfo                    # {current: 2, total: 3}
    reply: str                                # 面向农户的回复文本
    questions: list[QuestionView] | None = None
    prescription: PrescriptionView | None = None
    environmentNote: str | None = None        # "暂无环境数据，判断基于你的描述"
    handoff: HandoffView | None = None        # 转人工信息（含联系方式与朗读入口）
    quotaPrompt: QuotaPromptView | None = None
    degraded: bool = False                    # 是否处于降级状态
```

### handoff 用 200 加字段表达而非错误码

转人工是正常业务结果，不是异常。因此：

```python
@router.post("/chat", response_model=ChatResponse)
async def chat(req: ChatRequest, ...) -> ChatResponse:
    return await get_ai_service().chat(user_id, req)   # 始终 200
```

`handoff` 非空时 `prescription` 必为 `None`，两者互斥。`handoff.reason` 用封闭枚举，取值与技术方案 6.7 的四类情形对应，外加 `not_converged`：

| `handoff.reason` | 触发点 | 输出内容 |
| --- | --- | --- |
| `out_of_scope` | `DiagnosisResult.out_of_scope = True` | 建议咨询当地农技站 + 可自行观察的要点 |
| `safety_degrade` | `GateResult.decision == "degrade"` | 转人工引导文案，解释为什么不建议自行用药 |
| `safety_block` | `GateResult.decision == "block"` | 同上，附加命中红线摘要（不展示内部规则 id） |
| `not_converged` | 问诊轮次 ≥ 4 且关键槽位仍 missing | 建议携样本咨询农技站 |
| `mandatory_report` | `ReportDecision.triggered = True` | 立即隔离、消毒、报告 + 本地联系入口 |

若用错误码（4xx/5xx）表达转人工，前端会把"转人工"渲染成失败态，农户看到红色报错，且前端可能在重试逻辑里把提示吞掉。用 200 + 字段后，前端渲染路径与正常处方一致，只是多渲染一个 `handoff` 区块。

### environmentNote 在 env_source 为 none 或 sensor_stale 时必填

产品说明书 4.2.3 功能点 6 要求界面明确标注"当前没有环境数据，以下判断基于你描述的情况"。实现上不允许"没数据就留空"：

```python
STALE_ENV_SOURCES = {"none", "sensor_stale"}


def build_environment_note(state: ConsultationState, process_id: ProcessId) -> str | None:
    """env_source 为 none / sensor_stale 时必须返回提示文案，不允许为空。"""
    env = state.get("observations") or {}
    env_source = env.get("env_source", "none")
    if env_source in STALE_ENV_SOURCES:
        region_label = env.get("region_hit_level")      # 保留实际命中级，见地区回退
        if region_label:
            return f"暂无本地的环境数据，以下判断基于你的描述；农时提示按{region_label}通用口径给出。"
        return "暂无环境数据，以下判断基于你的描述的情况。"
    return None
```

`env_source` 的取值由环境事实三级回退采集写入（T3-02）：`sensor` / `sensor_stale` / `weather` / `none`。`sensor_stale` 表示有传感器但读数过期，同样属于"不能拿来支撑判断"，必须提示。注意这个字段在 `verify` 与 `prescribe` 阶段往往更关键——处方里的环境相关建议若建立在过期读数上，必须让农户知道。

### 服务层改造

```python
"""AI 对话编排服务：图驱动，落库走 repository，出参为 ChatResponse。"""
from app.agent import get_agent, resume_graph
from app.agent.state import ConsultStage
from app.schemas.consult import ChatRequest, ChatResponse
from app.services.profile_service import ProfileService


class AIService:
    async def chat(self, user_id: str, req: ChatRequest) -> ChatResponse:
        session_id = req.sessionId or new_session_id()
        # 命中归属校验：会话必须属于当前用户，否则视为新会话（T1-06）
        await self._assert_or_create_session(user_id, session_id, req)

        state = await self._resume_or_start(session_id, user_id, req)
        return self._build_response(session_id, state)

    async def _resume_or_start(self, session_id: str, user_id: str, req: ChatRequest) -> dict:
        """新会话 / 中断恢复 / 已结束 三分支。"""
        graph = await get_agent()
        config = {"configurable": {"thread_id": session_id}}

        if req.sessionId is not None:
            snapshot = await graph.aget_state(config)
            if snapshot.next:                       # 中断中，携带答案恢复
                resume_value = self._resume_value(req)
                return await resume_graph(session_id, resume_value)

        # 新会话：构建初始 state。context 由 service 层组装，不把 db 传进图（守 L2）
        initial_state = {
            "session_id": session_id,
            "user_id": user_id,
            "farm_plot_id": req.farmEntryId,
            "process_hint": req.processHint,
            "image_url": req.imageUrl,
            "voice_url": req.voiceUrl,
            "user_message": req.message,
            "context": await self.build_context(user_id, req),
            "messages": [{"role": "user", "content": req.message or ""}],
        }
        return await graph.ainvoke(initial_state, config=config)
```

**关键删除项**：不再传 `config["configurable"]["db"]`。现有代码把 ORM Session 塞进图 config，让节点直接访问数据库，这违反 L2（`app/agent/` 不得导入 `app/models/`）与 L4（不得直接 `db.query`）。改造后所有数据由 service 层通过 repository 取出、以结构化 `context` 注入图，图内的智能体只与 state 交互。`_persist`、`build_context`、`history` 里的 `db.query(...)` 全部改走 `app/repositories/`。

### 出参组装

```python
def _build_response(self, session_id: str, state: dict) -> ChatResponse:
    stage = state.get("stage", ConsultStage.INTAKE)
    return ChatResponse(
        sessionId=session_id,
        stage=stage,
        stageLabel=stage_label(stage),                    # 从流程配置口语化映射取
        progress=progress_of(state),
        reply=state.get("reply") or "",
        questions=self._questions(state),                 # 待答复时非空
        prescription=self._prescription(state),           # 门禁 allow 时非空
        environmentNote=build_environment_note(state, state.get("process_id")),
        handoff=self._handoff(state),                     # 转人工时非空
        quotaPrompt=self._quota_prompt(state),            # 关键节点非空
        degraded=state.get("degraded", False),
    )
```

`questions` 与 `handoff` 与 `prescription` 三者的互斥关系：`questions` 非空表示等待农户输入（中断中）；`handoff` 非空表示转人工结束；`prescription` 非空表示门禁放行结束。三者不应同时出现两个以上，组装时用断言固定。

### 契约与枚举约束

所有 `Literal` / `Enum` 字段来自契约层，不接受自由字符串。`answers` 里的 `status` 只用 `filled` / `unknown`，把"用户明确答不出"与"尚未询问"（`missing`）分开——`missing` 不出现在请求里，只出现在服务端 state 的 `slots` 中，这是全局约定第四节"区分未知与缺失"的接口体现。大模型输出的自由文本必须经解析落到枚举，解析失败即契约违约并触发降级，接口层不接收未落在枚举上的值。
