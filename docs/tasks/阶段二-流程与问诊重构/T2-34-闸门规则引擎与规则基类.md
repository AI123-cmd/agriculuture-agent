# T2-34 闸门规则引擎与规则基类

## 这一项要做什么

在 `app/gate/` 下建立安全闸门的骨架：规则抽象基类 `Rule`、规则注册表、判定入口 `GateEngine.evaluate`、以及闸门全部输入类型 `GateContext`。闸门是本方案中唯一拥有否决权的组件（产品说明书 6.2 要求它"必须独立于生成环节实现"，6.4 要求四条红线"任何迭代不得突破"），因此本项的第一目标不是功能而是边界：让闸门成为一个不依赖智能体层、不调用模型、每次判定可复现的独立包。第二条目标是让八类规则成为同构的纯函数，每条规则都能脱离数据库与模型单独单测，这是技术方案 14.2"闸门即评测关卡"能落地的前提。

## 前置依赖

- 依赖 T2-12：必须已提供 `GateResult`、`GateViolation` 的字段语义与三条校验器（红线未加载强制 block、存在 block 违规不得 allow、degrade 必须带文案）。本项把这三类契约的**定义位置**迁到 `app/gate/contracts.py`，T2-12 的文件改为从闸门包再导出（消解办法见下文，方向为 agent → gate，合法）。
- 依赖 T2-11：必须已提供 `Prescription`、`PesticideItem` 的字段集合（`pesticide_items`、`safety_interval_days`、`max_uses_per_season`、`facts_provenance`），闸门侧按同一结构建立只读镜像。
- 依赖 T2-06：必须已提供 `LoadedRedlines` 与 `GateRuleId`（含 `declared_rule_ids()` 与 `blocking_labels()`），闸门按它判断 `process_redlines_loaded`。
- 依赖 T2-01：必须已提供 `ProcessId` 与 `ViolationSeverity` 的取值集合；闸门不直接导入它们，改用同值的镜像枚举（原因见"包的边界"）。
- 外部环境：无。本项不碰数据库、缓存与模型服务，`pytest tests/gate/` 可在纯内存下运行。

## 实现要点

### 包的边界与两处技术推断

L1 规则由 `scripts/check_layers.py` 以"文件内 import 前缀"判定，`app.gate` 下任何文件出现 `app.agent` 或 `app.services` 开头的 import 即构建失败。这与 T2-12 把 `GateResult`/`GateContext` 放在 `app/agent/contracts/gate.py` 直接冲突，因此本项做两处必要推断并在此写明。

第一处，**闸门契约归闸门所有**。`app/gate/contracts.py` 是 `GateViolation`/`GateResult`/`GateContext` 的唯一定义处；`app/agent/contracts/gate.py` 只做 `from app.gate.contracts import GateResult, GateViolation, GateContext` 并列入 `__all__`。T2-12 定义的三条校验器原样移到闸门侧。方向合法：L1 只禁止 gate → agent。

第二处，**枚举镜像**。`ProcessId` 与 `ViolationSeverity` 的源在 `app/agent/state.py`（全局约定第二节的目录约定），闸门不能导入，故在 `app/gate/enums.py` 定义同值枚举。两者靠测试而非 import 保持同步：`tests/gate/test_contracts_mirror.py` 断言 `{p.value for p in gate.enums.ProcessId} == {p.value for p in agent.state.ProcessId}`。这是刻意的取舍——宁可多一份七行的枚举与一条测试，也不让闸门对生成链路产生任何编译期依赖。

### 规则基类 Rule

```python
# app/gate/rules/base.py
class Rule(ABC):
    """一条闸门规则。实现为纯函数：只读 ctx，不做 IO，不调模型。"""

    rule_id: ClassVar[str]
    severity: ClassVar[GateSeverity]          # block / degrade / warn
    description: ClassVar[str] = ""
    requires: ClassVar[frozenset[str]] = frozenset()   # 需要的上下文能力名

    @abstractmethod
    def check(self, ctx: GateContext) -> list[GateViolation]:
        """返回本轮命中的全部违规。无命中返回空列表，不得返回 None。"""

    def violation(self, field: str, message: str,
                  severity: GateSeverity | None = None) -> GateViolation:
        """按规则自身的 id 与等级构造违规，避免每条规则各写一遍 rule_id。"""
        return GateViolation(rule_id=self.rule_id, severity=severity or self.severity,
                             message=message, field=field)
```

`check` 返回列表而不是 `GateResult`：一条规则只负责"我发现什么"，"整体怎么裁定"由引擎统一决定。这让新增规则不需要理解 decision 聚合逻辑，也让同一条规则能被两个不同的引擎（例如影子模式下的宽松引擎）复用。`severity` 是类属性而非 `check` 的参数，因为等级属于规则的定义，不属于某一次判定。

### 规则注册表

```python
_REGISTRY: dict[str, type[Rule]] = {}

def register(cls: type[Rule]) -> type[Rule]:
    """登记规则类。rule_id 必须是枚举值、不得重复、不得是抽象类。"""
    rid = getattr(cls, "rule_id", None)
    if rid not in {r.value for r in GateRuleId}:
        raise GateConfigError(f"{cls.__name__} 的 rule_id {rid!r} 不在 GateRuleId 内")
    if rid in _REGISTRY:
        raise GateConfigError(f"规则 id 重复登记: {rid}")
    if inspect.isabstract(cls):
        raise GateConfigError(f"{cls.__name__} 仍有未实现的抽象方法")
    _REGISTRY[rid] = cls
    return cls

def build_rules(rule_ids: Iterable[str] | None = None) -> list[Rule]:
    """实例化规则。None 表示全部；未登记 id 直接抛错，不静默跳过。"""
    ids = [r.value for r in GateRuleId] if rule_ids is None else list(rule_ids)
    missing = [i for i in ids if i not in _REGISTRY]
    if missing:
        raise GateConfigError(f"规则未登记: {missing}")
    return [_REGISTRY[i]() for i in ids]
```

注册表以 `GateRuleId` 为白名单：配置里写了 `R-NOT-EXIST` 在 T2-06 已被拦，但代码侧漏实现一条已声明的规则同样要能被发现，`missing` 分支就是这一条的执行点。规则无参数、无状态，因此可以实例化后跨判定复用。

### GateContext

```python
# app/gate/contracts.py
class GateContext(BaseModel):
    """闸门全部输入。刻意不含会话消息与任何模型句柄。"""
    model_config = ConfigDict(extra="forbid", frozen=True)

    process_id: ProcessId
    config_version: int
    prescription: GatePrescription            # 处方只读镜像（字段与 T2-11 同名）
    payload: GatePayload                      # 展示文本，溯源扫描的输入
    redlines: LoadedRedlines
    slots: dict[str, str | date | None] = {}  # 槽位原始值，日期为 ISO 字符串
    knowledge: KnowledgeFacts                 # 只读事实源协议，非具体仓储
    medication_history: list[MedicationRecord] = []
    region_code: str | None = None
    today: date
    season_start: date | None = None          # 每季次数的统计起点
    rule_configs: dict[str, dict[str, object]] = {}   # rule_id -> 红线 data 载荷

    def slot_date(self, key: str) -> date | None:
        """取日期型槽位。空、unknown、解析失败一律返回 None（fail-closed）。"""
        raw = self.slots.get(key)
        if raw in (None, "", "unknown"):
            return None
        if isinstance(raw, date):
            return raw
        try:
            return date.fromisoformat(str(raw))
        except ValueError:
            return None
```

`GateContext` 不是 `dict` 而是 Pydantic 模型：`extra="forbid"` 让"给闸门塞了一个会话消息字段"在构造时就报错，把 8.1 的两条物理隔离（不接收会话消息、不调用大模型）从文档约定变成类型约束。`knowledge` 声明为 `Protocol` 而非具体类，是 L1 与可测性的共同要求：闸门只声明它需要的方法，测试可喂一个三行的假实现。

### KnowledgeFacts 只读协议

```python
# app/gate/ports.py
class KnowledgeEntrySnapshot(Protocol):
    knowledge_id: str
    name: str
    status: str                                   # draft / approved / suspended / deprecated
    registered_crops: tuple[str, ...]
    dosage_min: float | None
    dosage_max: float | None
    dosage_unit: str | None
    safety_interval_days: int | None
    max_uses_per_season: int | None
    forbidden_combinations: tuple[str, ...]
    region_scope: str | None

class KnowledgeFacts(Protocol):
    def get_entry(self, knowledge_id: str) -> KnowledgeEntrySnapshot | None: ...
    def is_approved(self, knowledge_id: str) -> bool: ...
```

`get_entry` 返回 `None` 表示"该 knowledge_id 不在已核准库中"，这与"条目存在但 `status != approved`"是两件事，前面几条规则要分别给出不同的提示语（前者是模型编造条目，后者是条目被暂停）。协议里不放 `search`，因为闸门不做检索——检索属于生成侧，闸门只核对已被引用的条目的字段。这条边界是"独立仲裁"与"生成"在数据上的分界。

### GateEngine.evaluate 完整骨架

```python
# app/gate/engine.py
_PRECHECK_RULE_IDS = (GateRuleId.REDLINE_LOAD.value,)

class GateEngine:
    """规则执行与结果聚合。无状态，可跨请求复用。"""

    def __init__(self, rules: list[Rule] | None = None) -> None:
        self._rules = rules if rules is not None else build_rules()
        order = {r: i for i, r in enumerate(_PRECHECK_RULE_IDS)}
        self._rules.sort(key=lambda r: (order.get(r.rule_id, len(order)), r.rule_id))

    def evaluate(self, ctx: GateContext) -> GateResult:
        """执行全部规则并裁定。任何异常一律 fail-closed。"""
        checked: list[str] = []
        violations: list[GateViolation] = []

        for rule in self._rules:
            if rule.rule_id in _PRECHECK_RULE_IDS or self._gate_open(ctx, violations):
                checked.append(rule.rule_id)
                violations.extend(self._run(rule, ctx))
            if not ctx.redlines.loaded:
                break            # 红线未加载：只跑完前置规则即停，不再执行其余规则

        decision = self._decide(violations)
        return GateResult(
            passed=decision == "allow",
            violations=violations,
            checked_rules=checked,
            process_redlines_loaded=ctx.redlines.loaded,
            decision=decision,
            degrade_output=DEGRADE_OUTPUT_TEXT if decision == "degrade" else None,
        )

    def _run(self, rule: Rule, ctx: GateContext) -> list[GateViolation]:
        """单条规则执行。抛异常即视为该规则判定失败，按最保守方向记一条 block。"""
        try:
            return rule.check(ctx)
        except Exception as exc:                     # noqa: BLE001 —— 闸门必须吞掉一切异常
            return [GateViolation(rule_id=rule.rule_id, severity="block",
                                  message=f"规则执行异常，按最保守判定拦截：{exc}",
                                  field="-")]

    @staticmethod
    def _gate_open(ctx: GateContext, violations: list[GateViolation]) -> bool:
        """红线未加载或已出现 block 级违规时，后续规则不再执行。"""
        if not ctx.redlines.loaded:
            return False
        return not any(v.severity == "block" for v in violations)

    @staticmethod
    def _decide(violations: list[GateViolation]) -> str:
        """聚合裁定：block 优先于 degrade，degrade 优先于 warn，其余放行。"""
        if any(v.severity == "block" for v in violations):
            return "block"
        if any(v.severity == "degrade" for v in violations):
            return "degrade"
        return "allow"
```

`_run` 的异常兜底是 fail-closed 在引擎层的执行点。生成链路遇到异常可以降级但仍服务（全局约定第六节），闸门不可以：规则抛异常意味着"没能完成校验"，此时唯一安全的结论是不放行。用 `exception` 粒度而不是窄类型捕获，是因为规则里任何一处 `KeyError`、`TypeError` 都会让校验半途而废，而半途而废的校验看起来像通过。

`_gate_open` 短路是"红线缺失即不可用"的工程落地。`R-REDLINE-LOAD` 在排序里排在第一位，它一旦 block，后续规则整体跳过。这样做的代价是 `checked_rules` 变短，正好被 8.5 的第三条复盘用途当作信号：`checked_rules` 未覆盖 `redlines.declared_rule_ids()` 时写审计告警。

### 严重度取值与契约的两处分歧

技术方案 8.2 的"违规等级"列出现三个取值——`block`、`degrade`（`R-REGION`）、`warn`（`R-CAUTION`），而 5.3.6 的 `GateViolation.severity` 只声明了 `Literal["block", "warn"]`。本项按 8.2 取三值全集，理由有二：T2-04 的 `tea.yaml` 里 `TEA-05` 明确写 `severity: degrade`，若契约收不下就只能在规则内部偷偷降级；`decision` 的三值与等级的三值一一对应（block→block、degrade→degrade、warn→allow 但留痕），收成两值会让"不通过但不属严重违规"这一档无处安放。`GateSeverity = Literal["block", "degrade", "warn"]`，`ViolationSeverity` 仍是两值枚举，二者不冲突：前者是规则的判定档位，后者是 T2-01 给配置层用的枚举。
