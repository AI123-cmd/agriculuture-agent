# T2-48 知识库索引构建器

## 这一项要做什么

在 `app/knowledge/indexer.py` 中实现知识条目的索引构建链路：从 `app/knowledge/seeds/` 下的条目数据文件读入原始条目，做字段校验、正文向量化、写入 `knowledge_item` 与 `knowledge_region` 两张表，并为新条目建立 HNSW 向量索引。它是 T2-52 与 T2-53 内容建设的落库入口，也是闸门规则的比对数据来源。

构建器要支持三种运行方式：全量重建（首次部署）、增量更新（内容建设阶段反复迭代）、dry-run（CI 与预发校验）。增量更新以内容指纹比对决定是否重算向量，避免每改一个字就把全部条目重新向量化。

## 前置依赖

- 依赖 T2-47：必须已提供 `KnowledgeItem`、`KnowledgeRegion`、`KnowledgeStatus`
- 依赖 T1-02：必须已提供异步数据库会话；依赖 T1-04：必须已提供迁移链路，本项不新增迁移，只写入数据
- 依赖 T2-01：必须已提供 `ProcessId`、`EvidenceKind`，用于校验 `process_id` 与 `kind`
- 外部环境：pgvector 扩展已启用；向量化服务可用（`EMBEDDING_API_URL` 或本地模型），维度固定 1024；`USE_MOCK_LLM=true` 时使用确定性伪向量
- 与 T2-52、T2-53 的关系：本项只实现构建器，条目内容由这两项提供；与 T2-49 的关系：构建器写入的数据是混合检索的输入

## 实现要点

### 条目数据文件模型

```python
class KnowledgeRegionSpec(BaseModel):
    """条目的地区挂载点。"""
    model_config = ConfigDict(extra="forbid")
    region_code: str
    region_level: Literal["county", "city", "province", "national"]

class KnowledgeSeedItem(BaseModel):
    """条目数据文件中的一条记录。字段与 knowledge_item 表对应。"""
    model_config = ConfigDict(extra="forbid")
    knowledge_id: str
    process_id: ProcessId
    kind: EvidenceKind
    title: str
    content: str
    pesticide_name: str | None = None
    registered_crops: list[str] = []
    dosage_min: float | None = None
    dosage_max: float | None = None
    dosage_unit: str | None = None
    safety_interval_days: int | None = None
    max_uses_per_season: int | None = None
    forbidden_combinations: list[str] = []
    region_scope: str | None = None
    regions: list[KnowledgeRegionSpec] = []
    effective_date: date | None = None
    expire_date: date | None = None
    status: KnowledgeStatus = KnowledgeStatus.DRAFT
    status_reason: str | None = None
    source_ref: str | None = None
    @model_validator(mode="after")
    def _pesticide_fields_required(self) -> "KnowledgeSeedItem":
        if self.kind is EvidenceKind.PESTICIDE:
            if not self.pesticide_name:
                raise ValueError("kind=pesticide 必须给出 pesticide_name")
            if self.dosage_min is None or self.dosage_max is None or not self.dosage_unit:
                raise ValueError("kind=pesticide 必须给出完整剂量区间与单位")
            if self.safety_interval_days is None:
                raise ValueError("kind=pesticide 必须给出 safety_interval_days")
        return self
    @model_validator(mode="after")
    def _suspended_requires_reason(self) -> "KnowledgeSeedItem":
        if self.status is KnowledgeStatus.SUSPENDED and not self.status_reason:
            raise ValueError("status=suspended 必须给出 status_reason")
        return self
    def content_fingerprint(self) -> str:
        """内容指纹，用于增量构建时判断是否需要重算向量。"""
        payload = {"title": self.title, "content": self.content, "kind": self.kind.value,
                   "pesticide_name": self.pesticide_name, }
        return hashlib.sha256(json.dumps(payload, ensure_ascii=False, sort_keys=True).encode("utf-8")).hexdigest()
```

`kind=pesticide` 的字段强制校验是 `R-DOSAGE` 与 `R-INTERVAL` 的前置保障：闸门要求剂量落在条目给定区间内、必须显式给出安全间隔期，若条目本身缺这些字段，规则就失去比对基准。把这个校验放在载入阶段，比在闸门运行时才发现缺失更早，也更便宜。指纹只覆盖影响检索与展示的字段，`status` 与 `regions` 变化不改指纹，因为它们不改变向量。

### 向量化接口

```python
class Embedder(Protocol):
    """向量化接口。真实实现走模型服务，mock 实现返回确定性伪向量。"""
    dimensions: int
    async def embed(self, texts: list[str]) -> list[list[float]]: ...

class HttpEmbedder:
    """真实向量化：批量请求，失败按指数退避重试。"""
    dimensions = 1024
    def __init__(self, url: str, api_key: str, timeout: float = 30.0) -> None: ...

class MockEmbedder:
    """mock 向量化：由文本哈希种子生成确定性单位向量，保证同文同向量。"""
    dimensions = 1024
    async def embed(self, texts: list[str]) -> list[list[float]]:
        return [self._unit_vector(text) for text in texts]
```

`MockEmbedder` 必须确定性：同一文本每次生成同一向量，不同文本生成不同向量。若用随机向量，测试中"相似查询能召回对应条目"这类断言会随机失败。确定性种子让 mock 模式下也能验证检索链路的顺序与融合逻辑，只是不验证真实语义相似度。

向量化的输入文本是 `title + "\n" + content`，不含药剂字段。原因是向量召回用于找"语义相关的条目"，而药剂名、剂量这类字段由元数据过滤与精确匹配负责，把它们拼进向量文本会稀释语义信号。

### 构建流程

```python
class KnowledgeIndexer:
    """知识索引构建。支持全量重建、增量更新与 dry-run。"""
    def __init__(self, session: AsyncSession, embedder: Embedder) -> None:
        self._session = session
        self._repo = KnowledgeRepository(session)
        self._embedder = embedder
    async def build(self, items: list[KnowledgeSeedItem], *, dry_run: bool = False) -> BuildReport:
        report = BuildReport()
        for item in items:
            existing = await self._repo.get_by_id(item.knowledge_id)
            if existing is not None and existing.content_hash == item.content_fingerprint():
                report.skipped += 1
                continue
            report.upserted += 1
            if dry_run:
                continue
            await self._upsert_one(item, existing)
        return report
    async def _upsert_one(self, item: KnowledgeSeedItem, existing: KnowledgeItem | None) -> None:
        """写入一条：先算向量，再写主表，再同步地区表。同一事务内完成。"""
        vector = (await self._embedder.embed([f"{item.title}\n{item.content}"]))[0]
        if len(vector) != self._embedder.dimensions:
            raise IndexBuildError(f"向量维度不符: {item.knowledge_id} 得到 {len(vector)}")
        row = self._to_row(item, vector)
        if existing is None:
            self._session.add(row)
        else:
            await self._session.execute(update(KnowledgeItem).where(
                KnowledgeItem.knowledge_id == item.knowledge_id).values(**self._to_update_values(item, vector)))
        await self._sync_regions(item)
```

`build` 的幂等通过 `content_hash` 比对实现。写入主表与地区表在同一事务内，避免出现"条目写了但地区挂载没写"导致检索漏召回。写入顺序是先向量后落库：向量化失败则整条不写入，不会留下 `embedding` 为空的条目（空向量条目在检索时会静默失效，最难排查）。

`content_hash` 需要新增一列（本项在 T2-47 的表基础上补），也可以复用 `updated_at` 比对，但指纹更精确：只改 `status` 不应触发重算向量，指纹设计已排除 `status`。

### 地区挂载的展开

```python
    async def _sync_regions(self, item: KnowledgeSeedItem) -> None:
        """同步地区挂载：先删旧挂载，再按条目声明写入。"""
        await self._session.execute(delete(KnowledgeRegion).where(
            KnowledgeRegion.knowledge_id == item.knowledge_id))
        specs = item.regions
        if not specs and item.region_scope is None:
            specs = [KnowledgeRegionSpec(region_code="000000", region_level="national")]
        for spec in specs:
            self._session.add(KnowledgeRegion(id=str(uuid4()), knowledge_id=item.knowledge_id,
                region_code=spec.region_code, region_level=spec.region_level))
```

条目未声明任何地区时，自动挂到全国兜底（`region_code="000000"`，`region_level="national"`）。这样保证每条 `approved` 条目在回退链的最后一级一定可被检索到，不会出现"条目存在但任何地区都召回不到"的情况。这也是 T2-50 回退链最后一级的语义基础。

### dry-run 与报告

```python
@dataclass(slots=True)
class BuildReport:
    """构建报告。dry-run 时只填 would_upsert 与 skipped。"""
    upserted: int = 0
    skipped: int = 0
    region_rows: int = 0
    errors: list[str] = field(default_factory=list)
```

构建报告要能被启动自检与 CI 读取。CI 中跑 `build(items, dry_run=True)` 断言 `errors` 为空，把"条目数据文件写错了"这类问题挡在部署之前。错误不抛整体异常而是收集到 `errors`，让一次构建能报出全部问题条目，而不是修一个跑一次。构建时同时校验条目的 `process_id` 在流程配置中存在，防止"知识库有条目但流程没建"的悬空状态。
