# T2-45 闸门子图接入与过闸门流程

## 这一项要做什么

在 `app/agent/graph/gate_graph.py` 中实现闸门子图，把它挂到主图的 `prescribe` 之后、`followup` 之前。子图负责三件事：从 `ConsultationState` 组装 `GateContext`（这一步是唯一允许读 state 的地方）、调用 `GateEngine.evaluate`、把 `GateResult` 的三个 decision 语义映射为输出处理——`allow` 放行处方卡；`degrade` 把输出**整体替换**为 `degrade_output`（标准转人工引导文案），不修改后输出；`block` 拒绝输出并写审计事件、触发知识条目复核工单。它是"生成与校验物理隔离"在编排层的落点：闸门是图上一个独立子图，输入只有三类，拿不到会话消息。

## 实现要点

### 上下文组装是唯一的 state 读取点

```python
# app/agent/graph/gate_graph.py
def build_gate_context(state: ConsultationState, *, knowledge: KnowledgeFacts,
                       today: date) -> GateContext:
    """把 state 压成 GateContext。这是闸门侧唯一允许读 state 的地方。

    刻意不读 messages 与 reply：8.1 要求闸门不接收会话消息，
    因此无法被对话中的表述影响。多读一个字段就等于多一个被影响的入口。
    """
    prescription = Prescription.model_validate(state["prescription"])
    return GateContext(
        process_id=ProcessId(state["process_id"]),
        config_version=state.get("config_version", 0),
        prescription=GatePrescription.from_contract(prescription),
        payload=GatePayload(rendered_text=state.get("prescription_text") or ""),
        redlines=LoadedRedlines.model_validate(state["redlines"]),
        slots=_flatten_slots(state.get("slots") or {}),
        knowledge=knowledge,
        medication_history=_history(state.get("prescription_history") or []),
        region_code=state.get("region_code"),
        today=today,
        season_start=_season_start(state),
        rule_configs=_rule_configs(state["redlines"]),
    )


def _flatten_slots(slots: dict) -> dict[str, str | None]:
    """只取已确认的值。unknown 与 missing 一律落成 None，让规则走保守分支。"""
    out: dict[str, str | None] = {}
    for key, slot in slots.items():
        raw = slot if isinstance(slot, dict) else slot.model_dump()
        out[key] = raw.get("value") if raw.get("status") == "filled" else None
    return out
```

`_flatten_slots` 把 `unknown` 与 `missing` 都落成 `None`，`R-INTERVAL` 因此在两种情形下都判定"缺少下一轮采摘计划"并 block，这是 fail-closed 的正确方向（全局约定第四节：区分未知与缺失是问诊层的职责，闸门层不区分，因为二者都无法证明方案不冲突）。

### 三个 decision 的输出处理

```python
async def build_gate_node(knowledge: KnowledgeFacts, today: date | None = None):
    """产出闸门节点。knowledge 由调用方注入，闸门不自行创建仓储。"""
    service = GateService()

    async def gate_node(state: ConsultationState, config=None) -> dict:
        ctx = build_gate_context(state, knowledge=knowledge, today=today or date.today())
        draft = Prescription.model_validate(state["prescription"])
        result = await service.review(draft, ctx)          # 引擎 + 审计 + 影子模式

        if result.decision == "allow":
            # 放行：处方卡正常返回，original 文本保留
            return {"gate_result": dump_contract(result), "stage": ConsultStage.GATE,
                    "prescription_text": state.get("prescription_text")}

        if result.decision == "degrade":
            # 降级：输出整体替换为 degrade_output，不修改后输出（产品说明书 6.2）
            return {"gate_result": dump_contract(result), "stage": ConsultStage.GATE,
                    "prescription_text": result.degrade_output,
                    "prescription_suppressed": True}

        # block：拒绝输出并记录审计事件，同时触发知识条目复核工单
        await _raise_review_ticket(ctx, result)
        return {"gate_result": dump_contract(result), "stage": ConsultStage.BLOCKED,
                "prescription_text": DEGRADE_OUTPUT_TEXT,
                "prescription_suppressed": True}

    return gate_node
```

**`degrade` 不修改后输出**是本项最容易被写错的一点。产品说明书 6.2 明确"校验不通过时，输出降级为建议联系当地农技站，而不是修改后输出"。实现上体现为三处：`prescription_text` 被整体赋值为 `result.degrade_output`（不做局部替换）；原处的 `prescription` 保留在 state 里不被改写（供审计与复盘），但 `prescription_suppressed=True` 让展示层不渲染它；`actions`、`pesticide_items` 等字段不做任何删改。若实现者试图"只删掉有问题的药剂条目再输出"，那是修改后输出，违反产品要求。

**`block` 的 `stage` 是 `BLOCKED` 而非 `HANDOFF`**：T2-01 明确二者必须分开统计——前者是闸门硬红线拒绝输出，后者是正常业务结果（超边界、法定报告、连续未收敛）。审计表与线上指标据此区分。

### 处方卡输出的三态对照

| decision | `prescription_text` | `stage` | 展示层行为 | 审计 |
| --- | --- | --- | --- | --- |
| `allow` | 原文本 | `GATE` | 渲染处方卡 | 记录 result |
| `degrade` | `degrade_output` | `GATE` | 渲染引导文案，不渲染处方卡 | 记录 result，参与 degrade 率 |
| `block` | `degrade_output` | `BLOCKED` | 渲染引导文案，不渲染处方卡 | 记录 result + 触发复核工单 |

`block` 也用 `degrade_output` 作为对外文案，因为农户不需要知道"是硬红线还是地区不匹配"，两者对农户的正确指引都是"问本地农技站"。差别只在内部审计与工单。

### 子图组装

```python
def build_gate_subgraph(knowledge: KnowledgeFacts):
    """闸门子图：单节点，入口即出口。挂在主图 prescribe 之后。"""
    from langgraph.graph import END, StateGraph
    graph = StateGraph(ConsultationState)
    graph.add_node("gate_check", build_gate_node(knowledge))
    graph.add_edge("gate_check", END)
    return graph
```

子图只有一个节点是刻意的：闸门的判定必须是原子的——要么完成全部规则的执行并给出一个 decision，要么因异常走 fail-closed。中间态（"跑了一半规则"）不允许被主图观察到。主图按 T2-25 的方式挂载：`graph.add_node("gate", build_gate_subgraph(knowledge))`、`graph.add_conditional_edges("gate", route_after_gate, ROUTE_AFTER_GATE)`，其中 `allow → followup`、`degrade`/`block → handoff`。

### 复核工单的触发

```python
async def _raise_review_ticket(ctx: GateContext, result: GateResult) -> None:
    """block 事件触发知识条目复核工单（8.5 第一条复盘用途）。

    工单只记录必要字段，不落会话原文。落库走 repositories，不直接 db.query（L4）。
    """
    from app.repositories.gate_audit import enqueue_review_ticket
    await enqueue_review_ticket(
        process_id=ctx.process_id.value,
        config_version=ctx.config_version,
        rule_ids=sorted({v.rule_id for v in result.violations}),
        knowledge_ids=sorted({i.knowledge_id for i in ctx.prescription.pesticide_items}),
        decision=result.decision,
    )
```

工单里带 `knowledge_ids` 是 8.5 第一条复盘用途的关键：它让复核人员能直接定位"是这几条知识条目的数据有问题"还是"模型越界"。`enqueue_review_ticket` 走 `app/repositories/`，遵守 L4。

### 闸门不做的事

以下四件事明确不在本项范围内，写在此处防止执行者扩大范围。

- **不做降级话术生成**：`degrade_output` 是 `app/gate/constants.py` 里的固定文案，不调模型改写。若允许模型生成引导文案，就等于给了模型一条绕过闸门的输出通道。
- **不做本地化改写**：引导文案的口语化由展示层与 T4-04 的朗读入口处理，闸门只输出标准文案。
- **不重试引擎**：`GateService.review` 调用一次 `evaluate`。引擎内部已对每条规则做异常兜底（按最保守判定），重试只会延长农户等待且不改变结论。
- **不写 `messages`**：闸门不产生面向农户的对话消息，输出通过 `prescription_text` 与 `handoff` 字段表达。

### 拦截频率监控方式

闸门子图本身不做规则级监控（各规则在各自文件中说明），这里监控的是 decision 分布与耗时。

- **三态分布**：按 `gate_audit.decision` 分组，`allow` / `degrade` / `block` 的占比。`block` 占比过高说明生成侧质量差（8.5 第二条复盘用途的对称结论），`degrade` 率持续偏高说明某条流程知识库覆盖不足。
- **闸门耗时 P50/P95**：作为 14.3 链路级指标之一记录。闸门无 IO（除审计写入）且规则全是纯函数，耗时应在毫秒级。耗时上抬通常意味着 `KnowledgeFacts` 的实现每次都在查库（应在检索阶段一次性取好）。
- **`prescription_suppressed` 的比例**：该值等于 `degrade` 与 `block` 之和，异常升高时检查是否有规则被误配成过严的等级。
- **`process_redlines_loaded` 的分组**：该值为 False 的分组必须为空（对应 T2-43 的"命中数恒为 0"要求）。
