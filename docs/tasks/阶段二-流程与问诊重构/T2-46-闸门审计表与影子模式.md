# T2-46 闸门审计表与影子模式

## 这一项要做什么

新增 `gate_audit` 表与 `app/gate/audit.py` 写入链路，让每一次闸门判定都可复盘；同时实现 `GATE_MODE=shadow` 的影子模式：只记录不拦截，返回 `GateResult(passed=True, shadowed=result)`。影子模式是灰度期的必要过渡（技术方案 14.2："闸门写的规则难以一次准确，直接全量开启会大面积误杀"），而灰度结束后必须能干净地切到强制拦截，因此生产环境启动检查中增加一条：`GATE_MODE` 不允许为 `shadow`。本项把"闸门即评测关卡"这条双轨验证机制落地。

## 实现要点

### gate_audit 表完整字段

```python
# app/models/gate_audit.py
class GateAudit(Base, OwnedMixin):
    """闸门判定审计。每次 evaluate 写入一行，供 8.5 的三条复盘用途。"""
    __tablename__ = "gate_audit"
    id: Mapped[str] = mapped_column(String(36), primary_key=True)      # UUID
    session_id: Mapped[str] = mapped_column(String(36), nullable=False, index=True)
    user_id: Mapped[str] = mapped_column(String(36), nullable=False, index=True)
    process_id: Mapped[str] = mapped_column(String(20), nullable=False, index=True)
    config_version: Mapped[int] = mapped_column(Integer, nullable=False)
    decision: Mapped[str] = mapped_column(String(10), nullable=False, index=True)  # allow/degrade/block
    violations: Mapped[list[dict]] = mapped_column(JSONB, nullable=False, default=list)
    checked_rules: Mapped[list[str]] = mapped_column(JSONB, nullable=False, default=list)
    prescription_snapshot: Mapped[dict] = mapped_column(JSONB, nullable=False, default=dict)
    shadowed: Mapped[bool] = mapped_column(Boolean, nullable=False, default=False)
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True), nullable=False, server_default=func.now(), index=True)
    __table_args__ = (
        Index("ix_gate_audit_decision_created", "decision", "created_at"),
        Index("ix_gate_audit_process_decision", "process_id", "decision"),
    )
```

字段与 8.5 表格一一对应，另加 `shadowed` 布尔。`violations` 存 `GateViolation` 的 JSON 数组而不存拼接字符串：8.5 三条复盘用途都要按 `rule_id`、`severity`、`field` 聚合，结构化才能查。`checked_rules` 与 `config_version` 必须同时存在：8.5 第三条用途是"定期核对 `checked_rules` 是否覆盖该流程 `redlines` 声明的全部规则 id，发现'声明了但没执行'的配置错误"，而"声明了哪些"由 `config_version` 对应配置决定，缺任一字段都无法核对。`prescription_snapshot` 存处方的 `model_dump(mode="json")` 全量快照，是表中最大的字段。`shadowed` 是必要新增：影子模式下 `decision` 落的是真实判定但对外返回 `passed=True`，若不标记则事后无法区分"真实拦截"与"影子期记录"，14.2 要求的"人工抽查被拦但不该拦的比例"将无法筛选，且该字段为 True 的行不计入 14.3 的"闸门拦截率"。

`ck_gate_audit_decision` 与全局约定第四节"状态字段用字符串枚举值，不用整数编码"配合，同时防止写入 `passed`/`deny` 这类非枚举值。`downgrade` 只 `drop_table`，因为该表无外键指向其他表（`session_id` 与 `user_id` 是弱引用，不做外键以便审计数据在用户注销后仍保留）。刻意不与业务表建外键是审计数据的完整性要求，不违反全局约定第二节的物理隔离。

### 审计写入器与影子模式

```python
# app/gate/audit.py
class GateAuditWriter:
    """闸门审计写入。写入失败不得影响判定结果（审计不能成为可用性瓶颈）。"""
    def __init__(self, repo: GateAuditRepository) -> None:
        self._repo = repo
    async def record(self, draft: GatePrescription, ctx: GateContext,
                     result: GateResult, *, shadowed: bool = False) -> None:
        row = GateAudit(
            id=str(uuid4()), session_id=ctx.session_id, user_id=ctx.user_id,
            process_id=ctx.process_id.value, config_version=ctx.config_version,
            decision=result.decision, shadowed=shadowed,
            violations=[v.model_dump(mode="json") for v in result.violations],
            checked_rules=list(result.checked_rules),
            prescription_snapshot=draft.model_dump(mode="json"))
        try:
            await self._repo.add(row)
        except Exception:                    # noqa: BLE001
            # 审计失败不阻断服务，但必须留结构化错误日志与指标，供 T6-09 告警。
            logger.error("gate_audit_write_failed", process_id=ctx.process_id.value,
                         decision=result.decision, exc_info=True)
            metrics.increment("gate.audit.write_failed")

# app/gate/service.py
class GateService:
    """闸门门面：引擎 + 审计 + 影子模式。决策语义见 GateResult docstring。"""
    def __init__(self, engine: GateEngine | None = None, audit: GateAuditWriter | None = None,
                 settings: Settings | None = None) -> None:
        self.engine = engine or GateEngine()
        self.audit = audit or GateAuditWriter(GateAuditRepository())
        self.settings = settings or get_settings()
    async def review(self, draft: Prescription, ctx: GateContext) -> GateResult:
        result = self.engine.evaluate(ctx)
        await self.audit.record(draft, ctx, result)
        if self.settings.GATE_MODE == "shadow":
            return GateResult(passed=True, shadowed=result)     # 只记不拦（仅灰度期）
        return result
```

`ctx` 因此需要 `session_id` 与 `user_id` 两个字段，本项在 `GateContext` 上补这两个字段（T2-34 可预留），因为审计表要求归属字段，而这两个值只有 state 知道，`build_gate_context`（T2-45）负责填入。**审计写入异常被吞掉**是本项第二处刻意的 fail-open：引擎的 fail-closed 保护"不放过不合格处方"，审计写入保护"判定本身可完成"——若审计写库失败就拒绝出方，数据库抖动会直接变成服务不可用，而判定结果本身是正确的；但"吞掉"必须伴随后果：结构化错误日志 + `gate.audit.write_failed` 指标 + T6-09 告警规则，确保审计缺失不是静默的。

`GateService.review` 是技术方案 14.2 原文的落地。`shadowed` 字段是必要新增：14.2 原文写作 `GateResult(passed=True, shadowed=result)`，而 5.3.6 的 `GateResult` 定义里没有该字段，本项按 14.2 加入 `shadowed: "GateResult | None" = None`，与附录 A.5 一致，需要 `model_rebuild()` 在模块内解析前向引用。`passed=True` 与内层 `decision="block"` 会触发 `_decision_consistency`，因此校验器必须显式跳过影子这一种组合：

```python
    @model_validator(mode="after")
    def _decision_consistency(self) -> "GateResult":
        if self.shadowed is not None:
            return self                      # 影子模式：外层是"放行"外壳，内层才是真实判定
        has_block = any(v.severity == "block" for v in self.violations)
        if has_block and self.decision == "allow":
            raise ValueError("存在 block 级违规时不得 allow")
        if self.decision == "allow" and not self.passed:
            raise ValueError("decision=allow 时 passed 必须为 True")
        return self
```

影子模式只影响"是否拦截"，不影响审计与展示口径：`audit.record` 在影子分支之前调用，记录的是真实判定并以 `shadowed=True` 标记；T2-45 的节点在影子模式下按 `result.shadowed.decision` 决定是否渲染处方卡——即影子期农户看到的仍是真实判定后的结果，影子模式的作用是"让规则先跑起来积累数据"，而不是"让农户看到被拦截后的处方"，这一点必须写清否则执行者可能理解反。审计写入在两种模式下都执行，且审计失败不回滚。

`blocks_for_review` 不排除 `shadowed=True` 的行，因为灰度期的拦截正是要抽查的对象；而 14.3 的"闸门拦截率"口径要排除影子行。两处口径不同，在仓储方法上分开提供，避免调用方各自拼条件。

### 数据保留与拦截频率监控

`gate_audit` 是本项产物，也是全部规则监控的数据源，因此必须保证以下可用性。
- **写入完整率**：表行数应等于 `GateService.review` 调用次数，不一致说明写入被吞（只有日志能发现）；监控方式是 `gate.audit.write_failed` 指标必须恒为 0。
- **影子期与强制期分离**：按 `shadowed` 分组统计 `decision` 分布；影子期 `block` 占比就是"若立即切强制会拦下的比例"，是切 `enforce` 的决策依据，误杀率由人工抽查 `shadowed=True` 且 `decision="block"` 的行得出。
- **按 `process_id` 与 `config_version` 分组**：同一流程不同 `config_version` 的拦截率对比，能看出某次配置变更引入了多少新增拦截，是配置变更的回归验证手段。
- **`checked_rules` 长度分布**：长度恒为 1 说明 `R-REDLINE-LOAD` 一直在 block（对应 T2-43 的"恒为 0"监控）；长度等于规则总数说明全部规则都跑了。`created_at` 索引写入开销随表增长，需按时间分区或定期归档，并监控 P95 写入耗时。
