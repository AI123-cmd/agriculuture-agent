# T2-37 剂量区间与每季次数规则

## 这一项要做什么

在 `app/gate/rules/dosage.py` 中实现两条规则：`R-DOSAGE` 校验剂量必须落在知识条目给定的 `[min, max]` 区间内；`R-MAX-USE` 校验 `max_uses_per_season` 不得超出登记值，且与档案用药史的累计次数不超过上限。两条规则同属"剂量安全"，共用一个模块、各自独立注册。等级均为 `block`。它们是"不得超出登记标签"这条法规要求的自动执行点，也是辣椒流程红线 `CHILI-04`（不得建议更高剂量试图解决土传病害）的直接依托。

## 前置依赖

- 依赖 T2-34：必须已提供 `Rule` 基类、`register`、`GateContext`、`MedicationRecord`、`GateViolation`、`GateRuleId`。
- 依赖 T2-35：必须已提供 `KnowledgeFacts` 假实现，本项需要 `dosage_min` / `dosage_max` / `dosage_unit` / `max_uses_per_season` 字段。

- 依赖 T2-06：`RULE_PAYLOAD_SPEC` 中 `R-DOSAGE` 接受键 `{unit, min, max}`，`R-MAX-USE` 接受键 `{limit}`；本项按此读取 `ctx.rule_configs`。

- 外部条件：剂量区间与登记次数为农技内容，需人工确认（全局约定第八节）。

## 实现要点

### R-DOSAGE 剂量区间

```python
@register
class DosageRangeRule(Rule):
    """R-DOSAGE：剂量必须落在知识条目给定的 [min, max] 区间内。"""

    rule_id = GateRuleId.DOSAGE.value
    severity: GateSeverity = "block"
    description = "剂量必须落在知识条目给定的区间内"

    def check(self, ctx: GateContext) -> list[GateViolation]:
        violations: list[GateViolation] = []
        for i, item in enumerate(ctx.prescription.pesticide_items):
            entry = ctx.knowledge.get_entry(item.knowledge_id)
            if entry is None:
                continue                     # 条目不存在由 R-WHITELIST 拦截，本规则不重复报
            lo, hi = entry.dosage_min, entry.dosage_max
            if item.dosage_min is None and item.dosage_max is None:
                continue                     # 处方未给剂量：由 R-INTERVAL 与展示层处理
            if lo is not None and item.dosage_min is not None and item.dosage_min < lo:
                violations.append(self.violation(
                    field=f"pesticide_items[{i}].dosage_min",
                    message=(f"《{item.name}》用药量 {item.dosage_min}{entry.dosage_unit or ''} "
                             f"低于登记下限 {lo}{entry.dosage_unit or ''}"),
                ))
            if hi is not None and item.dosage_max is not None and item.dosage_max > hi:
                violations.append(self.violation(
                    field=f"pesticide_items[{i}].dosage_max",
                    message=(f"《{item.name}》用药量 {item.dosage_max}{entry.dosage_unit or ''} "
                             f"高于登记上限 {hi}{entry.dosage_unit or ''}"),
                ))
            if (lo is not None and hi is not None
                    and item.dosage_min is not None and item.dosage_max is not None
                    and item.dosage_min > item.dosage_max):
                violations.append(self.violation(
                    field=f"pesticide_items[{i}].dosage_min",
                    message=f"《{item.name}》剂量区间上下限颠倒：{item.dosage_min} > {item.dosage_max}",
                ))
        return violations
```

三条判定各自独立的理由。**低于下限也拦**是容易被忽视的一条：技术方案 5.3.5 要求剂量照抄知识条目，低于下限意味着模型改了数字，而"少打一点"在农户认知里像是更安全的选择，实际会导致防效不足、农户二次施药、反而增加总用药量与农残风险。**区间颠倒**在数值上合法（两个数字都在区间内）但在语义上不可能，属模型输出畸形，单列一条更易定位。**未给剂量时跳过**，因为"该不该给剂量"由 `R-INTERVAL` 与流程配置决定，本规则只负责"给了的必须合法"。

### R-MAX-USE 每季次数

```python
@register
class MaxUsePerSeasonRule(Rule):
    """R-MAX-USE：每季次数不得超出登记值，且与用药史累计不超限。"""

    rule_id = GateRuleId.MAX_USE.value
    severity: GateSeverity = "block"
    description = "每季使用次数与登记值、用药史累计均不得超限"

    def check(self, ctx: GateContext) -> list[GateViolation]:
        violations: list[GateViolation] = []
        limit = self._configured_limit(ctx)
        used = self._history_used(ctx)
        for i, item in enumerate(ctx.prescription.pesticide_items):
            declared = item.max_uses_per_season
            if declared is not None and limit is not None and declared > limit:
                violations.append(self.violation(
                    field=f"pesticide_items[{i}].max_uses_per_season",
                    message=f"《{item.name}》每季 {declared} 次超出登记上限 {limit} 次",
                ))
            hit = used.get(item.knowledge_id, 0)
            bound = limit if limit is not None else declared
            if bound is not None and hit + 1 > bound:
                violations.append(self.violation(
                    field=f"pesticide_items[{i}].max_uses_per_season",
                    message=(f"《{item.name}》本季已用 {hit} 次，再加本次将超过上限 "
                             f"{bound} 次"),
                ))
        top = ctx.prescription.max_uses_per_season
        if top is not None and limit is not None and top > limit:
            violations.append(self.violation(
                field="max_uses_per_season",
                message=f"处方顶层每季次数 {top} 次超出登记上限 {limit} 次",
            ))
        return violations

    @staticmethod
    def _configured_limit(ctx: GateContext) -> int | None:
        """红线配置给出的次数上限（TEA-03 的 R-MAX-USE 分支）。"""
        raw = ctx.rule_configs.get(GateRuleId.MAX_USE.value, {}).get("limit")
        return int(raw) if isinstance(raw, (int, str)) and str(raw).isdigit() else None

    @staticmethod
    def _history_used(ctx: GateContext) -> dict[str, int]:
        """统计本季用药史中每个 knowledge_id 的已用次数。"""
        out: dict[str, int] = {}
        start = ctx.season_start
        for rec in ctx.medication_history:
            if start is not None and rec.used_on < start:
                continue
            if rec.knowledge_id:
                out[rec.knowledge_id] = out.get(rec.knowledge_id, 0) + 1
        return out
```

**累计口径以 knowledge_id 而非药剂名为键**：同一个农药商品名可能对应多个知识条目（不同剂型、不同厂商），而登记次数的约束对象是有效成分与剂型的组合，因此条目 id 是更精确的键。`used_on < season_start` 的记录被排除，因为"每季"是自然季或作物季，`season_start` 由调用方按流程给定，闸门不自行推断季节边界。

**上限优先取红线配置的 `limit`，其次取条目登记值**：`TEA-03` 的语义是"不得开出未核算每季最多使用次数的方案"，它给出的是一个流程级的更严格上限。当配置与登记值冲突时取**较小者**更安全，这里的实现取 `limit`（配置侧应保证 `limit <= 登记值`，该约束由 T2-06 的载荷校验与人工确认保证）。

### 两条规则与用药史的分工

`R-MAX-USE` 读用药史做**次数累计**，`R-CONFLICT`（T2-39）读同一份用药史做**重复与禁忌**判断。两者分开的原因：次数超限是"量"的问题，处置是换药或推迟；重复用药与禁忌搭配是"质"的问题，处置是停药并转人工。二者在农艺上对应不同的建议，合并成一条会让 `degrade_output` 无法指向正确的话术。

### 拦截频率监控方式

`gate_audit` 按 `rule_id` 分别聚合 `R-DOSAGE` 与 `R-MAX-USE`。

- `R-DOSAGE` 按 `violations[].field` 是否以 `dosage_max` 结尾拆分：`dosage_max` 命中多说明模型倾向"加大用量"，是提示词问题；`dosage_min` 命中多说明模型倾向"减量保守"，属模型对不确定性的过补偿，可考虑改为 degrade。
- `R-MAX-USE` 拆分 `_configured_limit` 命中与 `_history_used` 命中：前者说明药剂选择阶段未受 `limit` 约束（处方智能体的候选过滤有漏），后者说明档案用药史未被检索侧使用（T2-21 的 `_passes_history` 未生效）。
- 两条规则的命中数都应与季节相关：春耕前后应上抬，淡季应回落。若全年持平，需检查 `season_start` 是否恒为 `None` 导致累计口径失效。
