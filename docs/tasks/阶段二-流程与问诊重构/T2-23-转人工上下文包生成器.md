# T2-23 转人工上下文包生成器

## 这一项要做什么

在 `app/agent/agents/handoff.py` 中实现转人工上下文包生成器，把四类必须转人工的情形统一为一份农户可携带的上下文摘要（问题描述、已确认信息、观察要点、已排除项）。它让"建议咨询农技站"这条兜底路径真正有用：不是把农户推开，而是给他一份病历。 四类情形的触发点不同但输出结构相同，仅内容侧重不同。上下文包是正常业务结果而非错误响应，接口层用 200 加 `handoff` 字段表达（技术方案 13.2），本项负责生成这份字段的内容。

## 前置依赖

- 依赖 T2-19：必须已提供 `DiagnosisResult`，超边界与连续未收敛的判定结果从这里来；依赖 T2-08：必须已提供 `ConsultationState` 与槽位读取；依赖 T2-12：必须已提供 `ContactInfo`、`ReportDecision`，法定报告情形要带联系方式；依赖 T2-11：必须已提供 `GateResult` 与 `Prescription`，安全拦截情形要带降级说明；依赖 T2-02：必须已提供流程配置的 `slot_spec` 与 `terminology.colloquial_map`；外部条件：联系方式与朗读入口的接入由 T4-04 与 T3 系列提供

## 实现要点

### 上下文包结构

```python
class HandoffReason(str, Enum):
    OUT_OF_SCOPE = "out_of_scope"          # 超出能力边界
    SAFETY_BLOCK = "safety_block"          # 安全拦截（degrade 或 block）
    NOT_CONVERGED = "not_converged"        # 连续未收敛
    LEGAL_REPORT = "legal_report"          # 法定报告义务

class HandoffObservation(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)
    text: str
    source: Literal["user_answer", "sensor", "image", "diagnosis_basis"] = "user_answer"

class HandoffPackage(BaseModel):
    """转人工上下文包。农户可携带到农技站。"""
    model_config = ConfigDict(extra="forbid", frozen=True)
    reason: HandoffReason
    headline: str                                  # 一句话说明为什么转人工
    problem_summary: str                           # 问题描述
    confirmed_facts: dict[str, str] = {}           # 已确认信息，键为口语化标签
    observations: list[HandoffObservation] = []    # 观察要点
    excluded: list[str] = []                       # 已排除项
    suggested_questions: list[str] = []            # 建议向农技人员问的问题
    contacts: list[ContactInfo] = []
    mandatory_actions: list[str] = []              # 法定报告情形的强制动作
    voice_text: str                                # 供朗读的整段文本
    consult_summary_url: str | None = None         # 可分享的问诊摘要链接
    @model_validator(mode="after")
    def _legal_report_needs_actions(self) -> "HandoffPackage":
        if self.reason is HandoffReason.LEGAL_REPORT and not self.mandatory_actions:
            raise ValueError("法定报告情形必须给出强制动作")
        return self
    @model_validator(mode="after")
    def _headline_not_blank(self) -> "HandoffPackage":
        if not self.headline.strip():
            raise ValueError("headline 不得为空")
        return self
```

`confirmed_facts` 的键用**口语化标签**而不是槽位 key，因为农户要读给农技人员听，`tea_last_pick` 这种标识没有意义，键的生成要过 `display_label` 与 `colloquial_map`。`voice_text` 必填，对应技术方案 6.7 的 A5 假设落地：转人工引导文案同时提供朗读按钮，照顾不便阅读的农户，因此上下文包在生成时就准备好整段可朗读文本。

### 四类情形的内容侧重

| 情形 | headline | 内容侧重 | 依据 |
| --- | --- | --- | --- |
| 超出能力边界 | 这个问题超出我能给准建议的范围 | 可自行观察的要点、建议问的问题 | 4.2.2、6.3 兜底四 |
| 安全拦截 | 这个方案不建议自己动手，建议先问农技站 | 解释为什么不建议自行用药 | 6.2 第二层 |
| 连续未收敛 | 问了这几轮还没能确定，建议带样本去农技站 | 已确认信息、还缺什么 | 4.2.2 |
| 法定报告义务 | 需要马上报告，下面是该做的事 | 立即隔离、消毒、报告加联系入口 | 5.7、6.3 兜底四 |

四种情形输出结构相同，只有字段填充重点不同，这样接口层只需一个 `handoff` 字段类型，前端渲染路径统一，避免"转人工被当成异常从而在前端被吞掉"。

### 构造入口

```python
class HandoffBuilder:
    def __init__(self, contacts: ContactDirectory, summarizer: SummaryLinkBuilder) -> None:
        self._contacts = contacts
        self._summarizer = summarizer
    def build( self, reason: HandoffReason, state: ConsultationState, config: ProcessConfig, *, gate_result: GateResult | None = None,
        report_decision: ReportDecision | None = None,
        region_code: str | None = None,
    ) -> HandoffPackage:
        base = self._common_sections(state, config)
        match reason:
            case HandoffReason.OUT_OF_SCOPE:
                return self._out_of_scope(base, state, config, region_code)
            case HandoffReason.SAFETY_BLOCK:
                return self._safety_block(base, state, config, gate_result, region_code)
            case HandoffReason.NOT_CONVERGED:
                return self._not_converged(base, state, config, region_code)
            case HandoffReason.LEGAL_REPORT:
                return self._legal_report(base, state, config, report_decision, region_code)
        raise ValueError(f"未处理的转人工情形: {reason}")
```

用 `match` 穷举四种情形并在末尾抛异常，保证新增情形时不会静默走某个分支。Python 3.11 的 `match` 语句与全局约定的版本要求一致。

### 公共部分与术语口语化

```python
    def _common_sections(self, state: ConsultationState, config: ProcessConfig) -> dict[str, Any]:
        confirmed: dict[str, str] = {}
        for key, slot in (state.get("slots") or {}).items():
            if slot.status != "filled" or not slot.value:
                continue
            spec = config.slot_spec(key)
            if spec is None:
                continue
            confirmed[spec.display_label] = self._colloquialize(slot.value, config)
        return {"confirmed_facts": confirmed}
    def _colloquialize(self, text: str, config: ProcessConfig) -> str:
        """术语口语化替换。展示层与朗读文本都必须过这一步。"""
        out = text
        for term, plain in config.terminology.colloquial_map.items():
            out = out.replace(term, plain)
        return out
```

技术方案 9.1 明确"展示层渲染时必须经过 `colloquial_map` 替换"。上下文包要拿到农技站给人看，若出现"叶发病率"这类内部术语，农户读不出来，这份材料就失去意义。

### 未收敛与法定报告的构造

```python
    def _not_converged(self, base, state, config, region_code) -> HandoffPackage:
        missing = self._missing_slots(state, config)
        headline = "问了这几轮还没能确定，建议带样本去农技站"
        observations = [HandoffObservation(text=f"还缺这一项：{label}") for label in missing]
        return HandoffPackage(reason=HandoffReason.NOT_CONVERGED, headline=headline, problem_summary=self._problem_summary(state),
            confirmed_facts=base["confirmed_facts"], observations=observations,
            excluded=self._excluded_of(state), suggested_questions=self._suggested_questions(missing),
            contacts=self._contacts.for_region(region_code), mandatory_actions=[],
            voice_text=self._compose_voice(headline, base["confirmed_facts"], observations),
            consult_summary_url=self._summarize(state), )
    def _legal_report(self, base, state, config, decision, region_code) -> HandoffPackage:
        actions = list(decision.mandatory_actions) if decision else ["立即隔离发病猪只", "对栏舍消毒", "联系当地畜牧兽医部门报告", ]
        contacts = (list(decision.contacts) if decision and decision.contacts else self._contacts.for_region(region_code))
        headline = "需要马上报告，下面是该做的事"
        return HandoffPackage(reason=HandoffReason.LEGAL_REPORT, headline=headline, problem_summary=self._problem_summary(state),
            confirmed_facts=base["confirmed_facts"], observations=self._signal_observations(state),
            excluded=[], suggested_questions=[], contacts=contacts, mandatory_actions=actions,
            voice_text=self._compose_voice(headline, base["confirmed_facts"], actions),
            consult_summary_url=self._summarize(state), )
```

未收敛情形的 `observations` 列"还缺这一项"而不是"我不知道"，让农户知道该补什么。法定报告情形的 `excluded` 为空是刻意的：技术方案 6.7 明确疫情报告"不做责任或疫情的最终认定"，因此没有已排除项可述。`report_decision` 为 None 时用一组固定兜底动作，保证这条路径在守卫未被调用时也能产出可执行内容。

### 安全拦截的构造

```python
    def _safety_block(self, base, state, config, gate: GateResult | None, region_code) -> HandoffPackage:
        why = self._explain_block(gate)
        headline = "这个方案不建议自己动手，建议先问农技站"
        observations = [HandoffObservation(text=why, source="diagnosis_basis")]
        return HandoffPackage(reason=HandoffReason.SAFETY_BLOCK, headline=headline, problem_summary=self._problem_summary(state),
            confirmed_facts=base["confirmed_facts"], observations=observations,
            excluded=self._excluded_of(state),
            suggested_questions=["我这种情况可以用什么药", "有没有更安全的替代办法", "如果不打药，还能做什么"],
            contacts=self._contacts.for_region(region_code), mandatory_actions=[],
            voice_text=self._compose_voice(headline, base["confirmed_facts"], observations),
            consult_summary_url=self._summarize(state), )
    def _explain_block(self, gate: GateResult | None) -> str:
        """解释为什么不建议自行用药。只做原因归类，不得输出被拦截的具体方案。"""
        if gate is None:
            return "这个方案本身可能不安全，具体原因已记录，到农技站时可以直接说明本次咨询。"
        if not gate.process_redlines_loaded:
            return "这条流程的安全要求暂时没有完整加载，因此不能给用药建议。"
        fields = {v.field for v in gate.violations}
        if any("pesticide" in f for f in fields):
            return "推荐里的药剂不适合您这个作物或这个时期，不能照这个方案用药。"
        if any("interval" in f for f in fields):
            return "这个方案里的安全间隔期与您的采摘或出栏计划对不上，不能照这个方案用药。"
        return "这个方案没有通过安全校验，不能照这个方案用药。"
```

`_explain_block` 的关键是**解释原因但不复述被拦截的方案**。产品说明书 6.2 明确"校验不通过时，输出降级为建议联系当地农技站，而不是修改后输出"。若解释里带上"不建议使用某某药剂"，等于变相输出了被拦截的内容，反而给了农户自己判断的机会。

### 已确认、已排除与朗读文本

```python
    def _problem_summary(self, state: ConsultationState) -> str:
        first = (state.get("messages") or [{}])[0]
        return (state.get("user_message") or first.get("content") or "")[:200]
    def _excluded_of(self, state: ConsultationState) -> list[str]:
        diagnosis = state.get("diagnosis")
        return list((diagnosis or {}).get("excluded") or [])
    def _missing_slots(self, state: ConsultationState, config: ProcessConfig) -> list[str]:
        labels: list[str] = []
        for spec in sorted(config.required_slots, key=lambda s: s.ask_order):
            if not spec.required:
                continue
            slot = (state.get("slots") or {}).get(spec.key)
            if slot is None or slot.status == "missing":
                labels.append(spec.display_label)
        return labels
    def _compose_voice(self, headline: str, confirmed: dict[str, str], items: list[HandoffObservation] | list[str]) -> str:
        """组装整段可朗读文本。句子短，避免书面长句。"""
        lines = [headline]
        if confirmed:
            facts = "，".join(f"{k}{v}" for k, v in list(confirmed.items())[:5])
            lines.append(f"已经了解到的情况是：{facts}。")
        for item in items[:5]:
            lines.append(f"{item.text if isinstance(item, HandoffObservation) else item}。")
        return "".join(lines)
```

`_excluded_of` 从判定结果读取已排除项，这是技术方案 6.7 列出的上下文包四项内容之一。已排除项对农技人员很有价值：它说明农户已经排除了哪些可能，避免重复排查。朗读文本限制在五条事实与五条要点以内，句子短，因为这段文本会被完整读完，长度必须可控；上限值属工程参数，可调整但需同步更新测试。

### 与接口层的对接

`HandoffPackage` 序列化后放入 `ChatResponse.handoff` 字段，接口层用 200 状态码返回。`consult_summary_url` 指向一份可分享的问诊摘要（由注入的 `SummaryLinkBuilder` 生成），技术方案 6.7 指出这个设计"提升了建议咨询农技站这条兜底路径的实际价值——不是把农户推开，而是给他一份病历"。链接的生成与存储实现在 T2-33 配套，本项只调用注入的接口。
