# T2-03 流程配置加载器与校验

## 这一项要做什么

在 `app/process_config/loader.py` 中实现"从 YAML 文件到 `ProcessConfig` 对象"的加载与校验链路，并暴露 `load_process_config(process_id)` 与 `load_all_configs()` 两个入口。加载器要一次性完成语法解析、模型校验与跨字段一致性检查，让任何配置错误都在进程启动时报出来，而不是在农户提问时才暴露。

技术方案 8.4 明确"红线缺失即不可用"。加载器是这条规则的执行点：七条流程中任一条的红线为空、缺失或校验失败，该流程在路由表中即被标记为不可用，入口处直接返回转人工引导，禁止以通用规则代替。这个动作只做检测与标记，不做修复。

## 前置依赖

- 依赖 T2-02：必须已提供 `ProcessConfig` 及其全部子模型

## 实现要点

### 加载清单与入口函数

```python
from importlib.resources import files

SEEDS_PACKAGE = "app.process_config.seeds"
CONFIG_FILENAME = "{process_id}.yaml"


def load_process_config(process_id: ProcessId) -> ProcessConfig:
    """按流程标识加载单份配置。任何失败都抛 ConfigLoadError。"""
    path = files(SEEDS_PACKAGE).joinpath(CONFIG_FILENAME.format(process_id=process_id.value))
    if not path.is_file():
        raise ConfigLoadError(f"流程配置缺失: {process_id.value}")
    try:
        raw = yaml.safe_load(path.read_text(encoding="utf-8"))
    except yaml.YAMLError as exc:
        raise ConfigLoadError(f"YAML 语法错误: {process_id.value}") from exc
    if not isinstance(raw, dict):
        raise ConfigLoadError(f"配置根节点必须是映射: {process_id.value}")
    try:
        config = ProcessConfig.model_validate(raw)
    except ValidationError as exc:
        raise ConfigLoadError(f"配置校验失败: {process_id.value}: {exc.error_count()} 项") from exc
    _check_integrity(config)
    return config


def load_all_configs() -> dict[ProcessId, ProcessConfig]:
    """加载七条流程配置。红线为空的流程不进入返回值，由调用方标记不可用。"""
    available: dict[ProcessId, ProcessConfig] = {}
    for pid in ProcessId:
        try:
            available[pid] = load_process_config(pid)
        except ConfigLoadError as exc:
            logger.error("process config unavailable", extra={"process_id": pid.value, "reason": str(exc)})
    return available
```

`load_all_configs` 刻意不抛异常而是跳过：一条流程的配置坏了不应让整个服务起不来，只应让那一条流程不可用。但跳过的每一条都必须写 ERROR 级结构化日志，由启动自检（T1-08）汇总后在健康检查里暴露。

### 跨字段一致性检查

```python
def _check_integrity(config: ProcessConfig) -> None:
    """模型层查不出的跨字段问题在这里拦截。"""
    problems: list[str] = []

    # 1. 红线不可缺省（技术方案 8.4）
    if not config.redlines:
        problems.append("redlines 为空，该流程必须处于不可用状态")

    # 2. 槽位 key 唯一
    keys = [s.key for s in config.required_slots]
    duplicates = {k for k in keys if keys.count(k) > 1}
    if duplicates:
        problems.append(f"必问槽位 key 重复: {sorted(duplicates)}")

    # 3. owner 必须在已实现的智能体集合内
    known_owners = {"field_observer", "interviewer", "profile_loader"}
    unknown = {s.owner for s in config.required_slots} - known_owners
    if unknown:
        problems.append(f"槽位 owner 未实现: {sorted(unknown)}")

    # 4. 仅有兜底流程允许 panel_enabled 为 false 且 confusable_items 为空
    if config.panel_enabled and not config.confusable_items:
        problems.append("启用并行会诊但未配置易混淆项")

    # 5. 输出模板的必含小节必须属于小节顺序
    extra_sections = set(config.output_template.required_sections) - set(config.output_template.section_order)
    if extra_sections:
        problems.append(f"必含小节不在 section_order 内: {sorted(extra_sections)}")

    # 6. 时机判据与回访策略的 id 唯一
    for label, ids in (("timing_rules", [r.id for r in config.timing_rules]),):
        dup = {i for i in ids if ids.count(i) > 1}
        if dup:
            problems.append(f"{label} id 重复: {sorted(dup)}")

    if problems:
        raise ConfigIntegrityError(config.process_id.value, problems)
```

第 5 条最容易漏。输出模板的 `section_order` 决定处方卡的段落顺序，`required_sections` 决定哪些段落不许为空；若必含小节不在顺序表里，渲染时会静默丢段落，属于"配置写了但没生效"。

第 4 条来自技术方案 6.4：并行会诊只为茶、辣椒、杂草三条流程启用，选择依据正是这三条流程的易混淆项最多。启用却不配易混淆项，等于让 T2-20 的聚合器无判据可依。

### 油菜流程的专用检查

```python
def _check_rapeseed_restriction(config: ProcessConfig) -> None:
    """产品说明书 5.4：补齐调研前，油菜流程不得输出药剂推荐类内容。"""
    if config.process_id is not ProcessId.RAPESEED:
        return
    has_ban = any("药剂推荐" in item.desc for item in config.redlines)
    if not has_ban:
        raise ConfigIntegrityError(config.process_id.value, ["缺少 RAPE-01 禁止输出药剂推荐红线"])
```

这份限制的落实有两道：加载时必须有这条红线，闸门运行时靠 `R-REDLINE` 拦截。双保险的理由是知识库中可能误入油菜药剂条目，配置层的声明不能作为唯一的防线。

### 缓存与失效

```python
_CONFIG_CACHE: dict[ProcessId, ProcessConfig] = {}
_CACHE_LOCK = threading.Lock()


def get_process_config(process_id: ProcessId, *, refresh: bool = False) -> ProcessConfig:
    """带缓存的读取入口。refresh=True 时重载（供 T2-05 热加载调用）。"""
    with _CACHE_LOCK:
        if refresh or process_id not in _CONFIG_CACHE:
            _CONFIG_CACHE[process_id] = load_process_config(process_id)
        return _CONFIG_CACHE[process_id]
```

`get_process_config` 是给智能体使用的入口，`load_process_config` 是给启动自检与热加载使用的入口。缓存用锁保护，因为热加载可能由另一个线程触发。是否重新加载由 T2-05 决定，本项只提供 `refresh` 开关。

### 校验失败时的行为

加载失败一律抛异常，不返回默认配置。若在这里"给一份空壳配置让它跑起来"，所有下游的 `None` 检查都会退化成"反正不会为 None"的假设，反而是引入不可控状态。配置不可用应该在加载阶段就终结，由路由层把该流程指向 `handoff`。
