# T2-44 表述语气与无数据支撑规则

## 这一项要做什么

在 `app/gate/rules/presentation.py` 中实现两条与"怎么说"和"有没有依据"有关的规则：`R-CAUTION`（等级 `warn`）要求输出不得为强制命令语气，必须保留建议性与免责表述；`R-NO-DATA`（等级 `block`）要求处方结构中的任何数值字段都必须在 `facts_provenance` 中登记。两者合并在一个模块，因为它们都针对"表述层"的问题，且 `R-NO-DATA` 复用 T2-41 的正则与豁免集合。`R-CAUTION` 是 8.2 中唯一以 `warn` 为等级的规则。

## 前置依赖

- 依赖 T2-34：必须已提供 `Rule` 基类、`register`、`GateContext`、`GatePayload`、`GateViolation`、`GateRuleId`。
- 依赖 T2-41：必须已提供 `UNIT_PATTERN` 与 `STRUCTURAL_EXEMPTIONS`；本项**复用**这两个常量，不另写一份。
- 依赖 T2-11：必须已提供 `Prescription.numeric_paths()`（列出所有需溯源的数值字段路径）与 `facts_provenance`。
- 依赖 T2-02 与 T2-04：流程配置的 `output_template.required_sections` 与 `terminology.colloquial_map` 是本项判断"必含表述"的依据；语气检测的禁用短语来自红线 `forbidden_phrases`（T2-42 已用同一份清单拦截，本项针对的是"未达到命令语气阈值但含强制口吻"的情形）。
- 外部条件：语气措辞与免责表述为产品与农技共同确认范围（全局约定第八节）。

## 实现要点

### R-CAUTION 表述语气（warn）

```python
@register
class CautionToneRule(Rule):
    """R-CAUTION：输出不得为强制命令语气，须保留建议性与免责表述。

    等级为 warn：语气问题不致命，但会改变农户的风险感知。
    强制命令语气会让农户把"建议"当作"指令"执行，出事时责任归属模糊。
    """

    rule_id = GateRuleId.CAUTION.value
    severity: GateSeverity = "warn"
    description = "输出不得为强制命令语气"

    REQUIRED_SOFTENERS: ClassVar[tuple[str, ...]] = (
        "建议", "可以", "如果", "建议咨询", "可考虑", "不妨", "必要时",
    )

    def check(self, ctx: GateContext) -> list[GateViolation]:
        violations: list[GateViolation] = []
        text = ctx.payload.rendered_text
        for pattern in IMPERATIVE_PATTERNS:
            for match in pattern.finditer(text):
                violations.append(self.violation(
                    field="gate_payload.rendered_text",
                    message=f"出现强制命令语气「{match.group(0)}」，应改为建议性表述",
                ))
        if not any(s in text for s in self.REQUIRED_SOFTENERS):
            violations.append(self.violation(
                field="gate_payload.rendered_text",
                message="整段建议未出现任何建议性措辞（建议/可以/如果…），确定性表述偏高",
            ))
        return violations
```

`IMPERATIVE_PATTERNS` 用正则而非关键词表，放在 `app/gate/constants.py`：

```python
# app/gate/constants.py
# 强制命令语气模式：命中即 warn。仅收录明确的命令式表达，
# 不使用"必须"这类在安全提示中合法的词（"必须等待 7 天"是正确表述）。
IMPERATIVE_PATTERNS: tuple[re.Pattern[str], ...] = (
    re.compile(r"立即(?:大量)?(?:施用|喷洒|使用|灌)"),
    re.compile(r"务必(?:马上|立刻|立即)"),
    re.compile(r"直接(?:用|打|喷)(?:就|即可)"),
    re.compile(r"不用(?:问|管|考虑)"),
    re.compile(r"照做(?:就行|即可)"),
)
```

第一条模式（`立即大量施用` 之类）由 T2-42 的 `forbidden_phrases` 也可能拦到，两处都不删：`R-REDLINE` 拦的是"配置里显式列出的禁用短语"，本规则拦的是"满足模式但未进配置清单"的表述。前者随配置演进，后者是兜底。

`REQUIRED_SOFTENERS` 的第二条判定（整段无建议性措辞）容易被忽视：只查强制词会漏掉"无动词的断言式表述"（如"三天后采摘"），这类表述同样缺少建议性。该判定是 warn 级，命中后不改变 decision（`warn` 不导致 degrade 也不导致 block），只写审计留痕，供 14.3 的线上指标观察语气漂移。

### R-NO-DATA 无数据支撑数字（block）

```python
@register
class NoDataSupportRule(Rule):
    """R-NO-DATA：处方结构中的数值字段必须在 facts_provenance 中登记。

    与 R-PROVENANCE 的分工：本规则是正向核对（从数值字段找漏登记），
    R-PROVENANCE 是反向扫描（从展示文本找多出来的数字）。两者互补，缺一不可。
    """

    rule_id = GateRuleId.NO_DATA.value
    severity: GateSeverity = "block"
    description = "不得出现无事实来源的数值字段"

    def check(self, ctx: GateContext) -> list[GateViolation]:
        violations: list[GateViolation] = []
        provenance = ctx.prescription.facts_provenance
        for path in ctx.prescription.numeric_paths():
            if path in provenance and str(provenance[path]).strip():
                continue
            violations.append(self.violation(
                field=path,
                message=f"数值字段 {path} 缺少事实来源登记",
            ))
        violations.extend(self._scan_text(ctx, provenance))
        return violations

    @staticmethod
    def _scan_text(ctx: GateContext, provenance: dict[str, str]) -> list[GateViolation]:
        """第二道：展示文本中带单位的数字若既无 token 登记，其值也不在 provenance 来源中。"""
        out: list[GateViolation] = []
        registered_sources = set(provenance.values())
        for match in UNIT_PATTERN.finditer(ctx.payload.rendered_text):
            token = f"{match.group(1)}{match.group(2)}"
            if token in ctx.registered_numeric_tokens():
                continue
            if match.group(1) in STRUCTURAL_EXEMPTIONS:
                continue
            if any(match.group(1) in str(s) for s in registered_sources):
                continue
            out.append(GateViolation(
                rule_id=GateRuleId.NO_DATA.value, severity="block",
                message=f"文本数值「{token}」无事实来源登记",
                field="gate_payload.rendered_text",
            ))
        return out
```

`numeric_paths()` 来自 T2-11，返回处方的全部数值字段路径（顶层 `safety_interval_days`、`max_uses_per_season`，以及每个药剂条目的 `dosage_min`、`dosage_max`、`safety_interval_days`、`max_uses_per_season`）。正向核对只查这些路径，不查 `facts_provenance` 里多出来的键——多出的键说明处方层登记了不存在的字段，属另一个问题，由 T2-11 的契约校验处理。

### 两条规则的等级差异与 decision 影响

| 规则 | 等级 | 产生违规时 decision | 为什么 |
| --- | --- | --- | --- |
| `R-CAUTION` | `warn` | 仍为 `allow`（`_decide` 只看 block 与 degrade） | 语气问题不影响事实正确性，不应阻断服务 |
| `R-NO-DATA` | `block` | `block` | 无来源的数字直接违反产品说明书 6.4 第 4 条 |

`R-CAUTION` 的 `warn` 不改变 decision 是刻意设计：若 `warn` 也导致降级，一次措辞偏差就会让农户拿不到处方，代价远大于收益。`warn` 的价值在于审计留痕与 14.3 的语气漂移监控。

### 与 T2-42 的边界

`R-REDLINE` 扫的是"配置里显式列出的禁用短语"（如"可放心随意加大用量"），`R-CAUTION` 扫的是"命令语气模式"。两者可能对同一句话都报警，这是可接受的：`R-REDLINE` 产生 block，`R-CAUTION` 产生 warn，引擎以 block 优先，warn 的违规仍会进审计表供复盘。实现上不做去重，因为去重需要判断"是否同一处命中的同一种问题"，这个判断在措辞层无法可靠完成。

### 拦截频率监控方式

两条规则分开监控。

**`R-CAUTION`（warn）**

- **命中数不设上限也不设下限**，它是一个观察指标而非门禁指标。按 `IMPERATIVE_PATTERNS` 的模式分组统计：某条模式长期高发，说明提示词里对该场景缺少约束，应把该模式的正确表述写进提示词示例。
- **`REQUIRED_SOFTENERS` 未命中的比例**单独看：占比上升说明模型输出趋于断言化，与 `ConfidenceLevel` 为 `uncertain` 的场景交叉观察，uncertain 场景下断言化输出的比例应接近 0。
- **与阻断率的区分**：`R-CAUTION` 命中不应出现在任何"闸门拦截率"的计算里（14.3 的定义是基于 `passed=false`），否则会虚高。监控脚本要按 `severity` 过滤。

**`R-NO-DATA`（block）**

- **命中数必须为 0**，与 `R-PROVENANCE` 同源。该规则是对契约校验的二次确认：T2-11 的 `_provenance_covers_numbers` 若正常工作，本规则不应有任何命中；一旦命中，说明有人绕过了契约构造（例如直接改 state dict），属实现缺陷，立即告警。
- **与 `R-PROVENANCE` 的比值**是最有诊断价值的指标：`R-NO-DATA` 为 0 而 `R-PROVENANCE` 非 0，说明结构完整但文本有杂音（提示词问题）；两者都非 0，说明处方层整体没填 `facts_provenance`（上游缺陷）；两者都为 0 且展示文本非空，属正常。
- **豁免项的独立统计**：`STRUCTURAL_EXEMPTIONS` 中任一项在本规则里被大量豁免，与 T2-41 的同一指标合并看，任一规则里该豁免项出现频次异常都需人工介入。
