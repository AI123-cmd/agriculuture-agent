# T2-05 流程配置版本化与热加载

## 这一项要做什么

在 `app/process_config/registry.py` 中实现流程配置的版本注册表与热加载机制。每次配置变更插入新版本而非覆盖旧版本，闸门与问诊在会话开始时记录所使用的 `config_version`，使任意一次历史问诊都能按当时生效的配置复现。

热加载的用途不是"随时改随时生效"，而是让配置更新不必重启服务，同时保持一次会话内的配置恒定。配置加载失败时必须保留上一生效版本继续服务，并把失败写入告警，绝不出现"配置更新失败导致流程整体不可用"的情况。

## 前置依赖

- 依赖 T2-03：必须已提供 `load_process_config`、`get_process_config` 与缓存失效入口
- 依赖 T2-07：必须已提供 `process_config` 表与 `ProcessConfigRepository`，热加载时的版本比对以数据库为准
- 外部环境：PostgreSQL 16+，Redis 7+（跨进程广播热加载信号）
- 与 T2-30 的关系：检查点器负责状态持久化，本项只负责配置版本，二者都要求"会话可回溯"

## 实现要点

### 版本引用值对象

```python
class ConfigVersionRef(BaseModel):
    """一次会话在开始时刻固定的配置版本引用。"""
    model_config = ConfigDict(extra="forbid", frozen=True)

    process_id: ProcessId
    version: int
    content_hash: str          # 配置规范化 JSON 的 sha256 前 12 位
    loaded_at: datetime

    def matches(self, other: "ConfigVersionRef") -> bool:
        return self.process_id == other.process_id and self.content_hash == other.content_hash
```

`version` 是人工递增的语义版本号，`content_hash` 是内容的客观指纹。二者都要存：`version` 用于对人解释"这是第几版"，`content_hash` 用于判定"内容是否真的变了"。若只比对 `version`，一次忘记改版本号的编辑会被热加载忽略，问题很难发现。

### 注册表结构

```python
class ProcessConfigRegistry:
    """流程配置版本注册表。进程内单例，读取路径无锁。"""

    def __init__(self) -> None:
        self._active: dict[ProcessId, ProcessConfig] = {}
        self._refs: dict[ProcessId, ConfigVersionRef] = {}
        self._history: dict[ProcessId, deque[ConfigVersionRef]] = defaultdict(lambda: deque(maxlen=10))
        self._lock = asyncio.Lock()
        self._unavailable: dict[ProcessId, str] = {}   # 流程 → 不可用原因

    def active(self, process_id: ProcessId) -> ProcessConfig:
        """读取当前生效配置。未加载或不可用时抛 ConfigUnavailableError。"""
        config = self._active.get(process_id)
        if config is None:
            raise ConfigUnavailableError(process_id, self._unavailable.get(process_id, "未加载"))
        return config

    def is_available(self, process_id: ProcessId) -> bool:
        return process_id in self._active

    def unavailable_reason(self, process_id: ProcessId) -> str | None:
        return self._unavailable.get(process_id)

    def ref_of(self, process_id: ProcessId) -> ConfigVersionRef:
        return self._refs[process_id]
```

`active` 读的是普通字典，不加锁。热加载写入时整体替换字典条目（Python 的字典单条赋值是原子的），因此读取方永远看到完整的一份配置，不会读到半更新的中间状态。这个设计把锁只留在写入路径上，避免每次智能体读取配置都要竞争锁。

### 加载与预检

```python
async def bootstrap(registry: ProcessConfigRegistry, session_factory) -> None:
    """启动时加载：先读数据库，再以 seeds 兜底。"""
    async with session_factory() as session:
        stored = await ProcessConfigRepository(session).latest_per_process()
    for pid in ProcessId:
        try:
            if (row := stored.get(pid)) is not None:
                config = ProcessConfig.model_validate(row.config_json)
            else:
                config = load_process_config(pid)
        except Exception as exc:                      # noqa: BLE001
            registry.mark_unavailable(pid, str(exc))
            logger.error("process config bootstrap failed", extra={"process_id": pid.value})
            continue
        registry.activate(config)
```

数据库优先、seeds 兜底的理由是：热加载写入的是数据库，若进程重启后从 seeds 读，会把线上已经生效的修订退回到文件版本。seeds 只在数据库尚无记录时（首次部署）作为初始数据源。

### 热加载循环

```python
async def watch_and_reload(registry: ProcessConfigRegistry, session_factory, interval: int) -> None:
    """周期性比对版本，有变化则整体替换。异常不得中断循环。"""
    while True:
        await asyncio.sleep(interval)
        for pid in list(ProcessId):
            try:
                await _reload_one(registry, session_factory, pid)
            except Exception as exc:                  # noqa: BLE001
                logger.error("hot reload failed, keep previous", extra={"process_id": pid.value})
                continue


async def _reload_one(registry: ProcessConfigRegistry, session_factory, pid: ProcessId) -> None:
    async with session_factory() as session:
        row = await ProcessConfigRepository(session).latest(pid)
    if row is None:
        return
    incoming = ProcessConfig.model_validate(row.config_json)
    current = registry._refs.get(pid)
    incoming_ref = build_ref(incoming)
    if current is not None and current.matches(incoming_ref):
        return                                        # 内容未变，不动
    registry.activate(incoming)                       # 整体替换
    logger.info("process config reloaded", extra={"process_id": pid.value, "version": incoming.version})
```

`_reload_one` 的每一步都可能失败（数据库不可用、JSON 损坏、模型校验不过），全部捕获后记录并 `continue`。这里刻意不是 fail-closed：配置热加载失败的正确反应是继续用上一生效版本，而不是让流程不可用。若首次加载就失败（启动阶段），那才标记不可用。

### 会话内的版本固定

```python
def pin_version(registry: ProcessConfigRegistry, process_id: ProcessId, state: ConsultationState) -> ConfigVersionRef:
    """在会话开始时固定版本，写入 state 与 consultation 表。"""
    ref = registry.ref_of(process_id)
    state["config_version"] = ref.version
    state["config_hash"] = ref.content_hash
    return ref
```

版本固定发生在 `triage` 节点完成后、`observe` 之前。会话中途即使热加载把配置换掉，`observe` 到 `prescribe` 仍用 `triage` 时刻的那一份。实现方式是在图组装的节点工厂里把配置实例闭包进节点，而不是在节点内部每次现取——这一点由 T2-26 的工厂函数保证，本项只负责提供固定值。

### 并发与不可用标记

```python
def mark_unavailable(self, process_id: ProcessId, reason: str) -> None:
    self._active.pop(process_id, None)
    self._unavailable[process_id] = reason

def activate(self, config: ProcessConfig) -> None:
    self._active[config.process_id] = config
    self._refs[config.process_id] = build_ref(config)
    self._history[config.process_id].appendleft(self._refs[config.process_id])
    self._unavailable.pop(config.process_id, None)
```

`mark_unavailable` 与 `activate` 是仅有的两个写入口，前者只由启动引导与红线完整性校验失败调用。热加载过程中**不调用** `mark_unavailable`，因为一份坏配置不应该让正在服务的流程立刻停摆。

`_history` 保留最近十版，供排障时回答"这条流程在过去两周换过几版配置"。

### 与可观测性的对接

每次 `activate` 与 `mark_unavailable` 都要：
- 打一条 INFO 日志，字段含 `process_id`、`version`、`content_hash`
- 在指标中记录 `process_config_active_version{process_id}`，值取 `version`
- 在 `gate_audit.config_version` 中记录判定时刻的版本（由 T2-46 写入）

版本号进入审计表后，任何一次拦截都能回答"当时生效的是哪一版红线配置"，这是 8.4 要求"任何一次拦截都可追溯到配置版本"的落地方式。
