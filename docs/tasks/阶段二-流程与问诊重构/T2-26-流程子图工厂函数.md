# T2-26 流程子图工厂函数

## 这一项要做什么

把七条流程共用的五个节点（observe / interview / verify / judge / prescribe）写成"工厂函数 + 配置"的形式，落在 `app/agent/graph/factories.py`。方案 7.4 明确：子图文件本身极薄，只负责把配置注入通用节点，差异全部来自 `ProcessConfig`。这是"流程配置是数据而非代码"的核心落地点——新增第八条流程时，改动量被限定为一份 YAML + 约 15 行子图文件 + 路由表注册一行，不触碰任何智能体实现，不触碰闸门规则。

## 前置依赖

- T2-03 流程配置加载器与校验：提供 `load_process_config(ProcessId) -> ProcessConfig`。
- T2-02 流程配置 Pydantic 模型：`ProcessConfig`、`SlotSpec`、`RequirementSpec` 字段名。
- T2-16 问诊智能体 Interviewer：提供 `Interviewer.run(state, config, prompt)`。
- T2-18 证据核查智能体 Retriever：提供 `Retriever.run(...)`。
- T2-19 判定智能体 Diagnoser：提供 `Diagnoser.run(...)`。
- T2-20 受限并行会诊 Panel：提供 `build_panel_graph(config)`，仅供 panel 启用的流程使用。
- T2-21 处方智能体 Prescriber：提供 `Prescriber.run(...)`，其检索候选来自知识库。
- T2-15 现场采集智能体 FieldObserver：observe 工厂的内部实现。
- T2-13 Agent 基类：工厂产出的节点函数必须走基类的契约校验与降级重试。
- 外部环境：模型网关可用（`USE_MOCK_LLM=true` 可离线）；知识库可检；无数据库直连（守 L2 规则）。

## 实现要点

### 七个工厂函数

| 工厂 | 返回 | config 决定的行为 |
| --- | --- | --- |
| `make_observe_node(config)` | async 节点函数 | 是否需要图片、离线增强追问是否启用、环境事实三级回退口径 |
| `make_interview_node(config)` | async 节点函数 | 必问清单、候选池排序权重、术语口语化映射、每轮问题上限 |
| `make_verify_node(config)` | async 节点函数 | 知识检索的元数据过滤条件（`process_id`、`region_scope`、`status=approved`） |
| `make_judge_node(config)` | async 节点函数 | 易混淆项与决定性特征、`excluded` 强制非空、术语档 |
| `make_prescribe_node(config)` | async 节点函数 | 输出模板、安全间隔期口径、`calendar_source` 是否为空、禁用输出 |
| `make_panel_node(config)` | 编译后的子图或 None | `panel_enabled=False` 时返回 None，子图不注册该节点 |
| `make_handoff_node(config)` | async 节点函数 | 转人工四种情形各自的输出模板（超边界/安全拦截/未收敛/法定报告） |

工厂都用闭包捕获 `config`，返回一个签名统一的节点函数 `async def node(state, runtime) -> dict`。节点内部只与 state 交互，不直接读数据库或进程外资源（守 L2、L4）。

```python
"""通用节点工厂：config 决定行为，节点实现由各智能体提供。"""
from __future__ import annotations

from functools import lru_cache

from app.agent.agents.diagnoser import Diagnoser
from app.agent.agents.field_observer import FieldObserver
from app.agent.agents.interviewer import Interviewer
from app.agent.agents.prescriber import Prescriber
from app.agent.agents.retriever import Retriever
from app.agent.contracts.interview import InterviewBatch
from app.process_config.loader import load_process_config
from app.process_config.models import ProcessConfig
from app.agent.state import ConsultationState, ProcessId


@lru_cache(maxsize=32)
def get_config(process_id: ProcessId, version: int | None = None) -> ProcessConfig:
    """流程配置缓存：同一 (process_id, version) 只加载一次。"""
    return load_process_config(process_id, version=version)


def make_observe_node(config: ProcessConfig):
    observer = FieldObserver(config)

    async def observe(state: ConsultationState, runtime) -> dict:
        return await observer.run(state)

    observe.__name__ = f"observe_{config.process_id.value}"
    return observe


def make_interview_node(config: ProcessConfig):
    interviewer = Interviewer(config)

    async def interview(state: ConsultationState, runtime) -> dict:
        # 候选池由代码筛选（候选池筛选器），模型只在给定范围内生成问题文本
        batch: InterviewBatch = await interviewer.run(state)
        return {
            "pending_questions": [q.model_dump() for q in batch.questions],
            "stage_hint": batch.stage_hint,
            "stage": ConsultStage.INTERVIEW,
        }

    interview.__name__ = f"interview_{config.process_id.value}"
    return interview


def make_verify_node(config: ProcessConfig):
    retriever = Retriever(config)

    async def verify(state: ConsultationState, runtime) -> dict:
        evidence = await retriever.run(state)
        return {"evidence": [e.model_dump() for e in evidence], "stage": ConsultStage.VERIFY}

    verify.__name__ = f"verify_{config.process_id.value}"
    return verify


def make_judge_node(config: ProcessConfig):
    diagnoser = Diagnoser(config)

    async def judge(state: ConsultationState, runtime) -> dict:
        result = await diagnoser.run(state)
        return {"diagnosis": result.model_dump(), "stage": ConsultStage.JUDGE}

    judge.__name__ = f"judge_{config.process_id.value}"
    return judge


def make_prescribe_node(config: ProcessConfig):
    prescriber = Prescriber(config)

    async def prescribe(state: ConsultationState, runtime) -> dict:
        prescription = await prescriber.run(state)
        return {"prescription": prescription.model_dump(), "stage": ConsultStage.PRESCRIBE}

    prescribe.__name__ = f"prescribe_{config.process_id.value}"
    return prescribe


def make_panel_node(config: ProcessConfig):
    """并行会诊子图：仅 panel_enabled 的流程返回非 None。"""
    if not config.panel_enabled:
        return None
    from app.agent.agents.panel import build_panel_graph  # 局部导入，避免无谓依赖

    return build_panel_graph(config)


def make_handoff_node(config: ProcessConfig):
    from app.agent.agents.handoff import build_handoff_node

    return build_handoff_node(config)
```

### 新增一条流程的改动量

严格三步，缺一不可，且互不越界。

1. 新增 `app/process_config/seeds/{process_id}.yaml`，填 `required_slots`、`redlines`、`terminology`、`timing_rules`、`output_template`、`calendar_source`、`followup_policy`、`offline_questions`、`panel_enabled`、`object_aliases`、`confusable_items`、`banned_topics`。
2. 新增一个约 15 行的子图文件，内容与 `tea.py` 完全同构，只把 `ProcessId.TEA` 换成新流程，并在 `SUBGRAPH_BUILDERS` 中注册。
3. `app/agent/graph/subgraphs/__init__.py` 的 `SUBGRAPH_BUILDERS` 注册表加一行。

以下事项**不允许**因新增流程而改动：`app/agent/agents/*` 的任何智能体实现、`app/gate/rules/*` 的任何规则、`app/agent/graph/routes.py` 的任何一个路由函数。

### 子图文件的 15 行骨架

```python
"""轮作绿肥流程子图（示例：新增流程的标准形态）。"""
from langgraph.graph import END, StateGraph

from app.agent.graph.factories import (
    get_config, make_interview_node, make_judge_node,
    make_observe_node, make_prescribe_node, make_verify_node,
)
from app.agent.graph.routes import (
    ROUTE_AFTER_INTERVIEW, ROUTE_AFTER_JUDGE, ROUTE_AFTER_VERIFY,
    route_after_interview, route_after_judge, route_after_verify,
)
from app.agent.state import ConsultationState, ProcessId


def build_green_manure_subgraph():
    config = get_config(ProcessId.GREEN_MANURE)
    graph = StateGraph(ConsultationState)
    graph.add_node("observe", make_observe_node(config))
    graph.add_node("interview", make_interview_node(config))
    graph.add_node("verify", make_verify_node(config))
    graph.add_node("judge", make_judge_node(config))
    graph.add_node("prescribe", make_prescribe_node(config))
    graph.add_edge("observe", "interview")
    graph.add_conditional_edges("interview", route_after_interview, ROUTE_AFTER_INTERVIEW)
    graph.add_edge("verify", "judge")
    graph.add_conditional_edges("judge", route_after_judge, ROUTE_AFTER_JUDGE)
    graph.add_edge("prescribe", END)
    return graph
```

上例用于说明形态，实际本项只需交付工厂函数，不改动 `ProcessId` 枚举。

### 为什么用工厂而非继承

七个节点在七条流程里的差异全在配置字段上，不在控制流上。用工厂闭包比用七个 `TeaInterviewer`、`RiceInterviewer` 之类的子类更好：一是新增流程不产生新类，二是配置改动能被热加载（T2-05），而类继承关系是静态的，配置更新后必须重启才生效。`get_config` 用 `lru_cache` 缓存，热加载时通过版本号变化命中新的 key，旧 key 由 T2-05 的注册表负责失效。

### 契约与降级

所有节点内部都通过 Agent 基类（T2-13）执行，具备"契约校验失败 → 重试一次 → 降级"的能力。工厂本身不实现重试，只负责把 config 注入智能体；降级策略（守卫类 fail-closed、其余降级仍服务）由基类与各智能体决定。
