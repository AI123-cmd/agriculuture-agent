# T2-31 轮次与成本预算守卫

## 这一项要做什么

新建 `app/agent/budget.py`，定义 `ConsultBudget` 与一组纯函数守卫，统一管理单次问诊的四个轮次上限与一个 token 预算。方案 7.3 给出五个取值与三类超预算处理，本项把它们从"路由函数里散落的默认值"收敛成一个可单测、可传递、可持久化的对象。现有实现里只有 `round` 一个计数，且阈值来自 `settings.MAX_COLLECT_ROUNDS`，既没有单槽位上限，也没有 token 预算，本项予以替换。

## 前置依赖

- T2-08 ConsultationState 与 ConsultStage 重构：`ConsultationState` 上必须有 `budget` 字段承载本对象的字典形式。

- T2-24 条件边函数 routes：全部路由读取 `state["budget"]`，字段名以本项为准。
- T2-25 主图组装 main：`intake` 节点负责在会话开始时初始化 `budget`。
- T2-55 模型网关统一入口、T2-59 token 计量：token 计数由网关在每次调用后回写，预算守卫只做判断。
- 外部环境：无（本模块为纯逻辑，不依赖数据库、Redis 或模型服务）。

## 实现要点

### 完整定义

```python
"""轮次与成本预算守卫：把四个轮次上限与一个 token 预算收进一个可单测的对象。"""
from __future__ import annotations

from enum import Enum

from pydantic import BaseModel, Field


class BudgetExceeded(str, Enum):
    """超预算的类型，供路由与日志区分处理方式。"""

    NONE = "none"
    INTERVIEW_ROUNDS = "interview_rounds"      # 问诊轮次用尽仍未收敛 -> 转人工
    SLOT_ROUNDS = "slot_rounds"                # 单槽位追问超限 -> 强制写 unknown
    JUDGE_LOOPS = "judge_loops"                # 判定回环用尽 -> 转人工
    TOKENS = "tokens"                          # token 超预算 -> 降级小模型继续


class ConsultBudget(BaseModel):
    """单次问诊的预算：上限 + 已用量。每次节点推进后调用记账方法。"""

    # 上限（来自技术方案 7.3，均为产品说明书要求的硬约束）
    max_interview_rounds: int = 4          # 产品说明书 2.3：收敛轮次目标 <= 4
    max_judge_loops: int = 2               # 4.2.2：置信度不足反向补问最多 2 次
    max_questions_per_round: int = 2       # 4.2.2：每轮追问不超过 2 个问题
    max_slot_rounds: int = 6               # 单槽位重复追问上限，超限写 unknown
    max_tokens_per_consult: int = 24000    # 单次问诊 token 预算

    # 已用量
    interview_rounds: int = 0
    judge_loops: int = 0
    questions_this_round: int = 0
    slot_rounds: dict[str, int] = Field(default_factory=dict)
    tokens_used: int = 0

    @classmethod
    def initial(cls) -> ConsultBudget:
        """会话开始时的初始预算，由 intake 节点调用。"""
        return cls()

    # ---- 记账 ----

    def note_interview_round(self) -> None:
        """一轮问诊结束：轮次 +1，本轮问题数清零。"""
        self.interview_rounds += 1
        self.questions_this_round = 0

    def note_question(self, slot_key: str) -> None:
        """提出一个问题：本轮问题数 +1，该槽位追问次数 +1。"""
        self.questions_this_round += 1
        self.slot_rounds[slot_key] = self.slot_rounds.get(slot_key, 0) + 1

    def note_judge_loop(self) -> None:
        """判定要求补问一次：回环计数 +1。"""
        self.judge_loops += 1

    def note_tokens(self, count: int) -> None:
        """模型网关每次调用后回写 token 用量。"""
        self.tokens_used += count

    # ---- 守卫 ----

    def check_interview_rounds(self) -> BudgetExceeded:
        if self.interview_rounds >= self.max_interview_rounds:
            return BudgetExceeded.INTERVIEW_ROUNDS
        return BudgetExceeded.NONE

    def check_judge_loops(self) -> BudgetExceeded:
        if self.judge_loops >= self.max_judge_loops:
            return BudgetExceeded.JUDGE_LOOPS
        return BudgetExceeded.NONE

    def check_question_quota(self) -> bool:
        """本轮是否还能再问一个问题（每轮 <= 2 问）。"""
        return self.questions_this_round < self.max_questions_per_round

    def check_slot(self, slot_key: str) -> BudgetExceeded:
        """单槽位是否已被追问超过上限（超过即应写 unknown，不再追问）。"""
        if self.slot_rounds.get(slot_key, 0) >= self.max_slot_rounds:
            return BudgetExceeded.SLOT_ROUNDS
        return BudgetExceeded.NONE

    def check_tokens(self) -> BudgetExceeded:
        if self.tokens_used >= self.max_tokens_per_consult:
            return BudgetExceeded.TOKENS
        return BudgetExceeded.NONE

    def to_state(self) -> dict:
        """序列化进 ConsultationState；路由函数按这些键名读取。"""
        return self.model_dump()
```

### 五个上限与依据

| 字段 | 取值 | 依据 | 超限后果 |
| --- | --- | --- | --- |
| `max_interview_rounds` | `4` | 产品说明书 2.3 收敛轮次目标 ≤ 4 | 转人工，输出携带已确认信息 |
| `max_judge_loops` | `2` | 产品说明书 4.2.2 反向补问最多 2 次 | 转人工 |
| `max_questions_per_round` | `2` | 产品说明书 4.2.2 每轮不超过 2 问 | 本轮不再生成新问题，交回路由 |
| `max_slot_rounds` | `6` | 方案 7.3 单槽位重复追问上限 | 强制写 `status="unknown"`，不再追问该槽位 |
| `max_tokens_per_consult` | `24000` | 方案 7.3 单次问诊 token 预算 | 降级小模型继续，记录日志，不中断服务 |

### 超预算的三种处理

方案 7.3 明确列出三种，且它们的行为不同，必须分开实现。

**第一种，轮次达 4 且未收敛，转人工。** 由 `route_after_interview` 读取 `budget.interview_rounds >= max_interview_rounds` 后返回 `handoff`。转人工的上下文包必须携带已确认信息（已填槽位、已排除项、已观察要点），使农户到农技站后不必从头复述。触发条件对应产品说明书第六章 6.7 的"连续未收敛"一行：轮次 ≥ 4 且关键槽位仍 `missing`。注意判定用的是 `missing`，不是 `unknown`——农户明确答不出的槽位达到上限后已按第三种处理写入 `unknown`，不再计入未收敛。

**第二种，单槽位被追问超过上限仍未填，强制写 `unknown`。** 这条在问诊节点内部执行，不在路由里。产品说明书 4.2.2 要求"不允许为了凑齐信息而反复逼问同一个问题"。实现方式：问诊节点生成下一轮问题之前，对候选池里的每个槽位调 `check_slot(slot_key)`，命中 `SLOT_ROUNDS` 的槽位直接从候选池剔除，并在 `slots` 中写入 `{status: "unknown", source: "inferred"}`。此后该槽位既不再被追问，也不计入"关键槽位未齐备"，从而正常推进到 `verify`。

**第三种，token 超预算，降级为小模型继续。** 由模型网关（T2-58 降级链、T2-59 计量）执行。守卫只负责在每次调用后调用 `note_tokens` 并在 `check_tokens()` 命中时把 `state["degraded"] = True`，网关据此路由到小模型档位。**不中断服务**，也不走向 `handoff`——这与前两种有本质区别：轮次用尽是"信息不够"，token 用尽是"成本超支"，前者影响结论可靠性，后者只影响成本。

### 与路由的接口约定

路由函数只读字典，不重建对象，保证纯函数与可重放：

```python
ROUTE 读取的键（来自 ConsultBudget.model_dump()）：
    interview_rounds, max_interview_rounds, judge_loops, max_judge_loops
```

节点内需要记账时，从 state 反序列化出对象、改完再写回：

```python
budget = ConsultBudget(**state.get("budget", {}))
budget.note_interview_round()
return {"budget": budget.to_state()}
```

### 为什么不用全局配置

现有实现把阈值放在 `settings.MAX_COLLECT_ROUNDS`，问题是阈值在所有流程、所有会话间共享一份可变全局状态，重启才能改，且无法按会话追溯。收进 `ConsultBudget` 后有两个直接收益：一是可被写进检查点，历史问诊能复现"当时用了多少轮、花了多少 token"；二是可按流程差异化（例如未来给复杂流程放宽轮次），而无需动全局配置。

  - `note_tokens(24000)` 后 `check_tokens() == BudgetExceeded.TOKENS`，且 `to_state()` 能被 `ConsultBudget(**state)` 无损还原（round-trip 测试）。
