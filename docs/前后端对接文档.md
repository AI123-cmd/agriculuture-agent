## 二、业务流程

### 2.1 登录流程

```
用户点击登录
    │
    ▼
wx.getUserProfile() ──→ 获取用户头像、昵称（需用户确认授权）
    │
    ▼
wx.login() ──→ 获取临时登录凭证 code（有效期 5 分钟）
    │
    ▼
前端调用 POST /api/login，传参: code + userInfo
    │
    ▼
后端用 code 调用微信 jscode2session，换取 openid + session_key
    │
    ▼
后端根据 openid 判断用户是否存在
    ├── 新用户 → 创建用户记录
    └── 老用户 → 更新用户信息
    │
    ▼
后端生成自定义 token 返回给前端
    │
    ▼
前端存储 token，后续所有请求携带 token
```

### 2.2 新用户完整链路

```
用户打开小程序
    │
    ▼
【登录页】──微信授权登录──▶ POST /api/login → 返回 token + userId + isNewUser
    │
    ▼
判断档案状态 ──▶ GET /api/farmer/profile
    │
    ├── 已有档案 ──────────▶ 直接进入首页
    │
    └── 无档案
             │
             ▼
     【农户档案页】填写基础信息 + 种植作物（作物名称+面积+生长阶段）
             │  POST /api/farmer/profile（含 crops 数组）
             │
             ▼
     后端根据作物名称匹配农业垂类大模型，生成初始用户画像
             │
             ▼
     进入【首页】
        ├── 今日农事播报（GET /api/broadcast/today）
        ├── 快捷入口：AI咨询 / 拍照识别 / 查看环境 / 农事管理
        └── 环境摘要（GET /api/environment/summary）
             │
             ▼
     【AI咨询页】对话（POST /api/ai/chat）
             │
             ▼
     对话结束 ──▶ 自动更新用户画像
             │
             └──▶ 下一次播报 & 问答基于新画像提供精准上下文
```

### 2.3 前端路由判断逻辑

登录成功后需判断跳转方向：

```ts
登录成功 → 存 token
  → 请求 GET /api/farmer/profile
     ├── 有档案 → wx.reLaunch({ url: '/pages/index/index' })
     └── 无档案 → wx.reLaunch({ url: '/pages/profile/farmer-profile' })
```

## 三、接口通用规范

### 3.1 鉴权

所有需要登录态的接口，前端在请求头携带：

```
Authorization: Bearer <token>
```

### 3.2 统一响应格式

```json
{
  "code": 200,
  "message": "success",
  "data": { ... }
}
```

### 3.3 错误码

| 错误码 | 说明 |
|--------|------|
| 200 | 成功 |
| 400 | 参数缺失或格式错误 |
| 401 | 登录已过期 / code 无效 |
| 500 | 服务器内部错误 |

token 无效时返回：

```json
{ "code": 401, "message": "登录已过期，请重新登录", "data": null }
```

## 四、接口清单

### 4.1 登录接口

#### POST /api/login

前端传入微信 code 和用户信息，后端换取 openid 后返回登录态。

**请求：**

```json
{
  "code": "0a3xxxxxxxxxxxxxxx",
  "userInfo": {
    "nickName": "张三",
    "avatarUrl": "https://thirdwx.qlogo.cn/...",
    "gender": 1,
    "country": "中国",
    "province": "广东",
    "city": "深圳"
  }
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| code | string | 是 | wx.login() 返回的临时凭证，有效期 5 分钟 |
| userInfo.nickName | string | 是 | 用户昵称 |
| userInfo.avatarUrl | string | 是 | 用户头像 URL |
| userInfo.gender | number | 否 | 0:未知 1:男 2:女 |
| userInfo.country/province/city | string | 否 | 国家/省/市 |

**响应：**

```json
{
  "code": 200,
  "data": {
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "userId": "user_001",
    "isNewUser": true
  }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| token | string | 后续所有接口请求需在 Header 携带 |
| userId | string | 用户唯一ID |
| isNewUser | boolean | 是否新用户（前端据此判断是否引导填档案） |

#### POST /api/farmer/profile

首次填写 / 修改档案。crops 中的 cropName 决定后端匹配哪个农业垂类大模型。

**请求：**

```json
{
  "realName": "张建国",
  "age": 52,
  "gender": 1,
  "phone": "13800138000",
  "experienceYear": 15,
  "province": "湖南",
  "city": "益阳",
  "district": "赫山区",
  "address": "八字哨镇某某村12组",
  "totalMu": 86.5,
  "cultivationType": 1,
  "waterSource": "河水",
  "remark": "低洼田，雨季注意排水",
  "crops": [
    { "cropName": "水稻", "plantMu": 20.5, "growthStage": "分蘖期" },
    { "cropName": "辣椒", "plantMu": 5.0, "growthStage": "结果期" },
    { "cropName": "烟草", "plantMu": 10.0, "growthStage": "成熟期" }
  ]
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| realName | string | 是 | 真实姓名 |
| age | number | 否 | 年龄 |
| gender | number | 是 | 1男 2女 |
| phone | string | 是 | 联系电话 |
| experienceYear | number | 是 | 种植经验年限 |
| province/city/district | string | 是 | 省市区 |
| address | string | 否 | 详细地址 |
| totalMu | number | 是 | 总种植面积（亩） |
| cultivationType | number | 是 | 1露地 2大棚 3混合 |
| waterSource | string | 否 | 灌溉水源 |
| remark | string | 否 | 备注 |
| crops | array | 是 | 种植作物列表（至少1种） |
| crops[].cropName | string | 是 | 作物名称（用户自由输入，后端据此匹配垂类大模型） |
| crops[].plantMu | number | 否 | 该作物种植面积（亩） |
| crops[].growthStage | string | 否 | 当前生长阶段 |

> **重要：** `cropName` 为用户自由输入文本，不限于预设列表。后端需根据作物名称匹配对应农业垂类大模型（如"水稻"→水稻专家模型，"烟草"→烟草专家模型）。无法精确匹配时建议模糊匹配或归入通用农业模型。

### 4.3 地点 / 设备接口

#### POST /api/location/set

保存用户农事地点（省市区或自定义地名）。前端支持自动定位（`wx.getLocation` 获取 GPS 坐标）或手动输入。

**请求：**

```json
{
  "locationName": "湖南省长沙市芙蓉区",
  "latitude": 28.521,
  "longitude": 112.354,
  "source": "manual"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| locationName | string | 是 | 地点名称（如"湖南省长沙市芙蓉区"） |
| latitude | number | 否 | 纬度（自动定位时传入） |
| longitude | number | 否 | 经度（自动定位时传入） |
| source | string | 是 | `"manual"` 手动输入 / `"gps"` 自动定位 |

**响应：**

```json
{
  "code": 200,
  "data": {
    "locationName": "湖南省长沙市芙蓉区",
    "weatherSummary": "多云 26°C"
  }
}
```

> **前端当前状态：** 地点存储在本地缓存 `farmLocation`，每次进入首页自动读取。自动定位调用 `wx.getLocation` 获取坐标，逆地理编码使用模拟数据（显示坐标），后端对接后替换为真实地图 API。手动输入通过 `wx.showModal` 弹出输入框。

#### GET /api/location/reverse-geocode

逆地理编码：将 GPS 坐标转为省市县地址。

**参数：** `latitude=28.521&longitude=112.354`

**响应：**

```json
{
  "code": 200,
  "data": {
    "province": "湖南省",
    "city": "长沙市",
    "district": "芙蓉区",
    "fullAddress": "湖南省长沙市芙蓉区"
  }
}
```

> 后端可对接腾讯地图 / 高德地图 API 实现逆地理编码。

### 4.5 AI 咨询接口

#### POST /api/ai/chat

发送问题。后端自动读取用户画像 context 作为对话上下文，问答结束后异步刷新画像标签。

```json
// 请求
{
  "message": "我的水稻叶子发黄是什么原因？",
  "imageUrl": "https://cdn.xxx.com/upload/20260816/xx.jpg",
  "sessionId": "sess_20260816_001",
  "cropTag": "水稻"
}

// 响应
{
  "code": 200,
  "data": {
    "sessionId": "sess_20260816_001",
    "reply": "从描述和图片判断，大概率是缺氮性黄化，结合您的土壤近期含水率偏高...",
    "relatedSuggestions": ["追施尿素建议", "排水建议", "3天后复诊叶片颜色"],
    "tagsAdded": ["缺氮", "水稻分蘖期病害"]
  }
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| message | string | 是 | 用户输入的问题文本 |
| sessionId | string | 是 | 会话ID，前端生成（`sess_` + 时间戳），用于关联历史记录 |
| cropTag | string | 否 | 当前选中的作物名称，后端据此路由到对应垂类大模型（如"水稻"→水稻专家模型） |
| imageUrl | string | 否 | 用户上传的图片URL（拍照识别场景） |

> **作物标签切换机制：** 咨询页顶部显示"当前咨询：[作物名] [切换]"标签条。默认从农户档案读取主作物（`farmerCrops[0]`），用户可点击"切换"在 ActionSheet 中选择其他作物。切换后 `cropTag` 字段同步更新，后端据此路由到对应农业垂类大模型。档案无作物时默认显示"通用农业"。

> **前端当前状态：** AI回复使用本地 mock 数据模拟，未调用真实接口。后端就绪后替换 `chat.ts` 中 `mockAIResponse()` 为 `wx.request` 调用即可。前端已实现：
> - 发送消息后自动平滑滚动到底部（`scroll-top` 数值方案）
> - 对话记录自动保存到本地缓存（`ai_conversation_list`），供历史页读取
> - 首条用户消息作为对话标题，AI最新回复作为预览摘要

#### GET /api/ai/history

对话历史列表。参数：`page=1&size=20`

**响应：**

```json
{
  "code": 200,
  "data": {
    "list": [
      {
        "id": "sess_20260816_001",
        "title": "我的水稻叶子发黄...",
        "preview": "从描述和图片判断，大概率是缺氮性黄化...",
        "updatedAt": 1723800000000,
        "messages": [
          { "id": 1, "role": "ai", "content": "你好，我是话农点金..." },
          { "id": 2, "role": "user", "content": "我的水稻叶子发黄是什么原因？" },
          { "id": 3, "role": "ai", "content": "从描述和图片判断..." }
        ]
      }
    ],
    "total": 1
  }
}
```

> **前端当前状态：** 历史列表从本地缓存 `wx.getStorageSync('ai_conversation_list')` 读取，按 `updatedAt` 倒序排列。后端就绪后替换 `list.ts` 中 `loadConversations()` 为 `wx.request` 调用即可。前端已实现：
> - 点击历史条目可恢复完整对话内容（`chat.ts` 的 `restoreConversation()`）
> - 删除对话同步更新本地缓存
> - 空状态提示"暂无历史对话"
> - 新对话入口跳转咨询页

#### DELETE /api/ai/history/{sessionId}

删除指定对话记录。

**响应：**

```json
{ "code": 200, "message": "success", "data": null }
```

> **前端当前状态：** 删除操作同步更新本地缓存，后端就绪后补充 `wx.request` 调用即可。

### 4.6 用户画像更新

#### POST /api/user-profile/update

后端内部调用，前端无需显式调用。触发时机：1) 档案保存后 2) AI对话结束后 3) 播报任务完成时。将最新用户标签、对话上下文快照写入 `user_profile_tag` 表。

---

### 4.7 头像 / 账号接口

#### 4.7.1 POST /api/user/avatar/upload（文件上传）

**说明**：用户在「我的」页修改头像后，前端通过 `wx.chooseAvatar` 得到临时本地文件路径（`tmpFilePath`），然后用 **`wx.uploadFile`** 以 multipart/form-data 形式将图片上传到后端。后端持久化保存到对象存储（OSS/COS/本地目录），返回可公网访问的 HTTPS URL，前端再写入 user.avatar_url。后端建议：限制图片 5MB 以内、格式 jpg/png/webp、自动压缩裁剪成正方形。

> 注意：chooseAvatar 返回的是微信小程序本地临时路径，**不能直接把 tmpFilePath 存到数据库**（临时文件7天过期），必须走 wx.uploadFile → 后端保存 → 后端返回永久 URL。

| 项目 | 说明 |
|------|------|
| 方法 | `wx.uploadFile`（HTTP POST multipart/form-data） |
| 路径 | `https://你的域名/api/user/avatar/upload` |
| Header | `Authorization: Bearer <token>`（放在 formData 外，wx.uploadFile 的 header 参数中传入） |
| name 参数 | `file`（wx.uploadFile 的 name 字段，后端按这个字段接收文件） |
| filePath 参数 | `wx.chooseAvatar` 返回的 `e.detail.avatarUrl`（本地临时路径） |
| formData | 可空 |

**响应示例**：
```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "avatarUrl": "https://cdn.你的域名/avatar/user_123_20260816.jpg"
  }
}
```

---

#### 4.7.2 DELETE /api/user/cancel（注销账号）

**说明**：用户在「我的」页底部点击"注销账号"，二次确认后调用。后端硬删除 `user` 表记录 + `farmer_profile` + `ai_conversation` / `ai_message` + `broadcast_log` + `location` + `user_profile_tag` 所有关联数据（或软删+30天注销冷静期）。**返回成功后，前端 `wx.clearStorageSync()` 清除所有本地缓存，`wx.reLaunch` 回到登录页。**

| 项目 | 说明 |
|------|------|
| 方法 | DELETE |
| Header | `Authorization: Bearer <token>` |
| 请求体 | 无 |
| 响应 | `{code:0, message:"ok"}` |
