# 转人工路径生成"问诊结果"改造技术方案

## 1. 背景与要解决的问题

产品期望：**每条问诊路径都应产出一份"问诊结果"**。出方路径已经产出（处方卡），但**转人工路径没有**：
农户走到转人工时，界面结尾只出现一张标题固定的卡片——「建议找农技人员」，既没有"本次判断是什么"，
也没有统一的"结果"载体；历史回看该会话时更是空白（转人工会话不落库、`handoff` 回看恒为 `null`）。

本方案要落两件事：

1. **所有终态路径都产出统一结构的"问诊结果"**（含转人工、安全拦截、法定报告）。
2. **转人工路径结尾不再单独弹"建议找农技人员"**，而是并入"问诊结果"卡，作为结果内的
   "下一步建议"区块呈现。

> 合规前提不变：安全拦截不得复述被拦截方案；法定报告不做最终认定；转人工仍是正常业务结果，
> 用 200 + 结构字段表达，不是错误响应。

## 3. 目标与非目标

**目标**

- 新增统一契约 `ConsultResultView`（"问诊结果"），由 `ChatResponse.result` 承载，**所有终态非空**。
- 转人工路径也产出"问诊结果"：结论（在合规边界内）+ 已了解情况 + 观察要点 + 已排除项 + 下一步建议。
- 转人工会话**落库**，历史回看能看到同一份"问诊结果"。
- 前端渲染统一为一张「问诊结果」卡；转人工不再单独出现「建议找农技人员」卡片，
  该引导降级为结果卡内的"下一步建议"区块。

**非目标**

- 不改路由与触发条件（转人工何时发生完全不变）。
- 不为安全拦截/法定报告编造诊断结论（合规红线）。
- 不改闸门规则、报告守卫的判定逻辑。

## 4. 总体设计

引入"**一份结果，三层贯通**"：

```
图产出（state）
  ├─ prescription / handoff_package / diagnosis / gate_result / report_decision
  ▼
① 契约层：统一投影为 ConsultResultView（所有终态都构造）
  ▼
② 落库层：终态一律落 consultation（新增 result_snapshot 列），处方路径另落 prescription_card
  ▼
③ 前端层：只渲染一张「问诊结果」卡，按 result.kind 决定内部区块
```

### 4.1 统一"问诊结果"契约

在 [consult.py](file:///f:/wx/agriculuture-agent/backend/app/schemas/consult.py) 新增：

```python
ConsultResultKind = Literal["prescription", "handoff", "blocked", "report"]

class ConsultResultView(BaseModel):
    kind: ConsultResultKind
    title: str = "问诊结果"                 # 卡片标题，固定不外泄内部枚举
    conclusion: str                         # 结论/判断（所有路径都有，合规文案见 §5.1）
    confidenceLabel: str | None = None      # 把握程度口语化（很可能是/初步判断/不确定），无则 None
    basis: list[str] = []                   # 判断依据
    confirmedInfo: list[str] = []           # 已了解的情况（含 HandoffPackage.confirmed_facts）
    observationPoints: list[str] = []       # 观察要点/还缺什么
    excludedItems: list[str] = []           # 已排除项
    actions: list[PrescriptionActionView] = []
    pesticideItems: list[PesticideItemView] = []
    followupPlan: FollowupPlanView | None = None
    nextStep: str | None = None             # 下一步建议（转人工：带记录咨询当地农技站）
    contacts: list[ContactInfoView] = []
    requiresTechStation: bool = False
    speakable: bool = False
    cardId: str | None = None               # 处方卡主键，入台账按钮用
```

`ChatResponse` 增加 `result: ConsultResultView | None`（见 §5.2 关于旧字段的取舍）。

### 4.2 kind 与来源映射

| kind | 触发来源（state） | conclusion 取值 | 关键区块 |
| --- | --- | --- | --- |
| `prescription` | `stage==FOLLOWUP` 且有 `prescription` | 处方 `diagnosis_summary` | actions / pesticideItems / followupPlan |
| `handoff` | 有 `handoff_package`，reason ∈ out_of_scope / not_converged | `diagnosis.conclusion` + 把握度；缺失则用 `headline` | confirmedInfo / observationPoints / excludedItems / nextStep / contacts |
| `blocked` | reason == safety_block（闸门 degrade/block） | 固定中性文案"本次未给出用药建议" | observationPoints（原因归类，**不复述药剂**）/ nextStep / contacts |
| `report` | reason == legal_report | 固定文案"需要马上报告" | actions=强制动作 / contacts |

> `handoff` 的 `result` 与 `handoff` 字段（若保留）内容同源，构造集中在服务层一处，避免两处漂移。

## 5. 详细改造

### 5.1 服务层：构造统一结果（`ai_service.py`）

新增纯函数 `build_consult_result(state, response) -> ConsultResultView`，放在服务层（可访问
`state["prescription"]`、`state["handoff_package"]`、`state["diagnosis"]`）。核心分支：

- **出方**：`conclusion = prescription.diagnosis_summary`；`confidenceLabel` 取
  `CONFIDENCE_DISPLAY[diagnosis.confidence_level]`；`basis = diagnosis.basis`；动作/药剂/回访直接投影。
- **转人工（超边界 / 未收敛）**：
  - `conclusion`：优先 `diagnosis.conclusion`（诊断智能体通常已产出），空则回落
    `handoff_package.headline`。**超边界时**用 `diagnosis.boundary_reason` 作为一句解释附在结论后。
  - `confidenceLabel`：有 `confidence_level` 才给，超边界/不确定场景给出"不确定"。
  - `confirmedInfo`：由 `handoff_package.confirmed_facts`（已是 `标签：值`）转 `标签：值` 列表。
  - `observationPoints`：`handoff_package.observations[].text`（未收敛时即"还缺这一项：X"）。
  - `excludedItems`：`handoff_package.excluded`。
  - `nextStep`：由 reason 决定的一句固定引导，例如未收敛→"建议带样本到当地农技站确认"；
    超边界→"建议把上面几条拍清楚、记下来，找当地农技站看看"。
  - `contacts`：`handoff_package.contacts`。
- **安全拦截（blocked）**：`conclusion` 用固定中性文案（**不得包含被拦截药剂名**，与
  `_explain_block` 同一红线）；`observationPoints` 用 gate 的原因归类；`nextStep` 固定"建议先问农技站"。
- **法定报告（report）**：`conclusion` 固定"需要马上报告，下面是该做的事"；
  `actions` 直接承载 `mandatory_actions`（顺序即展示顺序，不截断）；`excludedItems` 恒空。
- `speakable`：转人工/报告为 `True`（保留朗读入口）；纯出方为 `False`。

**合规红线（复用既有约定，不新造）**：
- `blocked` 的 `conclusion` / `observationPoints` 不出现任何来自 `gate.violations` 的药剂名。
- `report` 的 `excludedItems` 恒为空，`conclusion` 不出现疾病名称或"确诊"。

### 5.2 互斥关系的调整

现状断言三者互斥的**目的是**"同一轮不能既追问又出方又转人工"。引入 `result` 后：

- `result` **不参与互斥**——它是"结果载体"，与 `questions`（追问）互斥，但与 `prescription` / `handoff`
  同源，不是并列的第四种产物。
- 推荐做法（**选项 A，推荐**）：保留 `questions / handoff / prescription` 三者互斥断言不变，
  新增 `result` 作为"终态必填、追问轮为空"的补充字段，并加一条断言：
  `questions 非空时 result 必须为空`。改动最小、向后兼容。
- 兼容做法（**选项 B**）：`result` 成为唯一渲染源，`prescription` / `handoff` 仍下发一轮（灰度期），
  前端切到只读 `result`。待前端发版稳定后，下一版删除 `handoff`（`prescription` 因入台账仍保留）。

> 建议：本期采用 **A**（后端加 `result`，旧字段不动），前端切到读 `result`；`handoff` 字段保留一个版本
> 作为过渡，避免前后端同时发版。

### 5.3 落库改造（转人工也落 `consultation`）

问题：转人工会话当前不落 `consultation` 行，历史回看无结果。`PrescriptionCard.consultation_id`
是 NOT NULL，转人工没有处方卡，因此不能只靠卡片承载结果。

**方案**：给 `consultation` 增加一列 `result_snapshot JSONB`，承载统一的"问诊结果"结构。

- 模型：[consultation.py](file:///f:/wx/agriculuture-agent/backend/app/models/consultation.py#L47-L84)
  的 `Consultation` 增列 `result_snapshot: Mapped[dict] = mapped_column(JSONB, nullable=False, default=dict)`。
- 迁移：新增 `alembic/versions/00xx_consultation_result_snapshot.py`（`op.add_column`，可空性/注释与 ORM 逐字对齐，
  否则 `test_metadata_matches_orm` 报差异）。
- 服务层 `_persist`：把落库判据从"有处方"改为"**是终态**"：
  - 终态（`response.result is not None`）：一律 upsert `consultation`，写 `result_snapshot`；
    `status` 按路径取值——出方 `observing`；转人工 `escalated`；安全拦截/报告 `blocked`。
  - 仅 `prescription` 路径：额外落 `prescription_card` 并发 `prescription.created` 事件（现状不变）。
- `_persist_prescription` 可拆出"建/滚动 consultation 行"为独立的 `_persist_consultation`，
  两条路径共用，避免逻辑重复。

`ConsultStatus` 五值现成可用（[enums.py](file:///f:/wx/agriculuture-agent/backend/app/models/enums.py#L74-L84)）：
`escalated` 对应转人工、`blocked` 对应安全拦截/报告，语义已对齐，无需新增枚举。

### 5.4 历史回看改造

[conversation_detail](file:///f:/wx/agriculuture-agent/backend/app/services/ai_service.py#L754-L774)：

## 8. 验收标准

- 出方、转人工（超边界/未收敛）、安全拦截、法定报告四类终态，`ChatResponse.result` **均非空**。
- 转人工场景：`result.kind ∈ {handoff, blocked, report}`，`result.conclusion` 非空，
  `result.nextStep` 非空，`result.contacts` 与 `handoff_package.contacts` 一致。
- **合规断言**：`blocked` 的 `conclusion` 与 `observationPoints` 不含任何 `gate.violations` 中的药剂名；
  `report` 的 `excludedItems` 为空。
- 追问轮（`questions` 非空）时 `result` 为空。
- 转人工会话落 `consultation` 行（`status=escalated`），`result_snapshot` 非空；
  历史回看 `GET /api/ai/consult/{id}` 的 `result` 与实时一致。
- 前端：转人工路径**不再出现**独立「建议找农技人员」卡；统一「问诊结果」卡可见结论 +
  下一步建议 + 联系方式；历史回看转人工会话能看到「问诊结果」。
- `ruff check`、`ruff format --check`、`mypy app`、`pytest` 全绿。

## 9. 待确认项

1. **旧 `handoff` 字段的保留期**：本方案默认保留一个版本（灰度），确认是否需要立即移除。
2. **转人工 `conclusion` 的口径**：超边界场景是否允许直接展示诊断智能体的 `conclusion`
   （在 `boundary_reason` 已说明"超出范围"的前提下），还是统一用"超出范围"的中性表述。
   （本方案默认：允许展示 `conclusion` 并附 `boundary_reason`，因它不含用药方案、无合规风险。）
