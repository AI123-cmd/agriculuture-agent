# 「拍照 → AI 文字描述 → 返回小程序」打通方案

> 适用仓库：`f:\wx\agriculuture-agent`（"话农点金" HNDJ）
> 核心链路：**农户拍照 → 上传拿到图片地址 → 图片交给模型（deepseek-v4-flash / VISION 档）→ 模型输出针对性文字描述 → 随问诊结果返回小程序展示**
> 本文只描述方案，不含已实施的代码改动。

---

## 一、目标与范围

农户在问诊页点「拍照/相册」，拍下一张田地或叶片照片，系统把照片交给模型识别，模型输出一段**面向农户的针对性文字描述**（"照片里叶子边缘发黄，有零星斑点"），并把这段描述回显在小程序聊天流里，同时作为现场事实参与后续问诊与判定。

范围内：

- 小程序端拍照/选图入口与上传
- 后端图片上传接口（校验 + 落盘 + 返回可访问地址）
- 图片识别的生产实现（调模型，走 VISION 档）
- 识别结果 → 文字描述 → 接口响应 → 小程序渲染
- 既有分层约束（L1–L4）与既有契约（`ImageCandidate` / `ObservationResult` / `ChatRequest` / `ChatResponse`）的遵守

范围外：不改问诊流程结构、不改安全闸门、不新增流程配置项、不做图片内容安全审核（沿用"上传内容不可执行"这条既有保障）。

## 四、分步改造方案

### 第 1 步：后端新增图片上传接口

新增路由 `POST /api/ai/chat/upload`（[ai.py](file:///f:/wx/agriculuture-agent/backend/app/api/v1/ai.py)，`router` 前缀 `/ai` 已存在，最终路径为 `/api/ai/chat/upload`，与技术方案 13.1 的路径在版本段上按本项目实际写法落为 `/api/...`）。

实现要点（**照抄头像上传的既有顺序，不新增校验逻辑**）：

1. 提前粗筛：`file.size > settings.UPLOAD_MAX_BYTES` 直接 400（`UploadFile.size` 可伪造，只作粗筛）。
2. `validate_image(filename, content_type, data, max_bytes=..., allowed=...)` 三重校验（[validators.py:43-75](file:///f:/wx/agriculuture-agent/backend/app/core/validators.py#L43-L75)）：**大小 → 真实魔数 → 与声明类型一致**，顺序不可换。
3. 校验通过才 `get_storage().save_image(data, check.mime)`（[storage.py:27-42](file:///f:/wx/agriculuture-agent/backend/app/integrations/storage.py#L27-L42)），返回 `/static/<哈希前2位>/<哈希>.<ext>`。
4. 响应用统一包装 `ok({"url": url})`，与 `UploadResult`（[api.d.ts:460-462](file:///f:/wx/agriculuture-agent/miniprogram/types/api.d.ts#L460-L462)）一致。

**与头像上传的唯一差异**：问诊图片**不落库**。头像上传后要更新 `user.avatar_url`，问诊图片只是临时素材，地址随 `ChatRequest.imageUrl` 走，由 `AIMessage.image_url` 在落消息时一并保存（[ai_service.py:474](file:///f:/wx/agriculuture-agent/backend/app/services/ai_service.py#L474) 已有）。因此本接口**不需要 `db` 依赖**，也**不需要 `unit_of_work`**——文件落盘失败就没有 URL，不存在"文件与记录半途分离"的问题。

参考骨架：

```python
@router.post("/chat/upload")
async def upload_chat_image(
    file: UploadFile = File(...),
    user_id: str = Depends(get_current_user),
) -> dict:
    """问诊图片上传：校验后落盘，返回可访问地址（技术方案 13.1）。"""
    settings = get_settings()
    if file.size and file.size > settings.UPLOAD_MAX_BYTES:
        raise BadRequest(f"文件超过上限 {settings.UPLOAD_MAX_BYTES // 1024 // 1024}MB")
    data = await file.read()
    check = validate_image(
        file.filename or "", file.content_type, data,
        max_bytes=settings.UPLOAD_MAX_BYTES, allowed=settings.UPLOAD_ALLOWED_TYPES,
    )
    if not check.ok or check.mime is None:
        logger.warning("问诊图片被拒：user=%s file=%s reason=%s", user_id, file.filename, check.reason)
        raise BadRequest(check.reason or "图片校验失败")
    return ok({"url": get_storage().save_image(data, check.mime)})
```

> 校验与存储若照搬进路由会与 `user_service` 重复，建议抽到 `app/services/media_service.py`（或直接复用 `UserService` 的一个不落库方法）——是否抽取决口子实施时按"避免第三处重复"判断，本方案不强制。

### 第 3 步：修正 state 图片通道（断点 A）

改 [field_observer.py](file:///f:/wx/agriculuture-agent/backend/app/agent/agents/field_observer.py#L174-L182) 的 `_collect_images`，让它读 state 里真正存在的键，并兼容既有测试写法：

```python
async def _collect_images(self, state: ConsultationState, ctx: AgentContext) -> list[ImageCandidate]:
    """图片识别候选域按流程限定，避免跨流程候选污染。"""
    # `image_url` 是接口层注入的声明键（T2-33）；`observations.image_urls` 为历史写法保留，
    # 两者都接受是为了不破坏既有单测，新代码一律走前者。
    url = state.get("image_url")
    image_urls = [url] if url else list((state.get("observations") or {}).get("image_urls") or [])
    if not image_urls:
        return []
    allowed = self._allowed_labels(ctx.process_config)
    raw = await self._image.recognize(image_urls, allowed_labels=allowed)
    return [ImageCandidate(label=c.label, score=c.score, part=c.part) for c in raw if c.label in allowed]
```

要点：

- **只改取值来源，不动候选域过滤**。`if c.label in allowed` 这一步是代码层硬约束（不依赖模型自律），必须保留——茶流程的照片不该被识别出"稗草"这类杂草标签。
- `state["image_url"]` 是单张（`ChatRequest.imageUrl` 是 `str | None`）。**本方案按单图设计**；若将来要支持多图，应改 `ChatRequest.imageUrl` 为 `list[str]` 而不是继续往 `observations` 里塞数组。

### 第 4 步：图片识别的生产实现（断点 B + C）

#### 4.1 放置位置与分层

`ImageReader` 端口定义在智能体层（[field_observer.py:104-108](file:///f:/wx/agriculuture-agent/backend/app/agent/agents/field_observer.py#L104-L108)），按注释其生产实现"在智能体层之外注入"。推荐放在 **`app/integrations/image_reader.py`**：

- 它需要访问文件系统/网络取图片字节，属 IO，不该进 `app/agent/`（保持智能体层可喂假数据单测）；
- 它要调 `ModelGateway`（`app.llm`），L1–L4 均未禁止 `integrations → llm`；
- 工厂 [factories.py](file:///f:/wx/agriculuture-agent/backend/app/agent/graph/factories.py) 导入 `app.integrations` 组装并注入，与现有的"占位实现 + 注入"风格一致。

**合规自查**：不导入 `app/models`（守 L2）、不写 `db.query`（守 L4）、网关侧不改（守 L3，`app.llm` 不反向依赖业务）。

#### 4.2 接口实现骨架

```python
class ModelImageReader:
    """图片识别端口的生产实现：取图 → 多模态调用 → 解析为候选（T2-15 的 ImageReader）。"""

    def __init__(self, gateway: ModelGateway, storage: Storage) -> None:
        self._gateway = gateway
        self._storage = storage   # LocalStorage 需补 read_image(key) -> bytes | None

    async def recognize(
        self, image_urls: list[str], *, allowed_labels: set[str]
    ) -> list[ImageCandidate]:
        images = [b for b in (self._load(u) for u in image_urls) if b is not None]
        if not images:
            return []
        schema = _CandidatesOut    # 内部专用契约，见 4.3
        messages = self._build_messages(images, allowed_labels)
        try:
            response = await self._gateway.chat(TaskType.OBSERVE, messages, schema)
        except AllProvidersFailedError as exc:
            log.warning("image recognition failed", reason=str(exc))
            return []          # 不抛：观察节点已用 return_exceptions 兜底，这里给空候选更干净
        if response.parsed is None:
            return []
        allowed = allowed_labels
        return [
            ImageCandidate(label=c.label, score=c.score, part=c.part)
            for c in response.parsed.candidates
            if c.label in allowed          # 二次过滤：与智能体层的过滤形成双保险
        ]
```

关键点：

1. **只用图片的原生键，不拼绝对路径**：`/static/ab/cd.png` 这类相对路径由服务端解析成 `STORAGE_LOCAL_DIR` 下的真实文件，**仅允许 `/static/` 前缀**（白名单校验），拒绝 `http://` / `../` 等任意路径 —— 否则 `ChatRequest.imageUrl` 就是一个 SSRF / 目录穿越入口。
2. **传图方式二选一**（按模型端点能力定）：
   - `base64` data URL（推荐，内网/本地部署首选）：`{"type":"image_url","image_url":{"url":"data:image/jpeg;base64,..."}}`；
   - 公网 URL：仅当模型端点能回连本服务时可用。
   单图 base64 会显著抬高 prompt token，建议**先压缩到长边 ≤ 1024、质量 80** 再编码（后端压缩或前端 `sizeType: ['compressed']` 二选一，前端压缩更省流量）。
3. **不抛异常**：识别失败返回空列表，由 [gather()](file:///f:/wx/agriculuture-agent/backend/app/agent/agents/field_observer.py#L148-L166) 的 `return_exceptions=True` 之外再兜一层，保证"照片识别不出来"不影响问诊继续。

#### 4.3 内部专用契约

给模型输出定义一个最小 schema（可放 `app/agent/contracts/observation.py` 或 reader 同模块，`extra="forbid"`）：

```python
class _CandidateOut(BaseModel):
    model_config = ConfigDict(extra="forbid")
    label: str
    score: float
    part: str | None = None    # 叶片/茎/根/果实

class _CandidatesOut(BaseModel):
    model_config = ConfigDict(extra="forbid")
    candidates: list[_CandidateOut] = []
```

提示词必须显式给出**候选域闭集**与"不确定就给低分/不给"的硬规则，例如：

```
你是茶叶病害识别的现场观察模块。只允许从以下标签中选择，不得自创新标签：
侵染性病害、生理性病害、全遮阴、半遮阴、无遮阴
对每个识别结果给出 0~1 的置信度；看不清或没有把握就返回空列表，不要猜。
```

### 第 5 步：把识别结果变成"针对性的文字描述"返回小程序

识别的产物要经两条路回给农户，**都用既有字段，不新增响应字段**。

**5.1 作为现场事实进入 prompt（已通）**

`image_candidates` 经 `post_validate` 写入 `ObservationResult.image_candidates`，`observed_facts` 由模型归纳后落在 `state["observations"]`，下游 [format_observations](file:///f:/wx/agriculuture-agent/backend/app/agent/prompts/formatters.py#L97-L106) 供问诊/判定节点读取。这一步**不需要改动**。

同时 `image_to_slots()`（[field_observer.py:219-242](file:///f:/wx/agriculuture-agent/backend/app/agent/agents/field_observer.py#L219-L242)）会把候选写进 `source_hint` 含 `image` 的槽位（茶 `tea_leaf_symptom_photo`、杂草 `weed_photo_candidate` 两个），此时**该槽位不再被追问**——照片能替代一次提问，这是拍照最直接的产品价值。

**5.2 作为"照片回执"文案即时回显（新增）**

现状问题：observe 节点只返回 `{"observations": ..., "stage": OBSERVE}`（[factories.py:158-160](file:///f:/wx/agriculuture-agent/backend/app/agent/graph/factories.py#L158-L160)），不写 `reply`；农户发完照片后收到的第一条回复往往是追问卡片，**看不到"AI 说照片里是什么"**，与用户预期不符。

最小改动方案：在 observe 节点写一句农户可见的回执，**只转述识别到的事实，不下诊断结论**：

```python
async def observe(state: ConsultationState) -> dict:
    result = await observer.run(state, _context_for(state, config, TaskType.OBSERVE))
    return {
        "observations": dump_contract(result),
        "stage": ConsultStage.OBSERVE,
        "reply": _photo_receipt(result),     # 新增
    }

def _photo_receipt(result: ObservationResult) -> str:
    """拍照回执：把识别结果说成一句人话。没照片时返回空串（不污染既有回复）。"""
    if not result.image_candidates:
        return ""
    seen = "、".join(c.label for c in result.image_candidates[:3])
    return f"我看过您发的照片了，照片里像是：{seen}。我再问您几个问题，好判断得更准。"
```

文案约束（与既有产品红线一致）：

- **不说"确诊"**：识别候选不是证据（[field_observer.py:222-224](file:///f:/wx/agriculuture-agent/backend/app/agent/agents/field_observer.py#L222-L224) 明确"图片识别结果不直接构成证据"），回执只能说"像是"；
- **不报置信度数字**：`confidence_score` 类内部分数"不得进入任何展示文案"（[state.py:359](file:///f:/wx/agriculuture-agent/backend/app/agent/state.py#L359)），`score` 同样只进日志与槽位，不进回执；
- **口语化 + 适老化**：短句，无术语，字数受 [T4-05](file:///f:/wx/agriculuture-agent/docs/tasks/阶段四-适老化改造/T4-05-后端文案长度约束配合.md) 的字数上限约束；
- **识别不到就给环境说明**：`image_candidates` 为空时回退到既有的 `note` / `environmentNote` 通道，不硬编一句"没看出问题"。

**5.3 前端渲染**

- AI 回复：走现有 `res.reply` → `aiMsg.content` 链路（[chat.ts:310-316](file:///f:/wx/agriculuture-agent/miniprogram/pages/ai/chat.ts#L310-L316)），**零改动**；语音朗读按钮 `showVoice` 也顺带可用（朗读回执）；
- 用户照片：`Message.image` 渲染 `<image>` 缩略图，点击可 `wx.previewImage` 看大图；
- 历史回看：`ConversationMessage.imageUrl` 与 [conversation_detail](file:///f:/wx/agriculuture-agent/backend/app/services/ai_service.py#L763) 已带 `imageUrl`，只需在历史页同样渲染缩略图。

## 七、风险与回退

| 风险 | 说明 | 处置 |
| --- | --- | --- |
| 端点非多模态 | `deepseek-v4-flash` 若该账号/端点不接受 image content，请求会 4xx | 已在 `recognize` 内吞异常返回空候选 → `data_available=False` + `note`，问诊照常；上线前用一张真实照片做一次联调确认 |
| base64 抬高 token | 单图进 prompt 可能数千 token，冲击预算与成本 | 前端 `sizeType: ['compressed']` + 后端长边压缩到 1024；`VISION` 档 `max_tokens` 单独可调 |
| 识别不准 | 视觉模型给出错误候选，误导判定 | 候选域闭集 + 双处过滤；照片不进证据集（既有设计）；回执文案用"像是"而非结论 |
| 图片累积占盘 | `uploads/` 无清理策略 | 本期沿用内容哈希去重（同图不重复落盘）；清理属运维项，不在本方案范围 |
| 旧基础库 | `wx.chooseMedia` 版本要求 | 回退用 `wx.chooseImage`，交互一致 |

**回退开关**：`USE_MOCK_LLM=false` 但未配视觉端点 → 自动回落 `_EmptyImageReader`；紧急情况下不配 `LLM_VISION_MODEL` + 摘掉 `FARM_LLM_API_URL` 即恢复"只上传不影响问诊"的状态。上传接口本身无副作用（不落库），可独立下线。

## 九、一句话总结

链路的**上传段与模型段是全新的**（新增上传接口 + 实现 `ImageReader`），**中间段有两个已有断点**（观察节点读错 state 键、工厂注入空实现），**返回段基本可复用**（`reply` + `imageUrl` 两个既有字段），因此工作量集中在"两个新件 + 两个小修 + 一句回执文案"。全链路必须坚持三条既有原则：**候选域代码侧硬过滤、识别失败不阻断问诊、图片不构成证据**。
