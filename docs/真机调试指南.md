>
> 适用对象：使用「微信开发者工具」上传代码 → 在手机微信里做真机预览/调试/体验版 的开发人员

## 一、微信公众平台后台（mp.weixin.qq.com）必须配置项

这些是**只要真机运行一次就必碰到**的硬门槛，没配会直接功能失败。

### 1.1 位置接口开通（自动定位 / 手动选点依赖）

路径：**设置 → 基本设置 → 接口设置**（或「开发 → 接口权限」）

| 权限项 | 作用 | 状态要求 |
|--------|------|----------|
| `scope.userLocation`（位置接口） | 允许 `wx.getLocation` / `wx.authorize` 拉取用户 GPS 坐标 | ✅ 必须已开通 |
| `wx.chooseLocation`（选点接口） | 如果后期要用地图选点再开通，当前用手动输入文本可不开通 | 本期可选 |

### 1.2 用户隐私保护指引（必须上传审批）

新版微信小程序在 2024 年之后强制要求填写"用户隐私保护指引"，真机如果没配，**所有涉及位置/相册/昵称的接口都会直接 fail auth**。

路径：**功能 → 用户隐私保护指引** →「收集的个人信息类型」里**必须勾选以下 4 项并填写用途**：

| 勾选项 | 用途填写（建议） |
|--------|-----------------|
| 位置信息 | 用于获取用户所在的乡镇/区域，提供本地化农事播报与环境监测建议 |
| 昵称 | 用于展示农户档案的基础信息 |
| 头像 | 用于展示用户资料卡的头像 |
| 相册（如后期加拍照识别则补） | 用于上传作物照片识别病虫害 |

> 保存后需要「提交审核」→ 微信侧审批通过（通常几十分钟到几小时）后才生效。**未通过前真机跑定位一律 auth deny**。

### 1.3 服务器合法域名

**真机环境下，所有 `wx.request` 必须是 HTTPS 且在白名单里**（开发者工具可以勾"不校验合法域名"绕开，真机没有这个开关）。

路径：**开发 → 开发管理 → 开发设置 → 服务器域名**

| 字段 | 填写示例 | 说明 |
|------|----------|------|
| request合法域名 | `https://api.你的域名.cn` | 后端接口所在域名，多条换行分隔 |
| socket合法域名 | （后期上 MQTT 时填） | 当前不用填 |
| uploadFile合法域名 | （后期拍照识别时填） | 当前不用填 |

> **重要**：域名必须是已备案、有效 HTTPS 证书、IP 地址不允许。

## 二、手机系统端必须授权

### 2.1 手机 GPS / 定位服务开关

- **安卓**：下拉通知栏 → 点亮「位置信息 / GPS」图标
- **iOS**：设置 → 隐私与安全性 → 定位服务 → 打开总开关

> GPS 没开时 `wx.getLocation` 失败 errMsg 包含 `system permission` 或 `location service`，本项目代码已弹对应提示："请在手机系统设置中开启定位服务/GPS"。

### 2.2 微信 App 的位置权限

| 平台 | 路径 | 要求 |
|------|------|------|
| 安卓 | 系统设置 → 应用 → 微信 → 权限 → 位置信息 | 选择「始终允许」或「仅在使用期间允许」，不要选「仅使用时询问」（容易被系统回收） |
| iOS | 设置 → 微信 → 位置 | 选择「使用App期间」，必须打开「精确位置」 |

### 2.3 首次进入小程序的授权弹窗

真机首次点"自动定位"会先弹系统层位置权限（上面这条）→ 再弹小程序层 `scope.userLocation` 授权框：

> 弹窗标题：**话农点金获取你的位置信息**
> 正文就是 `app.json` 里 `permission.scope.userLocation.desc` 填的那句：*用于获取您当前所在的乡镇/区域，提供本地化的农事播报与环境监测建议*

**必须点「允许」**，点了"不允许"之后需要按下面 2.4 救回来。

### 2.4 用户曾经拒绝过定位授权？一键恢复路径

真机右上角「**...**」菜单 → 设置 → 打开「**位置信息**」开关 → 返回小程序页面再次点击"自动定位"即可。

> 本项目代码在检测到 `authSetting.scope.userLocation === false`（已拒绝）时，会主动弹一个"去设置"的 Modal，点「去设置」直接跳到上面这个设置页。**不用手动翻菜单**。

## 三、开发者工具端设置

### 3.1 真机调试 vs 预览

| 方式 | 适用场景 | 怎么用 |
|------|----------|--------|
| **真机调试 2.0** | 要打 console 日志/接口抓包/查看报错 | 工具栏 → 真机调试 → 扫码 → 手机操作时开发者工具会实时打印 log 和 Network |
| **预览** | 快速验证界面和交互是否正常 | 工具栏 → 预览 → 手机扫码打开 |
| **上传代码 → 体验版** | 给甲方/业务方看、不连开发者电脑 | 工具栏 → 上传 → 填版本号 → mp后台「版本管理 → 选为体验版」 → 手机扫码打开 |

### 3.2 开发者工具里"验证定位功能"的两个办法

真机调试前可以先用工具本地模拟，确认代码逻辑没问题：

#### 办法 A：模拟地理位置
工具栏右上角「**详情**」→「**地理位置**」选项卡 → 勾选"**指定位置**" → 手动输入经纬度（如 104.24, 26.23 约等于宣威市）→ 点首页「定位 › → 自动定位」→ 工具里会走到 success 分支，显示 `定位坐标 26.23,104.24`。

#### 办法 B：模拟权限拒绝（验证三态分支）
开发者工具工具栏「**模拟**」→「**权限控制**」→ 找到 `scope.userLocation` → 先选"「未授权」"或"「已拒绝」" → 再点自动定位，观察是否弹正确的引导 Modal。

### 3.3 清缓存大法：真机出玄学问题第一步做

任何"本地工具没问题真机有问题"的情况，先按下面顺序排一遍：

```
1. 开发者工具 → 清缓存 → 全部清除（清数据缓存 + 清文件缓存 + 清授权）
2. 手机微信 → 发现 → 小程序 → 长按「话农点金」→ 删除
3. 重新扫码预览 / 真机调试
4. 还不行？看 3.1「真机调试 2.0」连开发者工具看 console.error 输出
```

## 四、常见错误分流对照表（对应 errMsg）

如果自动定位失败，打开「真机调试 2.0」看 console，本项目 `doGetLocation` 的 **fail 分支里把原始 errMsg 用 console.error 打印出来了**（搜关键字 `[autoLocate fail]`），对照下表处理：

| 看到的 errMsg 片段 | 含义 | 解决办法 |
|--------------------|------|----------|
| `auth deny` / `auth authorize:fail` / `deny` | 用户在授权弹窗点了「不允许」 | 2.4 的方式：右上角设置 → 开位置；或重删小程序 |
| `system permission denied` / `location service` | 手机 GPS 总开关没开 / 微信 App 系统级位置权限没开 | 2.1 + 2.2 两条都打开 |
| `network` / `timeout` | 手机网络差 / 当前区域 GPS 卫星搜不到 | 换开阔地带、开 WiFi+4G 双通再试 |
| `require privacy authorization` 或 隐私合规相关 | 1.2 的用户隐私保护指引没提交/未通过审批 | 回 1.2 提交审核，等通过 |
| `getLocation:fail no permission` 或 API 不存在 | 1.1 的位置接口在公众平台后台没开通 | 回 1.1 开通接口权限 |
| `The requested API ... requires "requiredPrivateInfos"` | app.json 里没声明 requiredPrivateInfos | 代码已配好见备注①，确认打包版本是最新上传 |
| 其他（只显示坐标不显示真实地名） | 不是失败，是 mock 逆地理编码 | 正常现象，等后端对接真实逆地理编码 API 后替换 `mockReverseGeocode` |

> 备注①：`app.json` 已在根节点加入 `requiredPrivateInfos: ["getLocation","chooseLocation"]` 和 `permission.scope.userLocation.desc`，代码侧没问题。

## 五、本项目其他真机高频坑（非定位）

### 5.1 tabBar 页面跳转方式必须用 wx.switchTab

真机里对 tabBar 页（首页/咨询/历史/我的）用 `wx.navigateTo` 会**静默失败无任何提示**，本项目之前"拍照识别"入口已修过。**如果新功能跳这四页一律用 `wx.switchTab`**。非 tabBar 页（档案/环境监测）继续用 `wx.navigateTo`。

### 5.2 自定义导航栏的刘海屏适配

真机的 `env(safe-area-inset-top)` 比工具里更大。代码已在 4 个 tab 页 + env.ts 全部加了：
- header `padding-top: calc(110rpx + env(safe-area-inset-top))`
- tabBar `padding-bottom: calc(20rpx + env(safe-area-inset-bottom))` 且盒模型 `content-box`

**真机检查项**：首页/咨询/历史/我的 四个 tab 来回切，观察顶部深绿色条和底部 tabBar 位置是否固定无跳动、内容不被刘海遮挡（iPhone 14+ 上最明显）。

### 5.3 聊天区域 scroll-view 高度

真机 100vh ≠ 工具的 100vh。chat.ts 里高度是 `height: calc(100vh - 270rpx - env(safe-area-inset-top))`，真机检查：键盘弹出后输入栏不悬浮在聊天内容上、AI 回复完自动到底部后最下面一条能完整显示（不被输入框遮住）。

### 5.4 登录后跳转顺序

真机上 `wx.setStorageSync` 写缓存 + `wx.reLaunch` 有时候会时序问题，如果登录后偶尔回到登录页再秒跳首页，属正常现象（app.json 第一个 page 是 login）。**不影响使用**。若要消除视觉闪烁，可把 app.json 第一个 page 改成首页，在首页 onShow 里判断无 token 再 `wx.reLaunch` 到 login。

### 5.5 语音播放喇叭 / 麦克风纯 CSS 图标

真机有些老手机对 `border-radius` 百分比 + transform 支持不好，注意看喇叭三条声波弧线是否正常显示。如果发现变形，把 rpx 微调成整数值即可。
