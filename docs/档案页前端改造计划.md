# 档案页前端改造计划（对齐后端七条流程）

> 目标：让农户档案页采集的数据，真正被后端七条流程（rice / tea / rapeseed / chili / weed / pig / general）消费，
> 使"AI 开口之前就知道这位农户在哪儿、种了多少、种哪一类、处于什么阶段、以往用过什么药"这一设计意图落地。
>
> 依据：产品说明书 v2.0 §4.1（农户档案）；后端流程配置 YAML；档案 → 农事历 → 问诊图的实际消费链路。

---

## 1. 结论先行

改造存在两个层次的问题：

1. **后端断链（决定成败，优先修）**：档案组装后注入的是 `state["context"]`，但问诊图内真正读取的是
   `state["profile"] / profile_process_id / profile_process_hint / profile["slot_values"]`，这些键在生产链路中
   **没有任何写入方**。不修此处，前端采集多少字段都不会影响问诊结果。
2. **字段错位（前端可独立修复）**：前端不采集播种日期、品种、流程类型、用药史，且生育阶段词表是全流程共用的一套，
   与各流程配置的阶段口径不匹配。

因此顺序必须是：**先接通后端桥接（P0-B），再补前端字段（P0-A 起）**。

---

## 2. 现状与落差

### 2.1 链路事实

| 环节 | 事实 | 位置 |
| --- | --- | --- |
| 前端采集 | 人员 / 地区 / 面积 / 种植类型 / 水源 + `crops[]{cropName, plantMu, growthStage}` | `miniprogram/pages/profile/farmer-profile.ts` |
| 接口契约 | `CropItem{cropName, plantMu, growthStage}`，无播种日期 / 品种 / 地块 | `backend/app/schemas/farmer.py` |
| 落库 | `replace_all` 只写 `crop_name / plant_mu / growth_stage / is_main` | `backend/app/repositories/conversation.py` |
| 农事历消费 | `load_calendar_entries` 依赖 `Crop.sowing_date`；缺日期 → `resolve_stage` 返回 `None` → 不产出任何农事历提示 | `backend/app/broadcast/inputs/calendar.py` |
| 问诊消费 | 图内读 `state["profile"]["slot_values"]`、`state["profile_process_id"]` | `backend/app/agent/agents/candidate_pool.py`、`triage.py` |
| 入口注入 | 仅注入 `initial_state["context"]`（`{farmer, crop, profile_tags}`） | `backend/app/services/ai_service.py` |

### 2.2 落差清单

| 编号 | 落差 | 影响 | 归属 |
| --- | --- | --- | --- |
| A | 不采集播种 / 起始时间 | 农事历（首页今日提示）零产出 | 前端 + 后端契约 |
| B | 档案未注入 `state["profile"]` 系列键 | `source_hint:[profile]` 槽位永远重复追问；对象确认失效；`format_entries` 恒为"无" | 后端 |
| C | 生育阶段词表全流程共用（12 项中文），与流程配置口径不符 | 阶段值无法驱动 `timing_rules`（`booting` / `flowering` 等内部值）与阶段同步 | 前端（+ 后端可选映射） |
| D | 无"流程类型"七选一 | 自由输入导致大量作物落到 general；杂草防治无处安放 | 前端 + 后端契约 |
| E | 无品种、无地块 | 与 §4.1.5 不符；`farmEntryId` 维度追溯缺失 | 前端 + 后端契约 |
| F | 无用药史、无完整度 / 渐进补全 | 用药史属红线级必填设计；一次性全量表单易劝退 | 前端 + 后端契约 |

## 3. 字段映射总表（改造后目标态）

| 前端字段（经营条目每项） | 后端 `CropItem` | `Crop` 表列 | 流程 / 农事历用途 |
| --- | --- | --- | --- |
| `processType`（七选一） | `processType` | 派生，不落列（或落 `crop_name` 归一值） | 决定问诊脚本与提示模板 |
| `cropName`（选"其他"时输入） | `cropName` | `crop_name` | `object_aliases` 别名匹配 → 流程 |
| `cropVariety`（选填） | `cropVariety` | `crop_variety` | 品种相关判据（如软米感病品种） |
| `plantMu` | `plantMu` | `plant_mu` | 规模适配建议 |
| `sowingDate`（选填） | `sowingDate` | `sowing_date` | **农事历起始时间（关键）** |
| `growthStage`（按流程动态枚举） | `growthStage` | `growth_stage` | 阶段同步 / 当前阶段展示 |
| （地块，P2） | `fieldId` | `field_id` | 地块绑定与快照维度 |

## 4. 分阶段改造计划

### P0-A｜补播种 / 起始时间采集（前端 + 契约）

**目标**：让农事历能产出提示。

**改动**
- 前端 `farmer-profile.ts`
  - `data.growthStages` 保留；在 `selectedCrops` 每项增加 `sowingDate: ''`。
  - `addCrop` / `quickAddCrop` / `fillForm` / `submitProfile` 同步该字段（`fillForm` 读 `c.sowingDate`，提交时透传）。
- 前端 `farmer-profile.wxml`
  - 作物项内新增 `picker mode="date"`，标签"播种 / 起始时间"，`bindchange` 写入 `selectedCrops[idx].sowingDate`。
- 前端 `types/api.d.ts`：`CropItem` 增加 `sowingDate?: string | null`。
- 后端 `app/schemas/farmer.py`：`CropItem` 增加 `sowingDate: date | None = None`。
- 后端 `app/services/farmer_service.py`：`save_profile` 组装 `replace_all` 项时带 `sowing_date`；`_build_profile` 回填 `sowingDate`（`isoformat()`）。
- 后端 `app/repositories/conversation.py`：`replace_all` 写入 `sowing_date=item.get("sowing_date")`。

**验收**
- 保存一条带播种日期的作物后，`GET /api/farmer/profile` 返回该 `sowingDate`。
- `POST /api/broadcast/snapshot` 对水稻条目：当 `sowing_date <= today` 且 `growth_stage` 非空时，`snapshot` 中出现 `source_kind == "calendar"` 的条目。
- 单测：`tests/broadcast/test_calendar_input.py` 覆盖"有日期产出 / 无日期不产出"。

---

### P0-B｜接通档案 → 问诊图（后端，前置条件）

**目标**：让 `state["profile"] / profile_process_id / profile_process_hint` 在生产链路中有值。

**改动**（集中在 `app/services/ai_service.py`）
- 扩展 `build_context` 的返回结构，或在 `initial_state` 之外新增一个映射步骤，产出图内契约键：
  - `state["profile"]`：至少含
    - `location`（省 + 市 + 县）
    - `entries`：`[{"process_id": <归一后的 ProcessId.value>, "start_date": <sowing_date iso>, "display_name": <crop_name>}, ...]`
    - `object_label`：主条目的展示名（如"水稻·3亩"）
    - `slot_values`：可由档案自动回答的槽位值，如 `{"rice_growth_stage": growth_stage, "rice_last_pesticide": <最近用药>}`
  - `state["profile_process_id"]`：主作物名经 `match_object_alias(crop_name, configs)` / `_resolve_process_hint` 归一得到的 `ProcessId.value`，未命中则 `None`。
  - `state["profile_process_hint"]`：与 `profile_process_id` 同源（用于对象冲突判定）。
- 注意 `slot_values` 的键必须与目标流程 `required_slots` 中的 key 一致，否则 `_collect_auto_facts` 无法生效。
- 用药史（`prescription_history`）在 P2 落地前，先留空 dict，不得写入伪造值。

**验收**
- 造档（水稻 + 分蘖期）后发起一次不带 `processHint` 的问诊，`triage` 的 `slot_gaps` 中**不再包含** `rice_growth_stage`。
- `tests/agent/test_candidate_pool.py` 增加"档案有值 → 候选被剔除"的端到端式用例（复用现有 `profile={"slot_values": {...}}` 断言路径）。
- `format_triage_prompt` 输出中"档案中的经营条目"不再恒为"无"。

---

### P1-A｜流程类型七选一 + 阶段词表按流程切分（前端 + 契约）

**目标**：解决落差 C、D。

**改动**
- 前端 `farmer-profile.ts`
  - `data` 新增 `processOptions`（七选一）：水稻 / 茶 / 油菜 / 辣椒 / 杂草防治 / 养猪 / 其他（→ general）。
  - 新增 `stageByProcess` 映射（与各 YAML 的 `options` 对齐）：
    - rice：`分蘖期 / 孕穗期 / 抽穗期 / 灌浆期`
    - rapeseed：`苗期 / 蕾薹期 / 花期 / 角果期`
    - chili：`苗期 / 开花坐果期 / 膨果期 / 采收期`
    - tea：采摘轮次（`春茶 / 夏茶 / 秋茶`）
    - pig：日龄阶段（`母猪 / 仔猪 / 育肥猪`）
    - weed / general：隐藏阶段选择
  - 作物项结构改为 `{processType, cropName, cropVariety, plantMu, sowingDate, growthStage}`；`processType !== 'other'` 时用流程展示名作为 `cropName`。
  - 校验调整：`processType` 必选；`other` 时 `cropName` 必填。
- 前端 `farmer-profile.wxml`：作物项改为"先选流程类型 → 输入/展示作物名 → 品种 → 面积 → 播种日期 → 阶段"。
- 前端 `types/api.d.ts` + 后端 `app/schemas/farmer.py`：`CropItem` 增加 `processType: str = ""`、`cropVariety: str | None = None`。
- 后端 `farmer_service` / `conversation.replace_all`：`crop_variety` 落列；`processType` 可用于校验或直接落 `crop_name`。
  - 建议：`processType` 非空且非 other 时，`crop_name` 存归一展示名（如"水稻"），确保 `object_aliases` 稳定命中。

**验收**
- 选择"杂草防治"时，阶段选择被隐藏，且保存后不产生生育期类农事历条目（`NO_CALENDAR_PROCESSES` 生效）。
- 选择"养猪"时，阶段选项为日龄阶段，`crop_name` 归一为"养猪"并能命中 `pig` 流程。
- 单测：`tests/test_farmer.py` 覆盖 `processType` / `cropVariety` 往返。

---

### P1-B｜阶段值口径对齐（后端，可选但推荐）

**目标**：解决落差 C 的后半段（中文阶段 vs `timing_rules.when` 的英文内部值）。

**改动**
- 在流程配置层提供阶段"中文展示名 ↔ 内部值"映射（`process_config` 已有 `options` 为中文、`timing_rules.when` 为英文的现状）。
- 二选一：
  - 方案 1（推荐、改动小）：前端提交中文阶段，后端在写 `GrowthStage` 前按流程配置做一次归一；
  - 方案 2：在 YAML 的 `required_slots` 里补充阶段项的 `value_map`，配置驱动映射。
- 不得用"用月份反推阶段"兜底（`calendar.py` 的硬约束）。

**验收**
- 水稻选"孕穗期"后，`timing_rules` 中 `rice_boot_window`（`when: {growth_stage: booting}`）能被正确判定。

---

### P2-A｜地块绑定（前端新页面 + 后端接口）

**目标**：解决落差 E 的地块部分。

**改动**
- 后端：新增 `field` 相关 schema / service / API（新建、列表），`CropItem` 增加 `fieldId`，`replace_all` 写 `field_id`。
- 前端：新增地块管理页（名称 / 面积 / 土壤 / 经纬度），档案页作物项增加"所属地块"选择。
- 联动：`farmEntryId` 维度快照（`/api/broadcast/snapshot?farmEntryId=`）与农事历 `facts_provenance.farm_entry_id`。
- **此阶段工作量最大，需单独确认是否纳入近期范围。**

---

### P2-B｜用药史 + 档案完整度 / 渐进补全（前端 + 契约）

**目标**：解决落差 F。

**改动**
- 用药史：
  - 档案页新增"历史用药"录入区（药剂名 / 时间 / 用量 / 是否药害），字段落到档案或关联表；
  - 支持"从处方卡一键转入"（对应 §4.1.4 功能点 4）；
  - 接入 P0-B 的 `slot_values`（如 `rice_last_pesticide`）与图内 `prescription_history`。
- 渐进补全：
  - 首次仅强制：地区 + 一类作物 + 规模；其余字段可空；
  - 前端本地计算"档案完整度 %"并展示（`已填建议字段 / 建议字段总数`），**不作任何服务端门槛**；
  - 校验函数 `validate()` 按"首次 / 补全"两种模式放宽必填项。

**验收**
- 首次建档仅填三项即可保存成功（不再被 `validate()` 拦截）。
- 完整度数字随字段填充变化，且不影响任何接口调用成功与否。

## 5. 兼容与回归要求

- **契约同步**：前端 `types/api.d.ts` 与后端 `app/schemas/farmer.py` 必须成对修改，否则新字段被 Pydantic 静默丢弃。
- **空值安全**：所有新增字段一律可选，老数据（无 `sowing_date` / 无 `crop_variety`）读取时返回 `None` / `""`，不得报错。
- **本地缓存**：`KEY.FARMER_PROFILE` / `KEY.FARMER_CROPS` 结构变更后，`fillForm` 需兼容旧缓存缺字段（现有实现的 `|| ''` 写法可沿用）。
- **分层门禁**：改动后必须通过 `python scripts/check_layers.py`（`app/agent/` 不得导入 `app/models/`）。
- **回归**：`tests/test_farmer.py`、`tests/broadcast/test_calendar_input.py`、`tests/agent/test_candidate_pool.py`、`tests/graph/test_main_route.py`。

## 6. 风险与待确认

| 项 | 说明 |
| --- | --- |
| P0-B 注入结构 | `state["profile"]` 的字段形态需与 `triage.py`（读 `object_label`）、`triage 提示词`（读 `location` / `entries`）、`candidate_pool`（读 `slot_values`）三处消费口径完全一致，建议先写一版并跑上述三个测试。 |
| 阶段内部值映射 | 采用方案 1（后端归一）时，需明确"未识别阶段"的降级行为（建议：原样存储 + 不产出阶段类提示，不猜测）。 |
| 地块范围 | P2-A 涉及新表操作与页面，是否纳入近期需确认。 |
| 用药史存储 | 是否复用现有 `prescription_history` 快照还是新增独立记录表，需确认（说明书 §4.1.4 功能点 4 描述为"列表，含药剂 / 时间 / 用量 / 结果"）。 |
| 七选一与"其他" | "其他"入口需提示"填写具体作物名有助于后续补充专线"，该文案与收集用途需产品确认。 |

---

## 7. 建议执行顺序（最小有效集）

1. **P0-B**：接通档案 → 问诊图（否则后续全部空转）。
2. **P0-A**：补播种 / 起始时间（让首页农事历"看得见"）。
3. **P1-A**：流程类型七选一 + 阶段按流程切分。
4. **P1-B**：阶段口径对齐。
5. **P2-B**：用药史 + 渐进补全。
6. **P2-A**：地块绑定（工作量大，单独排期）。
